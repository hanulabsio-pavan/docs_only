RV32IMAC Microarchitecture Specification

Hardware Implementation Guide — RTL Coding Phase Reference

Document Authority: This specification is subordinate to and must remain consistent with
docs/rv32imac_isa_reference.md (ISA String: RV32IMAC_Zicsr_Zifencei). In any conflict
between this document and the ISA reference, the ISA reference takes precedence.
Target platform: Xilinx Artix-7 xc7a200t (Nexys Video). Target workload: FreeRTOS /
Zephyr RTOS on IoT sensor nodes. All microarchitectural decisions are constrained by the
FPGA fabric resource budget and the real-time determinism requirements of the RTOS tick handler.

Implementation Tip: Reset all _vld bits to 0 on power-on and any flush event.
This ensures that bubbles propagate cleanly through the pipeline without triggering
spurious register writes or CSR updates during flush cycles.

4. Register File & Forwarding Unit

4.1 Register File Implementation

The 32×32-bit integer register file (regfile.v) is mapped to a Xilinx Simple Dual-Port BRAM configured as a 32-deep × 32-wide synchronous memory.

Attribute Value
Primitive RAMB36E1 (SDP mode, one per 18-bit half)
Read ports 2 (rs1, rs2) — registered outputs, 1-cycle latency
Write port 1 (rd) — synchronous on WB rising edge
x0 hardwire Write to addr 00000 is silently masked by rd_we_masked = rd_we & (rd != 5'b00000)
Reset Not required; x0 is masked at the write port

Implementation Tip — BRAM Read-First Mode: Set the BRAM READ_WIDTH / WRITE_WIDTH
to match exactly. Use READ_FIRST collision mode so that a simultaneous read and write
to the same address (which cannot occur in this pipeline, but protects against synthesis
elaboration warnings) returns the old value — consistent with the forwarding logic below.

4.2 Forwarding Unit (hazard_ctrl.v + de_stage.v)

The forwarding unit resolves RAW (Read After Write) data hazards for ALU-to-ALU sequences with zero stall penalty by selecting from the WB-stage result bus rather than the register file output.

fwd_rs1_sel:
  11 → forward de_wb_result  (WB-stage result, for ALU→ALU)
  10 → forward wb_rd_wdata   (Committed regfile data, fallback)
  00 → use rf_rs1_q          (No hazard)

fwd_rs2_sel:
  11 → forward de_wb_result
  10 → forward wb_rd_wdata
  00 → use rf_rs2_q

Forwarding Decision Logic (combinational):

// Forward from WB result to DE operand A (rs1)
if (de_wb_vld && de_wb_rd_we && (de_wb_rd == de_rs1) && (de_rs1 != 5'b0))
    fwd_rs1_sel = 2'b11;
else
    fwd_rs1_sel = 2'b00;

// Load-use hazard: forward not possible, stall required
if (de_wb_is_load && de_wb_rd_we &&
    ((de_wb_rd == if_de_rs1) || (de_wb_rd == if_de_rs2)))
    stall_load_use = 1'b1;

4.3 RAW Hazard Matrix

Producer Stage Consumer Stage Hazard Type Resolution
DE (ALU result in de_wb_result) DE (next instruction reading rs1/rs2) RAW — ALU→ALU Forward de_wb_result → operand mux (0 stall cycles)
WB (load data in wb_rd_wdata) DE (instruction in DE needing the loaded value) RAW — Load→Use Insert 1 bubble: stall IF, stall DE, flush WB input
WB (CSR read result) DE (next instruction reading same rs1) RAW — CSR→ALU Treat as ALU→ALU; forward de_wb_result

5. Instruction Fetch Stage (IF)

5.1 PC Register & Mux

The PC is a 32-bit registered value with a 4-input mux selecting the next value each cycle.

pc_sel[1:0] Source Condition
2'b00 PC + 4 or PC + 2 Normal sequential flow
2'b01 de_branch_target Branch taken or JAL/JALR resolved in DE
2'b10 mtvec_target Trap entry (from trap_ctrl.v)
2'b11 mepc MRET instruction

Priority (highest first): trap > branch_taken > mret > sequential.

Implementation Tip — PC Retiming: The PC adder (PC + 4) is on the critical
path from the BRAM output to the next BRAM address input. Registering the PC mux
output with a dedicated fast-path flip-flop (set KEEP_HIERARCHY = "TRUE" on
if_stage) typically recovers 0.3–0.5 ns of slack at 100 MHz on Artix-7 −1.

5.2 Instruction Memory Interface

imem_addr  [31:0]  → ITCM / Boot ROM address (PC)
imem_rdata [31:0]  ← Instruction word (registered BRAM output, 1-cycle)
imem_vld          ← BRAM data valid (always 1 for ITCM; gated for DDR3 stall)
imem_stall        → Assert to hold PC and IF/DE register (DDR3 miss)

5.3 Alignment & Exception Detection

// 32-bit instruction: must be 4-byte aligned
if (!if_de_is_compressed && PC[1:0] != 2'b00)
    if_de_exc_iam = 1'b1;   // mcause = 0x0000_0000

// Compressed instruction: must be 2-byte aligned (PC[0] == 0)
if (if_de_is_compressed && PC[0] != 1'b0)
    if_de_exc_iam = 1'b1;

6. Decode / Execute Stage (DE)

6.1 Instruction Decoder

The decoder is a purely combinational block that converts the 32-bit instruction word (post C-expansion) into the control signal bundle consumed by the rest of the DE stage.

Decoder outputs (partial — full list in Section 14):

Signal Width Description
de_alu_op 4 ALU operation select
de_alu_src_b 1 0 = rs2, 1 = immediate
de_mem_we 1 Data memory write enable
de_mem_re 1 Data memory read enable
de_mem_size 3 funct3 encoding for load/store width/sign
de_rd_we 1 Register file write enable
de_rd_sel 2 WB mux: 00=ALU, 01=load, 10=PC+4, 11=CSR
de_branch 1 Instruction is a branch
de_jump 1 Instruction is JAL/JALR
de_csr_op 3 CSR operation (funct3 from ISA ref §8.1)
de_is_mdu 1 Route to Mul/Div Unit
de_is_amu 1 Route to Atomic Unit
de_sys_op 2 00=none, 01=ECALL, 10=EBREAK, 11=MRET
de_illegal 1 Illegal instruction exception

6.2 ALU

32-bit combinational ALU supporting all RV32I arithmetic, logical, shift, and comparison operations. Operation select encoding:

de_alu_op[3:0] Operation ISA Instruction(s)
0000 rs1 + rs2_or_imm ADD, ADDI, loads, stores, AUIPC
0001 rs1 - rs2 SUB
0010 rs1 & rs2_or_imm AND, ANDI
0011 rs1 \| rs2_or_imm OR, ORI
0100 rs1 ^ rs2_or_imm XOR, XORI
0101 rs1 << rs2[4:0] SLL, SLLI
0110 rs1 >>ₗ rs2[4:0] SRL, SRLI
0111 rs1 >>ₐ rs2[4:0] SRA, SRAI
1000 (rs1 <ₛ rs2) ? 1:0 SLT, SLTI
1001 (rs1 <ᵤ rs2) ? 1:0 SLTU, SLTIU
1010 Pass imm[31:12]∥0¹² LUI
1011 Pass PC+4 JAL, JALR (link)

6.3 Branch Resolution Unit (BRU)

The BRU evaluates branch conditions and computes the target address entirely within the DE stage, generating a 1-cycle flush of the IF stage on a taken branch or any unconditional jump.

$$\text{branch_target} = \text{PC}_{DE} + \text{sx}(\text{imm})$$

$$\text{JALR target} = (\text{rs1} + \text{sx}(\text{imm}))\ \&\ \sim1$$

Condition signal Branch type
bru_eq BEQ
!bru_eq BNE
bru_lt_s BLT
!bru_lt_s BGE
bru_lt_u BLTU
!bru_lt_u BGEU

Branch penalty: Always 1 cycle (fetch slot behind a branch is unconditionally squashed when the branch is determined taken in DE). No branch predictor is implemented.

6.4 Load / Store Unit (LSU)

The LSU computes the effective address in DE and drives the data memory interface. For DTCM accesses, read data is available in the next cycle (WB stage), where it is byte-lane aligned.

dmem_addr  = rs1 + sx(imm)     // effective address
dmem_wdata = rs2                // store data (pre-alignment)
dmem_we    = de_mem_we          // write enable
dmem_size  = de_mem_size[1:0]   // 00=byte, 01=half, 10=word
dmem_stall → stall_load_use     // DTCM: never; DDR3: variable

Address misalignment check (combinational in DE):

case (de_mem_size[1:0])
    2'b01: dmem_exc_align = dmem_addr[0];       // halfword: addr[0] must = 0
    2'b10: dmem_exc_align = |dmem_addr[1:0];    // word:     addr[1:0] must = 0
    default: dmem_exc_align = 1'b0;             // byte: always aligned
endcase

7. Writeback Stage (WB)

7.1 Load Data Aligner

Raw DTCM output is always 32 bits wide. The aligner extracts and sign/zero-extends based on de_wb_mem_op (the funct3 field passed through the pipeline register):

de_wb_mem_op Width Signed? ISA Mnemonic
3'b000 8-bit Yes LB
3'b001 16-bit Yes LH
3'b010 32-bit N/A LW
3'b100 8-bit No LBU
3'b101 16-bit No LHU

Byte lane extraction uses dmem_addr[1:0] latched in de_wb_reg to select which byte/halfword of the 32-bit BRAM output to use.

7.2 Writeback Mux

wb_rd_wdata = de_wb_is_load  ? load_aligner_out :
              de_wb_rd_sel==2'b10 ? de_wb_pc_plus4 :   // JAL/JALR link
              de_wb_rd_sel==2'b11 ? de_wb_csr_rdata :  // CSR read
                                    de_wb_result;       // ALU result

The write is gated: rf_we = de_wb_rd_we & de_wb_vld & ~(de_wb_rd == 5'b0).

8. Hazard Control Unit

8.1 Stall & Flush Architecture

The Hazard Control Unit (hazard_ctrl.v) generates three categories of pipeline control signals:

Signal Affected Register Action
stall_if PC, if_de_reg Hold PC and IF/DE register at current value
stall_de de_wb_reg Hold DE/WB register; insert bubble into WB slot
flush_if if_de_reg Zero if_de_vld — kill instruction in IF slot
flush_de de_wb_reg Zero de_wb_vld — kill instruction in DE slot

8.2 Hazard Priority (highest to lowest)

Priority 1: Trap / Interrupt          → flush_if, flush_de (full pipeline drain)
Priority 2: AMO bus lock active       → stall_if, stall_de (hold both front stages)
Priority 3: DIV in progress           → stall_if, stall_de
Priority 4: MUL cycle 2 pending       → stall_if (1 cycle)
Priority 5: Load-use RAW              → stall_if, flush_de (insert bubble)
Priority 6: Branch taken / JAL/JALR   → flush_if (1-cycle fetch squash)
Priority 7: DDR3 imem stall           → stall_if
Priority 8: DDR3 dmem stall           → stall_if, stall_de

8.3 Hazard Summary Table

Hazard Type Detect Point Resolution Stall Penalty
RAW — ALU→ALU DE (compare de_wb_rd vs if_de_rs1/rs2) Bypass de_wb_result → operand mux 0 cycles
RAW — Load→Use DE (detect de_wb_is_load + rd match) Stall IF + flush DE bubble 1 cycle
Control — Branch taken DE (BRU resolves condition) Flush IF slot 1 cycle
Control — JAL DE (unconditional, resolved in decode) Flush IF slot 1 cycle
Control — JALR DE (needs rs1 value) Flush IF slot 1 cycle
MUL latency (2-cycle) DE (detect de_is_mdu & !div) Stall IF 1 cycle 1 cycle
DIV latency (34-cycle) DE (detect de_is_mdu & div) Stall IF+DE 33 cycles 33 cycles
AMO bus lock DE (detect de_is_amu) Stall IF+DE for AMO duration 4–6 cycles (DTCM)
Trap / Interrupt WB/trap_ctrl Flush IF + DE, vector to mtvec 5 cycles
DDR3 imem miss IF (imem_vld = 0) Stall IF 10–40 cycles
DDR3 dmem miss DE (dmem_stall = 1) Stall IF + DE 10–40 cycles

8.4 CPI Model

$$\text{CPI} = 1 + \sum_{i} \left( f_i \times P_i \right)$$

$$\text{CPI}_{typical} = 1 + (0.10 \times 1) + (0.05 \times 1) + (0.001 \times 33) \approx \mathbf{1.183}$$

Where $f_i$ is the fraction of instructions of type $i$ and $P_i$ is the stall penalty for that type. Assumed instruction mix: 10% load-use, 5% branches taken, 0.1% division.

9. M-Extension — Multiply / Divide Unit

9.1 MDU Overview

The Multiply/Divide Unit (mdu.v) is instantiated in the DE stage and uses a shared result register visible to the WB stage. It implements:

  • MUL / MULH / MULHSU / MULHU via a 2-cycle Booth-encoded pipelined multiplier using two cascaded DSP48E1 slices.
  • DIV / DIVU / REM / REMU via a 34-cycle non-restoring iterative divider using LUT fabric.

Both sub-units share the mdu_result[31:0] output register and an mdu_done handshake signal.

9.2 Multiplier Datapath (DSP48E1)

One bubble is inserted by the Hazard Unit (stall_if for 1 cycle) while the multiplier completes its second pipeline stage.

9.3 Divider Datapath

The divider uses a non-restoring shift-and-subtract algorithm, consuming 1 LUT slice per bit-step. A 6-bit iteration counter drives the mdu_busy signal for 32 active steps plus 2 overhead cycles.

State: { quotient[31:0], remainder[31:0], dividend[31:0], divisor[31:0], iter[5:0] }

Each cycle:
  shifted   = {remainder[30:0], dividend[31]}
  trial_sub = shifted - divisor
  if trial_sub[32] == 0 (no borrow):
      remainder ← trial_sub[31:0]
      quotient  ← {quotient[30:0], 1'b1}
  else:
      remainder ← shifted[31:0]
      quotient  ← {quotient[30:0], 1'b0}
  dividend ← {dividend[30:0], 1'b0}
  iter     ← iter + 1
  if iter == 32: mdu_done ← 1

Corner cases (mandated by ISA reference §5.3):

Condition DIV/DIVU Result REM/REMU Result
rs2 == 0 0xFFFF_FFFF rs1
rs1 == INT_MIN and rs2 == -1 (signed) rs1 (INT_MIN) 0

These are detected combinationally before the iterative loop starts (mdu_corner_case signal), bypassing all 34 cycles.

Implementation Tip — DIV in ISR: Division must never be used inside interrupt
service routines unless the ISR explicitly saves the MDU state. Since the iterative
divider is fully contained within mdu.v and the pipeline stalls the front stages,
a trap arriving during a DIV will stall until mdu_done before the trap sequence
begins. Factor the worst-case 34-cycle MDU stall into the RTOS interrupt latency
budget (see ISA ref §9.5). For FreeRTOS at 100 MHz with a 1 ms tick period:
34 cycles ≪ 100,000 cycles — comfortably within budget.

10. A-Extension — Atomic Memory Unit

10.1 AMU Architecture Overview

The Atomic Memory Unit (amu.v) implements LR.W, SC.W, and all nine AMO word instructions. It is instantiated in the DE stage and interacts directly with the DTCM interface and AXI4-Lite master.

The AMU contains three sub-components:

  1. Reservation Register — holds the reserved physical address and a resv_valid flag.
  2. AMO Sequencer FSM — drives read-modify-write cycles on the DTCM or AXI bus.
  3. Bus-Hold Arbitration — asserts stall_if and stall_de for the duration of an atomic operation.

10.2 Reservation Set Logic

// Reservation granule: 32 bytes (bits [4:0] of address are masked)
localparam GRANULE_BITS = 5;

reg [31:GRANULE_BITS] resv_tag;
reg                   resv_valid;

// LR.W: set reservation
if (amu_lr_w && !stall_de) begin
    resv_tag   <= dmem_addr[31:GRANULE_BITS];
    resv_valid <= 1'b1;
end

// SC.W: check reservation
sc_success = resv_valid && (dmem_addr[31:GRANULE_BITS] == resv_tag);

// Invalidation: any store to same granule, or any exception/interrupt
if ((dmem_we && (dmem_addr[31:GRANULE_BITS] == resv_tag)) ||
    trap_vld || mret)
    resv_valid <= 1'b0;

Implementation Note — DMA Invalidation: Any AXI master (DMA controller, external
debug probe) writing to the same 32-byte granule as the reservation will assert the
AXI BRESP on the monitored granule address. The AMU monitors the AXI interconnect
WADDR[31:5] on all write channels via a sideband axi_snoop_addr port. If a match
occurs while resv_valid == 1, the reservation is immediately invalidated. IoT DMA
channels must not be configured to target the reservation granule during lock-critical
sections.

11. C-Extension — Pre-Decode Expander

11.1 Placement in Pipeline

The C-Expander (c_expand.v) sits between the ITCM output and the IF/DE pipeline register, operating purely combinationally within the IF stage. All 16-bit instructions are expanded to their 32-bit canonical equivalents before the if_de_instr register is written. The DE stage decoder therefore always sees a 32-bit instruction and requires no knowledge of the C extension.

ITCM_rdata[31:0]

11.3 Expansion Logic — Critical Cases

The following encodings require special handling beyond simple field remapping:

16-bit Expansion Rule Critical Detail
C.ADDI4SPN ADDI rd', sp, nzuimm Trap nzuimm == 0 as illegal instruction
C.LUI rd, nzimm LUI rd, nzimm Trap nzimm == 0 or rd == x2 as illegal
C.ADDI16SP ADDI sp, sp, nzimm Detected by rd == x2; trap nzimm == 0

Implementation Tip — Illegal C Encoding: Any undefined C encoding (reserved
encodings per the RISC-V spec) must expand to a 32-bit ILLEGAL pattern
(32'hFFFF_FFFF) so that the decoder in DE generates de_illegal = 1 and triggers
an Illegal Instruction exception (mcause = 0x0000_0002). This is critical for
correct RTOS behavior — undefined instructions in RTOS-generated code are almost
always a linker script or toolchain configuration error that should be trapped loudly.

11.4 Immediate Reconstruction Examples

C-extension immediates are non-contiguous in the 16-bit encoding. The expander must reassemble them:

C.LW uimm[6:2] from inst[12:10,6:5]:

uimm = {inst[5], inst[12:10], inst[6], 2'b00};   // uimm[6:2] → byte offset

C.J / C.JAL imm[11:1] from scattered bits:

imm = {inst[12], inst[8], inst[10:9], inst[6],
       inst[7], inst[2], inst[11], inst[5:3], 1'b0};

C.BEQZ / C.BNEZ imm[8:1]:

imm = {inst[12], inst[6:5], inst[2], inst[11:10], inst[4:3], 1'b0};

13.2 Trap Controller (trap_ctrl.v)

The trap controller arbitrates between simultaneous interrupt sources and exceptions, serialises the CSR update sequence, and generates the PC redirect signal.

Interrupt priority logic (from ISA ref §9.1):

// Priority: MEI > MSI > MTI
always_comb begin
    trap_vld   = 1'b0;
    trap_cause = 32'h0;

    if (mstatus_MIE) begin
        if (mip_MEIP & mie_MEIE) begin
            trap_vld   = 1'b1;
            trap_cause = 32'h8000_000B;   // Machine External Interrupt
        end else if (mip_MSIP & mie_MSIE) begin
            trap_vld   = 1'b1;
            trap_cause = 32'h8000_0003;   // Machine Software Interrupt
        end else if (mip_MTIP & mie_MTIE) begin
            trap_vld   = 1'b1;
            trap_cause = 32'h8000_0007;   // Machine Timer Interrupt
        end
    end

    // Exceptions always taken regardless of MIE
    if (de_wb_exc_vld) begin
        trap_vld   = 1'b1;
        trap_cause = de_wb_exc_cause;     // mcause from ISA ref §8.6
    end
end

Trap entry sequence (5 cycles, matches ISA ref §9.2):

Cycle Action
N (detect) trap_vld asserted in WB; flush_if, flush_de asserted
N+1 mepc ← PC_of_faulting_instr; mcause ← trap_cause; mtval ← fault_addr_or_0
N+2 mstatus.MPIE ← mstatus.MIE; mstatus.MIE ← 0; mstatus.MPP ← 2'b11
N+3 PC ← mtvec (Direct) or mtvec.BASE + (4 × cause[4:0]) (Vectored)
N+4 First instruction of trap handler enters IF

13.3 mtvec Vectored Mode Address Computation

// mtvec MODE field (ISA ref §8.5)
wire [1:0] mtvec_mode  = mtvec[1:0];
wire [31:2] mtvec_base = mtvec[31:2];

assign trap_pc = (mtvec_mode == 2'b01 && trap_cause[31]) ?
                 // Vectored mode for interrupts only
                 {mtvec_base, 2'b00} + (trap_cause[4:0] << 2) :
                 // Direct mode for all others
                 {mtvec_base, 2'b00};

RTOS Tip — Vectored mtvec: For FreeRTOS, configure mtvec with MODE=01 (Vectored).
The machine timer interrupt (mcause = 0x8000_0007, cause[4:0] = 7) will vector to
BASE + 28, directly to the tick ISR entry, saving approximately 8 cycles of dispatch
overhead per tick compared to a software switch in Direct mode. Place the vector table
at a 64-byte aligned address to ensure all 12 vector slots fit within a single
cache-line-sized region and avoid AXI latency on the first vector fetch.

16.1 Critical Paths

The following paths are most likely to limit Fmax on Artix-7 −1 and must be constrained with appropriate set_multicycle_path or pipelining in the RTL:

Timing Closure Tip — Branch Path: The deepest combinational path in the design is
the branch-taken path: BRU condition eval → pc_sel mux → PC register input. In
Vivado, constrain this with:
tcl set_max_delay -datapath_only -from [get_cells de_stage/bru/*] \ -to [get_cells if_stage/pc_reg*] 9.0

and accept the 2-cycle branch penalty (update CPI model accordingly: change the

MMCM_LOCKED output to prevent the core from starting before the clock is stable.
This is especially important for the RTOS tick timer — a glitched mtime value at
startup can cause a spurious tick interrupt before the RTOS scheduler is initialised.

16.3 Power Optimization for IoT

Power Tip — Clock Gating: Synthesize the MDU with clock gating: assert
mdu_clk_en only when de_is_mdu = 1 or mdu_busy = 1. On a typical IoT sensor
workload (mostly GPIO polling, UART reads, and light arithmetic), the MDU is active
less than 1% of the time. Using BUFGCE primitives to gate the MDU clock can reduce
dynamic power by 5–10 mW at 100 MHz on Artix-7.

Power Tip — BRAM Sleep Mode: Configure DTCM BRAMs with the SLEEP port connected
to a power management register bit when the core is halted via WFI (Wait For
Interrupt). Artix-7 RAMB36E1 in sleep mode consumes < 0.5 mW vs ~8 mW active.
The RTOS idle task should execute WFI when the run queue is empty:
asm void vApplicationIdleHook(void) { __asm volatile ("wfi"); }

Power Tip — DDR3 Access Reduction: For latency-sensitive IoT paths, ensure all
hot-path code and data structures reside in ITCM/DTCM (0x0000_4000 / 0x2000_0000).
DDR3 accesses via the MIG controller dissipate approximately 20× more energy per
access than DTCM. Use the RTOS heap allocator to place FreeRTOS task stacks and
queues in DTCM by defining configAPPLICATION_ALLOCATED_HEAP = 1 and placing the
heap array in the .dtcm_data linker section.
