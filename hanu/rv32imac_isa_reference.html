RV32IMAC ISA Reference Document

Single Source of Truth — Hardware Implementation & Software Toolchain

Project Context: This document defines the ISA specification for an RV32IMAC soft-core processor
targeting the Xilinx Artix-7 FPGA (Nexys Video board). The implementation uses a 3-stage
in-order pipeline (Fetch → Decode/Execute → Writeback) optimized for area efficiency and
deterministic timing, suitable for IoT RTOS workloads (e.g., FreeRTOS, Zephyr RTOS).
All design decisions herein balance FPGA resource constraints against real-time responsiveness.

The mtime register increments at a fixed 10 MHz reference clock, independent of core frequency.

$$T_{tick} = \frac{1}{f_{ref}} = \frac{1}{10 \times 10^6} = 100\ \text{ns per tick}$$

3. Register File — RV32I Base

3.1 Integer Register File (x0–x31)

The core implements 32 general-purpose 32-bit registers. Register x0 is hardwired to zero; writes are silently discarded.

Register ABI Name Role Saved By
x0 zero Hardwired zero —
x1 ra Return address Caller
x2 sp Stack pointer Callee
x3 gp Global pointer —
x4 tp Thread pointer —
x5 t0 Temporary / alt link register Caller
x6–x7 t1–t2 Temporaries Caller
x8 s0/fp Saved register / frame pointer Callee
x9 s1 Saved register Callee
x10–x11 a0–a1 Function arguments / return values Caller
x12–x17 a2–a7 Function arguments Caller
x18–x27 s2–s11 Saved registers Callee
x28–x31 t3–t6 Temporaries Caller

Implementation Note (Artix-7): The 32×32 register file is implemented as a
synchronous BRAM with a dedicated forwarding bypass path. Two read ports and one
write port are synthesized using SDP (Simple Dual-Port) BRAM primitives. The
forwarding unit resolves RAW hazards within the 3-stage pipeline with zero stall
cycles for ALU→ALU sequences.

3.2 Program Counter (PC)

  • Width: 32 bits
  • Reset value: 0x0000_0000 (Boot ROM entry point)
  • Alignment: Must be 4-byte aligned for 32-bit instructions; 2-byte aligned for compressed (C-extension) instructions
  • Misaligned fetch raises: Instruction Address Misaligned exception (mcause = 0)

$$\text{PC}_{next} = \begin{cases} \text{PC} + 4 & \text{normal flow (32-bit)} \ \text{PC} + 2 & \text{compressed instruction} \ \text{target} & \text{branch/jump taken} \end{cases}$$

Implementation Note: All load/store operations to the DTCM complete in 1 cycle.
Accesses to external DDR3 incur variable latency (typically 10–40 cycles via MIG).
The pipeline stalls by inserting bubble cycles; no out-of-order execution is performed.

4.5 Branch Instructions

Mnemonic funct3 Condition Target
BEQ 000 rs1 == rs2 PC ← PC + sx(imm)
BNE 001 rs1 != rs2 PC ← PC + sx(imm)
BLT 100 rs1 <ₛ rs2 PC ← PC + sx(imm)
BGE 110 rs1 ≥ₛ rs2 PC ← PC + sx(imm)
BLTU 110 rs1 <ᵤ rs2 PC ← PC + sx(imm)
BGEU 111 rs1 ≥ᵤ rs2 PC ← PC + sx(imm)

Branch offset is 13-bit signed (range: −4096 to +4094 bytes).

Branch Penalty: The 3-stage pipeline always incurs a 1-cycle branch penalty (fetch bubble). No branch predictor is implemented; all branches are assumed not-taken.

$$\text{CPI}{\text{branch}} = 1 + P \cdot 1$$}

Where $P_{\text{taken}}$ is the probability of the branch being taken.

4.6 Jump Instructions

Mnemonic Format Operation
JAL rd, imm J-type rd ← PC+4; PC ← PC + sx(imm[20:1])
JALR rd, rs1, imm I-type rd ← PC+4; PC ← (rs1 + sx(imm)) & ~1

RTOS Note: JAL x0, imm (infinite loop with ra discarded) is the canonical
RISC-V idiom for a bare spin-loop. FreeRTOS uses JALR x0, x1, 0 for function
returns. The & ~1 masking in JALR clears the LSB, allowing Thumb-like encoding
hints without hardware mode switching.

5. Multiply/Divide Extension (M)

5.1 Instruction Encoding (R-type, opcode = 0110011, funct7 = 0000001)

Mnemonic funct3 Operand Types Result
MUL 000 Signed × Signed Lower 32 bits of 64-bit product
MULH 001 Signed × Signed Upper 32 bits of 64-bit product
MULHSU 010 Signed × Unsigned Upper 32 bits
MULHU 011 Unsigned × Unsigned Upper 32 bits
DIV 100 Signed ÷ Signed Quotient
DIVU 101 Unsigned ÷ Unsigned Quotient
REM 110 Signed % Signed Remainder
REMU 111 Unsigned % Unsigned Remainder

5.2 MUL / MULH Implementation

The 32×32→64 bit multiplier is implemented using a Booth-encoded 2-cycle pipelined multiplier mapped to Artix-7 DSP48E1 slices.

$$\text{MUL: } rd = (rs1 \times rs2)[31:0]$$

$$\text{MULH: } rd = (rs1 \times rs2)[63:32]$$

Implementation Note (Artix-7 DSP48E1): Two DSP48E1 slices are cascaded to produce
the full 64-bit result. MULH, MULHSU, and MULHU each require sign/zero extension
before the multiply. The multiplier introduces a 2-cycle latency; the pipeline
inserts one bubble automatically via a stall signal from the Decode stage hazard unit.

Timing estimate (Artix-7 -1 speed grade):

$$T_{MUL} = T_{DSP48} + T_{cascade} \approx 3.2\ \text{ns} + 0.4\ \text{ns} = 3.6\ \text{ns}$$

This satisfies a 10 ns clock period (100 MHz) with positive slack.

5.3 DIV / REM Implementation

Division is implemented via a non-restoring iterative algorithm (32 iterations, one bit per cycle).

$$\text{Latency: } L_{DIV} = 32 + 2\ \text{(overhead cycles)} = 34\ \text{cycles}$$

RTOS Warning: Avoid division in ISR context unless the ISR stack is sized to
accommodate 34-cycle stalls. For FreeRTOS, configure configUSE_PREEMPTION = 1
and ensure the tick timer interrupt latency budget accounts for worst-case division.

Corner Case Behavior (mandated by RISC-V spec):

Condition DIV/DIVU Result REM/REMU Result
Division by zero 0xFFFF_FFFF (−1) rs1 (dividend)
Signed overflow (INT_MIN / −1) rs1 (INT_MIN) 0

6. Atomic Extension (A)

6.1 Overview

Atomic instructions use opcode 0101111. They include a 2-bit ordering field:

aq rl Ordering Semantics
0 0 Relaxed (no ordering guarantees)
1 0 Acquire (no loads/stores after can move before this)
0 1 Release (no loads/stores before can move after this)
1 1 Sequentially consistent

RTOS Implementation Note: FreeRTOS spinlocks and queue primitives require
acquire semantics on loads and release semantics on stores. Use
LR.W aq=1, rl=0 / SC.W aq=0, rl=1 pairs for all critical-section entry/exit.

6.2 Load-Reserved / Store-Conditional (LR.W / SC.W)

LR.W — Load Reserved Word
Encoding: [ 00010 | 00000 | rs1 | 010 | rd | 0101111 ]

Operation:
1. Load the word at address rs1 into rd
2. Register a reservation on the cache line containing rs1
3. The reservation is valid until a matching SC.W or any exception/interrupt

$$\text{LR.W: } rd \leftarrow M[rs1],\quad \text{Reservation} \leftarrow rs1$$

SC.W — Store Conditional Word
Encoding: [ 00011 | rs2 | rs1 | 010 | rd | 0101111 ]

Operation:
1. If reservation on rs1 is valid: write rs2 to M[rs1], set rd ← 0 (success)
2. If reservation is invalid: do not write, set rd ← 1 (failure)

$$\text{SC.W: } \begin{cases} M[rs1] \leftarrow rs2,\ rd \leftarrow 0 & \text{if reservation valid} \ rd \leftarrow 1 & \text{if reservation invalid} \end{cases}$$

Canonical LR/SC Mutex Pattern
lock:
    li      t0, 1               # lock value = 1
retry:
    lr.w.aq t1, (a0)            # load-reserved from lock address
    bnez    t1, retry           # spin if already locked
    sc.w.rl t1, t0, (a0)        # attempt store-conditional
    bnez    t1, retry           # retry if SC failed
    ret

unlock:
    sw      zero, 0(a0)         # unconditional store clears lock
    ret

Reservation Granule: In this implementation, the reservation granule is
one cache line (32 bytes). Any store to the same granule by any agent
(DMA, other harts, AXI masters) will invalidate the reservation. This must
be factored into IoT peripheral DMA configuration.

7. Compressed Extension (C)

7.1 Overview

The C extension defines 16-bit instruction encodings sharing opcode space via quadrants identified by inst[1:0]:

inst[1:0] Quadrant
00 Q0 — Load/Store
01 Q1 — Control / Arithmetic
10 Q2 — Register / Stack
11 (32-bit instruction — not C extension)

Fetch Unit Note: The instruction fetch unit must detect inst[1:0] != 11
to identify a 16-bit instruction and advance PC by 2 instead of 4. The decode
stage expands the 16-bit encoding to its 32-bit equivalent before execution.

9. Interrupt & Exception Handling

9.1 Interrupt Priority

Priority is evaluated in the following order (highest first):

$$\text{Priority: MEI} > \text{MSI} > \text{MTI}$$

  1. Machine External Interrupt (MEI) — PLIC-aggregated peripheral IRQs
  2. Machine Software Interrupt (MSI) — CLINT msip register write
  3. Machine Timer Interrupt (MTI) — mtime ≥ mtimecmp

9.2 Trap Entry Sequence

When a trap is accepted (interrupt or exception), the hardware performs atomically:

1. mepc   ← PC of interrupted/faulting instruction
2. mcause ← trap cause code
3. mtval  ← faulting address (if applicable) or 0
4. mstatus.MPIE ← mstatus.MIE
5. mstatus.MIE  ← 0           # Disable interrupts
6. mstatus.MPP  ← current_privilege (always 11 = Machine)
7. PC ← mtvec (Direct) OR mtvec.BASE + 4×cause (Vectored)

Trap Latency:

$$L_{trap} = L_{pipe_flush} + L_{csr_write} = 2 + 3 = 5\ \text{cycles (worst case)}$$

Determinism Note: The 5-cycle trap latency is deterministic for ITCM/DTCM accesses.
If a trap occurs during a multi-cycle instruction (e.g., DIV at cycle 20/34), the
instruction is aborted and the pipeline is flushed before the trap sequence begins.
mepc is set to the address of the aborted instruction, which will be re-executed on
MRET. Ensure idempotency of instructions that may be interrupted mid-execution.

9.3 Trap Return — MRET

MRET

Hardware sequence:

1. PC           ← mepc
2. mstatus.MIE  ← mstatus.MPIE
3. mstatus.MPIE ← 1
4. mstatus.MPP  ← 11 (Machine)

9.4 Canonical RTOS ISR Context Switch (FreeRTOS)

    .global trap_handler
    .align  4
trap_handler:
    # Save caller-saved registers to current task's stack
    addi    sp, sp, -128
    sw      ra,   0(sp)
    sw      t0,   4(sp)
    sw      t1,   8(sp)
    # ... (t2–t6, a0–a7)

    # Save mepc and mstatus for nested interrupt support
    csrr    t0, mepc
    sw      t0, 120(sp)
    csrr    t0, mstatus
    sw      t0, 124(sp)

    # Identify cause and dispatch
    csrr    a0, mcause
    li      t0, 0x80000007      # Machine timer interrupt
    beq     a0, t0, timer_isr

    # ... other handlers

timer_isr:
    call    vTaskSwitchContext  # FreeRTOS scheduler
    # Update mtimecmp for next tick
    li      t0, CLINT_BASE
    lw      a0, 0xBFF8(t0)      # Read mtime low
    li      a1, TICK_CYCLES
    add     a0, a0, a1
    sw      a0, 0x4000(t0)      # Write mtimecmp

    # Restore context
    lw      t0, 120(sp)
    csrw    mepc, t0
    lw      t0, 124(sp)
    csrw    mstatus, t0
    lw      ra,   0(sp)
    # ... restore remaining registers
    addi    sp, sp, 128
    mret

9.5 Interrupt Latency Budget (RTOS Tick = 1 ms)

$$f_{core} = 100\ \text{MHz},\quad T_{tick} = 10\ \text{ms (configurable)}$$

$$T_{RTOS_tick} = \frac{1}{1000\ \text{Hz}} = 1\ \text{ms} = 100{,}000\ \text{cycles}$$

Phase Cycles Notes
Trap detection 1 End of current EX stage
Pipeline flush 2 Fetch + Decode bubbles
CSR atomic update 3 mepc, mcause, mstatus
ISR prologue (context save) ~40 10 registers × 4 cycles (DTCM)
FreeRTOS tick body ~200 Scheduler + list walk
ISR epilogue (restore) ~40
MRET + refill 3
Total worst case ~289 cycles < 0.3% overhead at 100 MHz

10.3 CPI Model

$$\text{CPI} = 1 + \text{stall_cycles_per_instruction}$$

$$\text{CPI}_{typical} \approx 1 + (0.1 \times 1) + (0.05 \times 1) + (0.001 \times 33) = 1.183$$

Where approximate instruction mix fractions are assumed: 10% load-use, 5% branches, 0.1% division.

FPGA Resource Estimate (Artix-7, xc7a200t):
- LUTs: ~2,800 (core logic, excluding multiplier/BRAM)
- FFs: ~1,400
- BRAM: 4× RAMB36E1 (32KB ITCM + 32KB DTCM)
- DSP48E1: 2 (multiplier)
- Fmax: ~110 MHz (−1 speed grade, post-place-and-route estimate)
