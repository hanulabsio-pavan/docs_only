0The Golden Rule

There are two types of files in this project. Knowing which is which prevents the most common and most dangerous mistakes.

DESIGN FILES

Files you create and edit. The source of truth.

e.g. KiCad .kicad_sch, C source .c, STEP enclosure files.

PRODUCTION FILES

Files exported from design files for manufacturing. Never edit directly.

e.g. Gerbers, BOM CSV, STL for print, firmware .bin.

If a conflict ever exists between a production file and its design source, the design source always wins. Regenerate the production file; never patch it by hand.

10Git Workflow for Hardware

  1. Never commit Gerbers without a version bump — they are production files; silent overwrites are dangerous.
  2. BOM and schematic commit together — they must always be in sync.
  3. Certification docs are immutable once approved — never edit approved BIS/WPC files.
  4. Design files are the source — if a Gerber and the KiCad source conflict, the source wins.
  5. Tag firmware releases — every build sent for certification must be a git tag (v1.0.0).
# Example: a hardware revision git checkout -b hw/pcb-v1.1-thermal-fix # ...edit PCB in KiCad, re-export Gerbers to gerbers/v1.1/, update BOM... git add hardware/ manufacturing/gerbers/v1.1/ git commit -m "PCB v1.1: add thermal vias under U3 (ESP32-S3)" git checkout main && git merge hw/pcb-v1.1-thermal-fix
