1. Design Goals & Constraints

#GoalDriving Constraint
G1Instant, reliable touch responseTouch-to-relay latency budget < 50 ms end-to-end. Touch works even with WiFi/cloud down.
G2Local-first controlAll gang on/off logic runs on-device; cloud is an enhancement, never a dependency.
G3Always-recoverableNo OTA, network glitch, or crash may leave a relay stuck or the device bricked. Watchdog + A/B OTA + rollback.
G4Matter + app + voice parityEvery control path drives the same state machine — one source of truth per gang.
G5Low standby powerBoard budget < 2 W quiescent; firmware uses light-sleep + modem-sleep when idle.
G6Secure by defaultSecure Boot v2 + Flash Encryption + signed OTA + TLS 1.2/1.3. No plaintext secrets in flash.
G7Field-updatableOTA from day one; telemetry + remote diagnostics for the 500u pilot fleet.
G8CertifiableWPC uses the pre-certified WROOM module radio — firmware must not alter RF calibration or use a custom antenna.

Hard vs. soft real-time split: the hard path (touch → debounce → relay GPIO) runs at high RTOS priority and is never blocked by network I/O. WiFi, Matter, MQTT, OTA, telemetry and voice inference are soft, lower-priority and fully preemptible.

5. RTOS Task Graph

FreeRTOS SMP across two LX7 cores. Core 0 hosts the WiFi/BT stacks (pinned by ESP-IDF); Core 1 hosts the time-critical control tasks so radio activity never delays touch→relay.

tsk_touch193 KBALERT ISR → semRead CAP1296 over I2C, debounce, emit EVT_TOUCH
tsk_control184 KBevent busOwns gang state machines; only task that drives relay GPIO
tsk_event_bus173 KBqueueCentral pub/sub router (fan-out)
tsk_voice1616 KB + PSRAMI2S ring bufWake-word + command inference (Phase 2)
tsk_wifi054 KBevent groupWiFi connect/reconnect + provisioning
tsk_matter058 KBMatter stackESP-Matter loop, attribute callbacks
tsk_mqtt045 KBevent groupCloud MQTT pub/sub, command intake
tsk_led142 KBtimer + eventsStatus LEDs / theme animations via LEDC
tsk_ota038 KBon-demandDownload + verify + write OTA image
tsk_telemetry023 KBtimerHeartbeat + metrics publish

Priority rationale: tsk_touch (9) > tsk_control (8) > tsk_event_bus (7) > tsk_voice (6) > network (3–5) > telemetry (2). The hard path always preempts everything on Core 1; network/OTA on Core 0 can never stall a relay action.

6. Event Bus (Central Messaging)

All cross-module communication uses one typed event bus instead of ad-hoc notifications. This decouples sources of control (touch, app, Matter, voice, schedule) from the one consumer that mutates relay state (tsk_control).

// include/setu_events.h
typedef enum {
    EVT_TOUCH,            // a touch zone was pressed/released/held
    EVT_CMD_SET,          // set gang N on/off/level (app/matter/cloud)
    EVT_VOICE_INTENT,     // voice classifier produced an intent
    EVT_SCHED,            // automation/schedule fired
    EVT_THEME_SET,        // activate a theme
    EVT_STATE_CHANGED,    // gang/device state changed (fan-out to reporters)
    EVT_CONN_CHANGED,     // connectivity bit changed
    EVT_OTA_PROGRESS,     // OTA lifecycle
    EVT_FAULT,            // driver/system fault
} setu_event_id_t;

typedef struct {
    setu_event_id_t id;
    uint8_t         gang;     // 0..N-1, or GANG_ALL
    int32_t         value;    // on/off, level, intent code…
    setu_src_t      source;   // SRC_TOUCH, SRC_APP, SRC_MATTER, SRC_CLOUD, SRC_VOICE, SRC_SCHED
    uint32_t        ts_ms;
} setu_event_t;

Publish: event_bus_post(&evt) (ISR-safe variant event_bus_post_isr). Subscribe: tasks register a callback + event-id mask; the bus fans out. Every event carries its source, used for arbitration, telemetry attribution, and echoing state back to the other control surfaces (a touch press updates the Matter attribute + cloud shadow + LED).

7. Boot & Initialization Sequence

app_main() is a deterministic init sequencer — safety-critical I/O first, network last, so the device is locally usable within ~200 ms even before WiFi.

sequenceDiagram participant Boot as 2nd-stage bootloader participant App as app_main participant HAL participant DRV as drivers participant SVC as middleware Boot->>Boot: Secure Boot verify → select OTA slot Boot->>App: jump to app App->>App: esp_event_loop + NVS init (encrypted) App->>HAL: board_init() — GPIO, I2C, LEDC, power_mgmt App->>DRV: relay_init() — ALL RELAYS OFF (safe default) App->>SVC: config_store_load() — restore last states + theme App->>DRV: relay_restore(saved) — re-apply if configured App->>DRV: touch_cap1296_init() — thresholds, enable ALERT App->>DRV: led_status_init() — boot animation App->>App: event_bus_init() + spawn control/touch/led tasks App->>SVC: ota_mark_valid() — confirm image healthy (cancel rollback) App->>SVC: wifi_mgr_start() — connect or provisioning SVC-->>App: WIFI_UP / IP_GOT App->>SVC: time_sync, matter, mqtt, telemetry, voice (Phase 2) Note over App: Device locally functional before this line;
cloud/voice are enhancements
Safe-state guarantee relay_init() drives all gangs OFF before anything else. Restoring last-known state is an explicit, configurable step (restore_on_boot) — "all off" and "restore" are both available per the power-loss policy, so loads never energize unexpectedly after a power blip.

8. Driver Layer

8.1 Touch Driver — touch_cap1296.c

  • Bus: I2C master @ 400 kHz, guarded by mtx_i2c.
  • Interrupt-driven: CAP1296 ALERT (active-low) → GPIO5 ISR → xSemaphoreGiveFromISR. No polling — saves power and meets the latency budget.
  • tsk_touch flow: wait on semaphore → read Main/Sensor status → clear INT → map channel→gang → debounce → emit EVT_TOUCH (press/hold/release).
  • Gestures: short tap = toggle; long-hold (≥800 ms) = theme cycle / dim ramp; multi-touch reserved for scenes.
  • Config: per-channel sensitivity, 50 Hz mains noise filter (critical inside a 230 VAC box), active shield (CS_SHLD), standby/active groups.
  • Resilience: I2C NACK/hang → bus recovery → re-init; emit EVT_FAULT(TOUCH_BUS) if persistent. Touch failure must not crash control of already-on loads.

8.2 Relay Driver — relay.c

  • Output: GPIO7–10 → 1 kΩ → BSS138 gate → relay coil (active-high = load ON). Mirrors the HW pin map.
  • Single-writer: only tsk_control calls relay_set(); all other paths post events. Eliminates load races.
  • Debounce / anti-chatter: min dwell between toggles (default 300 ms) protects contacts (100 K electrical ops).
  • Interlock hooks: optional mutual-exclusion groups for future motorized loads.
  • State readback: firmware holds commanded state authoritatively (no contact-sense in baseline HW); persisted to NVS.
  • Inrush staggering: multi-gang restore/theme energizes relays with a few-ms stagger to limit inrush.

8.3 LED Status Driver — led_status.c

  • Channels: GPIO11–14 per-gang + GPIO15 WiFi LED via LEDC (PWM) for brightness/breathing.
  • Semantics: solid = ON; off = OFF; WiFi LED — slow blink = provisioning, fast = connecting, solid = cloud up, double-blink = OTA, error patterns for faults.
  • Theme animations: tmr_led_anim @ ~30 Hz drives scene effects (Party chase, Devotional warm glow). RGB is a future variant.
  • Night dimming: auto-dim on Sleep theme / after sunset via time_sync.

8.4 Audio / Mic Driver — audio_i2s.c Phase 2

I2S MEMS mic on GPIO16/17/18 (Phase 2+ per HW pin map). DMA into a ring buffer feeding tsk_voice; compiled out in Phase 1 builds via Kconfig.

8.5 Button Driver — button.c

Handles EN/reset and a factory-reset gesture (long-press combo) → FACTORY_RESET_REQ → config_store wipe + re-provision.

9. Middleware / Services

9.1 WiFi Manager — wifi_mgr.c

State machine IDLE → PROVISIONING → CONNECTING → CONNECTED → (RECONNECT backoff) → CONNECTED. BLE/SoftAP provisioning on first boot; creds in encrypted NVS (never logged); exponential jittered backoff (1→60 s cap); modem-sleep when idle. WiFi loss never affects local touch control.

9.2 Matter Service — matter_svc.c

Built on ESP-Matter / connectedhomeip. Each gang is an On/Off endpoint (+ Level Control where dimming applies). Matter writes → EVT_CMD_SET; EVT_STATE_CHANGED → attribute report. Matter-over-WiFi (no 802.15.4 radio → no Thread). Multi-admin / multi-fabric; commissioning payload provisioned at factory.

9.3 Cloud MQTT — cloud_mqtt.c

  • MQTT over TLS 1.2/1.3; server-auth via CA bundle, device-auth via per-device X.509 cert (encrypted NVS / eFuse-bound).
  • Topics: setu/<id>/state, /cmd, /ota, /telemetry.
  • Publishes consolidated state on every EVT_STATE_CHANGED; reconciles desired-vs-reported on reconnect. Cloud is an enhancement (remote control, voice ASR fallback, telemetry, OTA trigger).

9.4 OTA Manager — ota_mgr.c

Summary — full design in SETU_OTA_Update_Protocol.md
  • Mechanism: esp_https_ota over TLS; image from a signed URL via MQTT ota topic.
  • A/B partitions: ota_0/ota_1 + otadata. Download to inactive slot, verify signature + SHA-256, set boot, reboot.
  • Signed images: Secure Boot v2 (RSA-3072) checked by bootloader and app before commit.
  • Rollback: new image boots pending-verify; app_main self-tests then calls esp_ota_mark_app_valid_cancel_rollback(). A crash/WDT-reset before validation auto-reverts to the last good slot.
  • Safety: OTA refused mid high-power transition; relays hold state across reboot; OTA_IN_PROGRESS blocks conflicting actions.

9.5 Voice Engine — voice_engine.c Phase 2

  • On-device wake-word ("Hey SETU") via ESP-SR / TFLite-Micro in PSRAM (the N8R8's 8 MB PSRAM exists for this).
  • Pipeline: I2S mic → ring buffer → AFE (noise suppression / AEC) → wake-word → command classifier → EVT_VOICE_INTENT.
  • Hybrid: small fixed command set recognized on-device; open-ended phrases optionally to cloud ASR when connected.
  • Themes by voice: intents map to EVT_THEME_SET (Devotional, Party, Movie, Sleep, Morning).
  • Privacy: audio processed locally; nothing streamed unless a wake-word fired and cloud ASR is user-enabled.

9.6 Config Store — config_store.c

NVS over an encrypted dedicated partition. Namespaces:

9.7 Time Sync — time_sync.c

SNTP after IP; timezone IST (Asia/Kolkata). Drives schedules, sunset/sunrise automation, log timestamps. Falls back to relative timers when offline.

9.8 Telemetry — telemetry.c

Heartbeat: uptime, free/min-free heap, RSSI, reset reason, OTA version, per-gang switch counts, fault counters. For pilot-fleet monitoring; rate-limited and dropped silently offline.

9.9 Provisioning — provisioning.c

First-boot / factory-reset flow: BLE or SoftAP credential entry and Matter commissioning + device-cert binding; coordinates with wifi_mgr and matter_svc.

10. Application Layer

10.1 Device Model — device_model.c

Global, mutex-guarded singleton — the single source of truth. Every control surface reads/writes it only through tsk_control (via events); every change fans out via EVT_STATE_CHANGED and is persisted.

typedef struct {
    gang_state_t gang[SETU_GANG_COUNT];  // {on/off, level, name, group, last_change_ts}
    theme_t      active_theme;
    bool         locked;                  // child-lock / cleaning mode
    conn_state_t conn;                    // mirror of eg_connectivity
    fw_info_t    fw;                       // version, build, running slot
} device_model_t;

10.2 Per-Gang State Machine — gang_sm.c

stateDiagram-v2 [*] --> OFF OFF --> ON: CMD(on) / TOUCH(tap) / theme ON --> OFF: CMD(off) / TOUCH(tap) / theme ON --> ON: level change (dim variant) OFF --> LOCKED: lock engaged ON --> LOCKED: lock engaged LOCKED --> OFF: unlock

Arbitration: last-writer wins, but touch takes precedence over a stale cloud command (touch carries a fresh timestamp). Relay GPIO is driven only here; debounce dwell is enforced; state is persisted.

Local schedules and rules (timer on/off, sunset-triggered, Morning ramp) run on-device so automations fire even when the cloud is unreachable; the cloud only edits the rule set.

13. Fault Handling, Watchdog & Recovery

  • Task Watchdog: tsk_control, tsk_touch, tsk_event_bus must feed within window; a stall → logged panic + reset.
  • Interrupt WDT + brownout detector enabled (brownout important on the 230 VAC-derived rail).
  • Safe state on fault: unrecoverable fault → NVS crash-counter → reset. Relay GPIOs default to a defined state out of reset; boot policy decides restore-vs-off.
  • Crash diagnostics: esp_core_dump to the storage partition; reset reason + summary published via telemetry next boot.
  • OTA self-heal: pending-verify + rollback recovers from a bad update automatically.
  • Network resilience: network tasks are restart-safe; their failure degrades features, never the local switch.

13.1 Dual-MCU Fallback (non-baseline)

If a variant reintroduces the STM32L0 for touch, the ESP32-S3 firmware adds inter_mcu.c: a UART/SPI framed protocol (STM32→ESP32 touch events, ESP32→STM32 LED/config) with CRC + heartbeat. The event abstraction (§6) means only the touch source changes — tsk_control and above are unaffected.

17. Coding Standards & Conventions

  • Style: C11, Espressif style; clang-format enforced; Kconfig for all compile-time options.
  • Naming: setu_<module>_<action>(); types *_t; events EVT_*; GPIO/pins only in board.h.
  • Error model: functions return esp_err_t; ESP_ERROR_CHECK only in init/boot, never on the hard path (must degrade gracefully).
  • No blocking on the hard path: tsk_touch/tsk_control never call network/flash-erase APIs synchronously.
  • Logging: ESP_LOGx with per-module tags; no secrets; level gated by build profile.
  • Reviews: every PR maps to a module in this doc; new control surfaces route through the event bus, not relay_set() directly.
