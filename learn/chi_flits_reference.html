Overview
CHI Channel Architecture

CHI (Coherent Hub Interface) defines four independent channels. Each carries a flit — the atomic unit of transfer. A flit is not a packet; it is a single indivisible message with specific fields for routing, control, and payload. Each channel has its own credit-based flow control at the Link Layer.

// CHI Channel Overview — Who sends what to whom
REQRequest — initiates all transactions
RSPResponse — completions, credits, acks
DATData — actual cache line payload
SNPSnoop — cache state interrogation
REQ Channel
Request Channel

The REQ channel initiates all transactions. Sent by RN (Requester Node) to HN (Home Node), or by HN to SN for memory operations. Contains address, opcode, routing IDs, and memory attributes. Carries no data payload.

ReadShared0x01ReadRN-F → HN-FRead cache line, accept Shared Clean state. Other nodes may also hold it. Most common cache miss opcode.SC
ReadClean0x02ReadRN-F → HN-FRead cache line, must receive it in Clean state (not dirty). Useful when requester doesn't want dirty responsibility.SCUC
ReadNotSharedDirty0x03ReadRN-F → HN-FRead line — prefer not to receive SharedDirty state. HN attempts to satisfy from clean memory or clean sharer.SCUC
ReadUnique0x04ReadRN-F → HN-FRead line and obtain exclusive ownership. All other copies must be invalidated. Required before writing a line not already uniquely owned.UCUD
ReadPreferUnique0x1CReadRN-F → HN-FPreference for Unique state but accepts Shared. Used as optimistic exclusive-read hint when contention is unlikely.UCSC
ReadNoSnp0x07ReadHN-F → SN-FNon-coherent read from memory. Used by HN-F to fetch data from Slave Node (DDR). Bypasses coherency — no snoops involved.—
ReadOnce0x00ReadRN-F → HN-FRead line once — does not intend to cache long-term. Returns data without granting a persistent coherent state. Used for streaming/non-temporal reads.SC
ReadOnceMakeInvalid0x08ReadRN-F → HN-FRead once and immediately invalidate the line everywhere after reading. Used for destructive reads / consume semantics.I
CleanUnique0x11CMORN-F → HN-FUpgrade from SC to UC without fetching data. Requester already has the data clean. Forces invalidation of all other sharers. No data transfer.UC
MakeUnique0x12CMORN-F → HN-FInvalidate all other copies without providing data. Requester will overwrite entire cache line. Most efficient upgrade when writing full line.UC
MakeReadUnique0x18CMORN-F → HN-FRead and upgrade — combines ReadUnique and MakeUnique semantics in a single transaction for efficiency.UC
WriteBack0x22WriteRN-F → HN-FWrite dirty cache line back to memory on eviction. Requester had UD state. Data follows on DAT channel as CopyBackWrData.I
WriteClean0x23WriteRN-F → HN-FWrite back a line that is clean in memory but dirty in cache. Requester transitions to UC or I after write. Used when memory needs updating.UCI
WriteEvictFull0x15WriteRN-F → HN-FEvict a clean unique line. No data write needed if HN chooses not to accept. HN may discard or accept data.I
WriteNoSnpFull0x30WriteHN-F → SN-FNon-coherent write to memory. Used by HN-F to write dirty data to Slave Node. No snoops involved.—
WriteNoSnpPtl0x31WriteHN-F → SN-FNon-coherent partial write — only some bytes valid (indicated by BE field). Updates subset of a cache line in memory.—
WriteUniqueFullStash0x35WriteRN-F → HN-FWrite full line and stash (prefetch) a copy to a specific target cache identified by StashNID. Combines write + hint.—
StashOnceShared0x28WriteRN-F → HN-FPrefetch hint — stash a Shared copy to target node specified by StashNID. No data transfer, purely a hint. HN may ignore.—
StashOnceUnique0x29WriteRN-F → HN-FPrefetch hint — stash a Unique copy to target node. Hint only. Used for producer-consumer latency hiding.—
AtomicStore0x34AtomicRN → HNAtomic Store (write) to memory. Data carried in extended REQ flit. No return data. Operations: ADD, CLR, EOR, SET, SMAX, SMIN, UMAX, UMIN.—
AtomicLoad0x35AtomicRN → HNAtomic Load — read-modify-write returning original value. Same operations as AtomicStore. Returns old value on DAT channel.—
AtomicSwap0x36AtomicRN → HNAtomic Swap — unconditionally exchange memory value with provided value. Returns old value. Used for lock implementation.—
AtomicCompare0x37AtomicRN → HNAtomic Compare-and-Swap (CAS). Compares memory value with compare operand; if equal, swaps with swap operand. Foundation of lock-free algorithms.—
CleanShared0x13CMORN → HNCache Maintenance Op — clean (write back) all dirty copies of this line without invalidating. Used before DMA reads.—
CleanSharedPersist0x24CMORN → HNClean to persistent memory (PMem). Ensures data reaches persistent storage domain. Used in NVM-aware software.—
CleanInvalid0x14CMORN → HNClean and invalidate — write back dirty data then invalidate all copies. Used before DMA writes to ensure memory coherency.I
MakeInvalid0x09CMORN → HNInvalidate all copies without writeback (discards dirty data). Use only when data is known to be replaceable.I
DVMOp0x14DVMRN → MNDistributed Virtual Memory operation — TLB invalidate, branch predictor invalidate, instruction cache sync. Coordinated via MN (Misc Node).—
PCrdReturn0x05MiscRN → HNReturn a protocol credit previously granted by PCrdGrant. Credits returned when no longer needed for pending retried requests.—
SnpReq0x06SnoopRN → HNRequest HN to perform a directed snoop to a specific node. Rarely used directly; usually HN decides who to snoop via filter.—

Opcode Name Hex Category Sender → Receiver Description
RespLCrdReturn0x00CreditAny → AnyReturn a link-layer credit (L-credit) to the sender. Restores flow-control budget so sender can send more flits on this channel.
SnpResp0x01SnoopRN-F → HN-FResponse to a snoop that did not involve data (line was Invalid or clean). Carries final cache state. No DAT flit needed.
SnpRespFwded0x02SnoopRN-F → HN-FResponse to a snoop where data was forwarded directly to another RN-F (DCT — Direct Cache Transfer). Tells HN data was sent, includes FwdState.
CompAck0x05CompRN-F → HN-FFinal handshake after receiving CompData. Confirms requester has installed the cache line. Allows HN to free its tracker entry.
RetryAck0x0BFlowHN → RNHN has no tracker slots available. Requester must wait for PCrdGrant, then re-issue the REQ with AllowRetry=0. Includes credit type.
PCrdGrant0x0CCreditHN → RNHN now has a free tracker slot. Requester may re-issue the previously retried REQ. PCrdType must match the RetryAck's type.
ReadReceipt0x0DCompHN → RNHN acknowledges receipt of a REQ and allocated a tracker entry. Allows requester to release protocol credits and issue more transactions.
Comp0x04CompHN → RNTransaction complete — combined completion and data buffer ID assignment. Used when no separate CompData is needed (e.g., write completions).
CompDBIDResp0x07CompHN → RNCombined Comp + DBIDResp in a single RSP flit. Used for write transactions — tells requester it's complete AND provides the data buffer ID.
DBIDResp0x06CompHN → RN / SN → HNData Buffer ID response — allocates a write data buffer slot. Requester must send write data using this DBID as the TxnID in DAT flits.
DBIDRespOrd0x14CompHN → RNOrdered DBIDResp — includes ordering guarantee. Requester may not send write data until this is received, ensuring ordering with prior transactions.
TagMatch0x09MiscHN → RNMemory Tag match result for MTE (Memory Tagging Extension) operations. Reports whether tag check passed or failed for the accessed location.
SnpRespData0x03Snoop(→ DAT)Snoop response that includes data (not a pure RSP — the data portion goes on DAT channel). The RSP portion conveys state; data on DAT.
// RespErr Field Values (present in RSP and DAT)
ValueNameMeaning
0b00OKNormal successful response. No error. Transaction completed as requested.
0b01ExOKExclusive OK — the exclusive access reservation (LDXR/STXR) succeeded. Store can proceed without retry.
0b10DataErrorError in the data payload (ECC/parity failure). Data may be corrupted. Software must handle.
0b11NonDataErrorError unrelated to data (access permission violation, slave error, unsupported transaction). Transaction failed.
DAT Channel
Data Channel

The DAT channel carries actual cache line data — the widest, heaviest channel. A 64-byte cache line may require multiple DAT flits (e.g., 2 flits on a 256-bit bus). Each flit includes routing, state, integrity fields, and the data payload itself.

DataID and CCID: On a 256-bit (32-byte) data bus, one 64-byte cache line = 2 DAT flits. DataID identifies which 32-byte chunk (0x0 = bytes 0–31, 0x1 = bytes 32–63). CCID (Critical Chunk ID) identifies the 16-byte sub-chunk the CPU needs most urgently — it is returned first to minimise pipeline stall.

SNP Channel
Snoop Channel

The SNP channel is used exclusively by HN-F to interrogate the caches of RN-F nodes. It has no TgtID field — the target is implicit from the physical link used. Snoops trigger state changes and optionally data returns. This channel is the mechanism of cache coherency.

No TgtID in SNP: Unlike REQ, RSP, and DAT which all carry TgtID for mesh routing, the SNP channel has no TgtID field. The target is determined by which physical port on the HN-F the flit is dispatched on. This saves bits and is possible because snoops are always point-to-point from HN to a specific RN-F determined by the Snoop Filter.

// SNP Channel — Complete Opcode Reference
Opcode Name Hex Category Data Returned? Final State Description
SnpLCrdReturn0x00CreditNo—Return link-layer credit for the SNP channel. Restores HN-F's ability to issue more snoop flits.
SnpShared0x01SnoopIf dirtySCSDRequest snoopee to downgrade to Shared state. If line is UC → SC. If UD → SD or SC_PD (if RetToSrc=1). Other sharers can coexist.
SnpClean0x02SnoopIf dirtySCUCEnsure the line is clean in memory without necessarily invalidating. If dirty, snoopee writes back and can stay Shared. DoNotGoToSD=1 implied.
SnpOnce0x03SnoopOptionalUnchangedSnapshot snoop — peek at the current state without changing it. Used by ReadOnce. Snoopee can keep its current state; returns data/state info only.
SnpNotSharedDirty0x04SnoopIf dirtySCUCEnsure line is not in SharedDirty state. Snoopee must transition out of SD to either SC, UC, or I. Used with ReadNotSharedDirty.
SnpPreferUnique0x05SnoopIf dirtyISCPrefer Unique — hint to snoopee to give up the line if possible. Not mandatory; used with ReadPreferUnique for optimistic upgrade.
SnpPreferUniqueFwd0x06SnoopIf dirtyISCSame as SnpPreferUnique but with forwarding — snoopee forwards data directly to requester if it has a valid copy.
SnpUnique0x07SnoopIf dirtyIMandatory invalidation — snoopee must give up the line. Used for ReadUnique, MakeUnique. Returns data if dirty. Line becomes Invalid at snoopee.
SnpUniqueFwd0x0BSnoopYes (fwd)IInvalidate + forward data directly to requesting RN-F (DCT). FwdNID/FwdTxnID specify the target. Reduces HN-F involvement in data path.
SnpSharedFwd0x0CSnoopYes (fwd)SCDowngrade to Shared + forward data to requester. Both snoopee and requester end up in SC. Uses DCT path for lower latency.
SnpCleanFwd0x0DSnoopYes (fwd)SCUCClean snoop with forwarding. Forward clean data to requester. Snoopee may retain a shared copy.
SnpOnceFwd0x0ESnoopYes (fwd)UnchangedSnapshot snoop with forwarding. Forward data without changing state. Used with ReadOnce for non-caching reads.
SnpCleanInvalid0x09CMOYesIClean maintenance snoop — snoopee must write back dirty data to memory, then invalidate. Used before DMA writes to ensure memory is updated before DMA proceeds.
SnpMakeInvalid0x0DCMONoIInvalidate without writeback — snoopee discards the line immediately. Only valid when data can be safely discarded. Used for scrub operations.
SnpMakeInvalidStash0x0FCMONoIInvalidate + stash hint. Used to free up a cache entry for anticipated new data. Combines invalidation with stash target information.
SnpStashShared0x10StashNoUnchangedHint to snoopee to fetch and cache a Shared copy of the target line. Purely advisory — snoopee may ignore. Used for prefetch hinting via stash flows.
SnpStashUnique0x11StashNoUnchangedHint to snoopee to fetch and cache a Unique copy. Advisory only. Used when producer knows consumer will write to the line soon (write-intent prefetch).
SnpDVMOp0x14DVMNo—Distributed Virtual Memory operation delivery — delivers a TLB invalidate, instruction cache sync, or branch predictor invalidate to a specific RN-F via the SNP channel.
