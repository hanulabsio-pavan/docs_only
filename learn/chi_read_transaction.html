CPU Issues ReadShared Request
CPU L1 cache misses on load to 0xBEEF_0040. A ReadShared flit is placed on the REQ channel toward the Home Node.

The CPU executes a load instruction (e.g., LDR X0, [0xBEEF_0040]). The address misses in L1 and L2 cache — no valid cache line exists.

The CPU's CHI interface constructs a ReadShared flit on the REQ channel. ReadShared means: "I want to read this line and hold it in Shared state — other nodes may also have it."

The Network Layer stamps TgtID=0x10 (Home Node) and routes the flit through the mesh. The Link Layer manages flit-level credits hop by hop.

Why ReadShared not ReadUnique? The CPU only needs to read — it doesn't intend to write. ReadShared allows other caches to hold the same line simultaneously (SC state), maximising concurrency.

Home Node Sends ReadReceipt
HN acknowledges receipt of the REQ and allocates a tracker entry. CPU may now accept CompData when it arrives.

On receiving the ReadShared, the Home Node allocates a transaction tracker (scarce hardware resource) for TxnID=0x07 from SrcID=0x01.

HN immediately sends a ReadReceipt back to CPU0. This RSP flit tells the CPU: "I have your request. You can now expect a CompData. Keep TxnID=0x07 open."

The ReadReceipt also allows the CPU's protocol credit counter to be released — the CPU knows HN has accepted ownership of this transaction.

Why ReadReceipt before data? HN may need time to fetch from memory. ReadReceipt decouples acknowledgement from data delivery, allowing the CPU to issue more transactions while waiting.

HN Sends ReadNoSnp to Memory
HN checks its Snoop Filter — no other RN-F holds this line. HN issues a non-coherent read directly to the Slave Node (memory controller).

The Home Node consults its Snoop Filter: no other cache currently holds address 0xBEEF_0040. No snoops are needed.

HN issues a ReadNoSnp on the REQ channel to the Slave Node (DDR memory controller). ReadNoSnp is a non-coherent read — it bypasses coherency protocol, simply fetching raw data from DRAM.

HN assigns its own internal TxnID=0xA3 for tracking this sub-transaction with the SN. This is separate from CPU0's TxnID=0x07.

ReadNoSnp vs ReadShared: ReadShared is used between coherent nodes (RN↔HN). ReadNoSnp is used between HN and memory (non-coherent). The HN translates one to the other.

Memory Returns Data to Home Node
The DDR controller fetches the 64-byte cache line from DRAM and sends it back to HN-F via two CompData DAT flits (on a 256-bit bus).

The Slave Node's DDR controller issues a DRAM read and receives the 64-byte cache line for address 0xBEEF_0040.

On a 256-bit (32-byte) data bus, one full cache line = 2 DAT flits, identified by DataID=0x0 and DataID=0x1. Each flit also carries a 32-byte BE (Byte Enable) mask.

The SN includes DataCheck (ECC bits) in each flit for end-to-end integrity verification. The opcode is CompData — data plus implicit completion.

CCID (Critical Chunk ID): If CPU0 needs bytes at offset +0x40, the SN can return that 16-byte chunk first (CCID=0) to minimise CPU stall, even before the rest of the line arrives.

HN Forwards CompData to CPU
HN re-packages and forwards the 64-byte cache line to CPU0 with Resp=SC (Shared Clean), also providing HomeNID for CompAck routing.

HN has the full cache line. It now forwards it to CPU0 via the DAT channel, again as two flits. The Home Node re-stamps the routing fields: TgtID=CPU0, and replaces TxnID with CPU0's original TxnID=0x07.

The Resp field is set to SC (Shared Clean) — HN grants the line in shared state, not unique, because other nodes might request it next.

Critically, HN includes HomeNID=0x10 in the flit. This tells CPU0 where to send the CompAck — it must go back to HN, not to the SN.

SC vs UC state: HN chose SC (Shared Clean) because ReadShared was requested. If CPU0 had issued ReadUnique, HN would grant UC (Unique Clean), giving CPU0 exclusive ownership to write.

CPU Sends CompAck — Transaction Complete
CPU0 confirms it has received and installed the cache line. HN-F deallocates its tracker. The transaction is fully closed.

After installing the cache line in state SC, CPU0 sends a CompAck on the RSP channel back to HN-F (HomeNID=0x10 from Step 5).

CompAck is the final handshake. It signals to HN: "I have received all data flits for TxnID=0x07 and the line is now resident in my cache."

On receiving CompAck, HN-F deallocates its tracker entry for this transaction. Resources are freed. The snoop filter is updated to record CPU0 as a sharer of 0xBEEF_0040.

Why CompAck is required: Without CompAck, the HN cannot safely allow another node to invalidate CPU0's copy via a snoop — it wouldn't know if CPU0 had actually received and installed the data yet.
