1The last mile

caveman mode

Mesh fast now. But server also need: stop one noisy tenant eating all cache (MPAM); catch bit flips and report them (RAS); turn off idle parts (power); route interrupts; and boot the whole thing in right order. Then capstone: draw whole chip from memory.

These features rarely headline a datasheet but they are why CMN-700 is an infrastructure interconnect rather than just a fast one. Multi-tenant servers need isolation, server silicon needs error containment, and everything needs a correct bring-up order.

2MPAM — partitioning and monitoring

MPAM (Memory System Resource Partitioning and Monitoring), an Armv8.4 feature, lets software tag traffic with a partition ID and then partition shared resources by that ID. CMN-700 implements it in the home nodes — you will see node variants named for secure and non-secure MPAM, such as HNS_MPAM_S and HNS_MPAM_NS — and extends it to the memory controllers.

Partition

Cap how much SLC capacity and memory bandwidth a given partition may consume, so one workload cannot starve others.

Monitor

Measure per-partition usage, so a hypervisor can attribute consumption and enforce policy with real data.

The canonical use case is the noisy neighbour: on a multi-tenant server, one VM streaming through memory can evict everyone else's hot data from a shared last-level cache. MPAM turns shared cache and bandwidth into allocatable resources.

3RAS — reliability, availability, serviceability

A server-class interconnect must detect, contain and report corruption, not merely move data quickly. CMN-700 implements Arm RAS:

AreaProtection
SLC data and tagsECC / parity, so a bit flip in a cached line is detected and, where possible, corrected.
Snoop filter and internal RAMsProtected too — a corrupted directory entry would otherwise corrupt coherency itself.
Error recordsArchitected registers record corrected and uncorrected errors for software to read and report.

The reasoning worth voicing: an undetected error in the snoop filter is more dangerous than one in a data line, because it corrupts the system's model of who owns what. That is why the directory is protected, not just the cache.

4Power management

CMN-700 is partitioned into multiple clock and power/voltage domains, crossed by the ADB / CDB bridges from Lesson 2. Low-power transitions use the standard Arm channels:

Q-channel

Clock and quiescence handshake — negotiate whether a block can be clock-gated because it is idle.

P-channel

Power-state handshake — negotiate transitions between power states for a domain.

The hard part is not gating; it is draining safely. Before a region powers down, in-flight transactions must complete and coherency state must be preserved or migrated, otherwise the system wakes up incoherent. Hardware manages that handshake — and saying so is a much better answer than just naming the two channels.

5Interrupts across the mesh

Interrupts in an Arm system are handled by the GIC, with the ITS translating message-signalled interrupts (for example from PCIe) to the right target. Those interrupt messages travel across the mesh like other traffic, so interrupt delivery is part of the interconnect's job. For a system architect the relevant points are which node fronts the GIC, and that MSI traffic shares the fabric with data traffic and therefore participates in QoS.

6Configuration, discovery and bring-up

Three distinct phases, often conflated in interviews — separating them cleanly is a good signal:

PhaseWhat happens
Build timeThe mesh is configured in Arm's Socrates tool: grid dimensions, node placement, SLC size, channel width, gateways. The chosen topology is baked into RTL.
DiscoverySoftware walks the mesh through the CFG node (co-located with the HN-D) to enumerate node types, IDs and coordinates — it reads the topology rather than assuming it.
Boot / bring-upProgram the SAM (address to target maps) and home-node hashing before coherent traffic flows. Until then RN SAMs default-route to the HN-D, which does not manage coherency — so other requesters must be quiesced during programming (Lesson 5).

Then MPAM partitions, QoS settings, PMU configuration and power policy are programmed, and the system begins normal operation.

7Capstone: whiteboard a CMN-700 SoC

The exercise: design the interconnect for a 128-core server SoC with DDR5 plus HBM, PCIe Gen5, a coherent accelerator, and a second die linked coherently. Work through it yourself before opening each step.

Step 1 — Choose a mesh size and justify it
Start from component count, not from the maximum. 128 cores in clusters of two to four means roughly 32 to 64 RN-F nodes, plus home nodes, memory interfaces, IO and gateways. With three devices per XP (four on edges) you size the grid so everything fits without inflating hop count — a mid-size grid rather than a full 12x12, because every extra row adds latency to every transaction that crosses it. State the trade explicitly: bigger mesh gives more cross-sectional bandwidth and more device slots, but raises average |dX|+|dY|.
Step 2 — Place the nodes
Memory controllers (SN-F) on the edges next to their PHYs, with HBM on one side for bandwidth-hungry work and DDR5 for capacity. Home nodes spread through the interior and interleaved with compute so no core is far from a home. CCG gateways at the edge near the chip-to-chip PHYs. PCIe via HN-P so peer-to-peer device traffic avoids pointless snooping. The coherent accelerator as an RN-F placed near the memory it streams from.
Step 3 — Size the caches and snoop filter
Pick total SLC from the working set and the slice count from the number of home nodes (roughly 4 MiB per slice). Then size the snoop filter at approximately 1.5 times the aggregate private cache of the cores it covers — and explain why: an undersized SF evicts directory entries, forcing back-invalidation of lines still live in core caches and causing spurious misses. This is the trade-off answer interviewers are listening for.
Step 4 — Configure the address map
Program RN SAMs to hash coherent regions across all HN-F slices with a fine enough interleave that a single hot buffer fans out rather than piling on one home. Program MC SAMs to interleave across memory channels, keeping HBM and DDR5 regions distinct so software can place data deliberately. Remember the bring-up rule: quiesce other requesters while programming, because the pre-configuration default route goes to the HN-D, which does not manage coherency.
Step 5 — Decide bandwidth and QoS
Enable the double mesh channel if the workload is data-heavy, since it takes DAT from 256 to effectively 512-bit per direction. Assign QoS classes so latency-critical flows are not stuck behind bulk DMA. Rely on CBusy to throttle prefetch when completers congest, and allow hot-spot re-routing where ordering rules permit.
Step 6 — Handle the second die
Add CCG gateways on both dice, bridging CHI to CXS Issue B, and enable the fast path to trim remote latency. Choose the coherency model deliberately: CCIX-style near-memory coherency for a symmetric peer die, CXL-style host-based coherency for an accelerator or memory-expansion device. If memory is shared across dice, designate a Super Home Node as the central coherency point. Then state the constraint honestly: remote access is materially slower and the link is narrower than the on-chip data channel, so software should keep working sets local.
Step 7 — Multi-tenancy, RAS and observability
Enable MPAM in the home nodes and memory controllers to partition SLC capacity and bandwidth per tenant, preventing a noisy neighbour from evicting everyone's data. Enable ECC on SLC data, tags and the snoop filter, with error records for reporting — protecting the directory matters most because corrupting it corrupts coherency itself. Plan PMU usage up front: which DTM events and watchpoints you will need, and how you will measure over a coherent global window via the DTC.
Step 8 — State what you would measure to validate it
Bandwidth and latency versus offered load; per-HN-F and per-XP distribution to prove the hash is balanced; SLC hit rate and snoop-filter back-invalidation rate to prove the SF is sized correctly; whether CBusy throttling engages under load; and remote versus local access latency across the CCG. Finish by naming the one number that would make you re-architect — for instance a persistent hot home node that retuning cannot fix.

8Mock interview — rapid fire across the whole course

Answer aloud before expanding. If an answer is shaky, the lesson to revisit is named.

1. What is CMN-700 and how does it relate to CHI? (L1)
Arm's third-generation coherent mesh interconnect IP. CHI Issue E is the protocol; CMN-700 is the micro-architecture implementing it — a 2-D mesh of crosspoints up to 12x12 connecting RN, HN and SN nodes, with distributed SLC and snoop filters in the home nodes, plus SAM, QoS, gateways and a distributed PMU.
2. Draw a crosspoint. What ports does it have? (L1)
Four mesh ports (N/S/E/W) to neighbouring XPs, plus device ports where components attach — three per XP, four on an edge XP, with the CAL allowing several devices to share a port. It switches each CHI channel independently.
3. RN-F vs RN-I vs RN-D? (L2)
RN-F is fully coherent with caches, typically a CPU cluster via a DSU. RN-I is an I/O-coherent bridge for AMBA masters with no coherent cache. RN-D is an RN-I that additionally handles DVM (TLB maintenance) messaging.
4. Why must every mesh have an HN-D? (L2)
It carries the configuration (CFG) node, the DVM node and the DTC, and it is the default route target before the SAM is programmed. It is the config, coherency-maintenance and trace anchor.
5. Walk a read miss end to end. (L3)
RN-F issues a REQ; the RN SAM hashes the address to the owning HN-F and the mesh routes by node ID. The HN-F checks SLC and snoop filter; on a clean miss its MC SAM selects an SN-F and it issues the read. Data returns on DAT, optionally via DMT straight to the requester; the HN-F updates SLC and SF state and the requester installs the line.
6. Why four separate channels? (L3)
Independent networks with separate buffers mean a stalled DAT flit cannot block the RSP or SNP traffic needed for forward progress. Combined with credited links and dimension-ordered routing, the fabric avoids deadlock.
7. What is inside an HN-F? (L4)
An SLC slice and a snoop filter, and it is the Point of Coherency and Serialization for its address range — ordering requests, issuing targeted snoops, resolving hazards.
8. How is the snoop filter sized and why does it matter? (L4)
Roughly 1.5 times the aggregate private cache it covers. Undersized, it must evict directory entries, which forces back-invalidation of lines still live in core caches, producing spurious misses. It is a genuine area-versus-performance trade.
9. How does a request find its home node, and how do you avoid a hot one? (L5)
The RN SAM translates the address to a home target ID, normally via a hash that interleaves across HN-F slices; the mesh routes by that ID. To avoid a hot home you tune the hash and interleave granularity so consecutive lines fan out instead of piling onto one slice.
10. What is the SAM bring-up gotcha? (L5)
Before programming, RN SAMs default-route to the HN-D, which does not manage coherency. So all other requesters must be quiesced during SAM programming until the default-node behaviour is cleared, or you get incoherent results.
11. Explain DMT and DCT. (L6)
DMT has memory return data directly toward the requester instead of store-and-forwarding through the home node, removing a data leg. DCT has an owning peer cache forward the line straight to the requester, avoiding DRAM entirely. The home node stays in the control loop for coherency in both cases.
12. Why do near-memory atomics help scaling? (L6)
They execute the operation near the data instead of requiring the requester to take the line uniquely, so a contended counter or lock no longer migrates between caches on every update.
13. How does the fabric handle congestion? (L7)
QoS classes prioritise at arbitration; CBusy signals completer congestion back so cores throttle prefetch and outstanding transactions, draining queues and raising useful throughput (about 15% reported on a V1-class design); hot-spot re-routing spreads load around a congested crosspoint where ordering permits.
14. How does placement affect performance? (L7)
Latency tracks hop count, so placement sets average distance. Memory at the edges near PHYs, home nodes spread through the interior so no core is far from a home, gateways near the chip-to-chip PHYs, and latency-sensitive accelerators near what they talk to.
15. How does CMN-700 scale across dice? (L8)
CML with CCG gateways bridging CHI to CXS Issue B carrying CCIX 2.0 or CXL. Inside the CCG, CCRA proxies remote requesters, CCHA represents remote home and coherency, CCLA drives the link. A Super Home Node provides the central coherency point for cross-die shared memory; the fast path bypasses the transaction layer to cut latency.
16. CCIX vs CXL? (L8)
CCIX resolves coherency near the memory, suiting symmetric peers and multi-socket SMP. CXL is host-based, with the host owning shared memory and snoop state, which simplifies coherent accelerators and memory pooling. CMN-700 supports both and grew CCIX device ports from 4 to 32.
17. How would you debug a bandwidth problem? (L9)
Per-XP DTMs (four events each, plus value/mask watchpoints by channel and device) feed up to eight global counters in the DTC in the HN-D, with timestamped ATB trace; Linux exposes it as arm_cmn. Method: characterise versus load, find the hot home node or crosspoint, classify as hashing, placement or saturation, check SLC hit rate and SF back-invalidations, check CBusy throttling, zoom in with watchpoints, change one thing and re-measure over the same window.
18. What does MPAM give you? (L10)
Traffic tagged with a partition ID lets software partition and monitor SLC capacity and memory bandwidth per partition, implemented in the home nodes and extended to the memory controllers. It stops a noisy neighbour VM from evicting other tenants' data from the shared cache.
19. Why protect the snoop filter with ECC, not just the cache? (L10)
A corrupted data line is a data error; a corrupted directory entry corrupts the system's model of who owns what, which can break coherency itself. So SLC data and tags, the snoop filter and internal RAMs are all protected, with architected error records for reporting.
20. Walk me through bring-up. (L10)
Build-time configuration in Socrates fixes the topology in RTL. At boot, software discovers the mesh through the CFG node co-located with the HN-D, enumerating node types, IDs and coordinates. Then it programs the SAM and home-node hashing — with other requesters quiesced, since the pre-configuration default route goes to the HN-D which does not manage coherency — followed by MPAM partitions, QoS, PMU setup and power policy.
