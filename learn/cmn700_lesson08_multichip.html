Multichip — CML, CCG, CXL & CCIX

Extending one coherency domain across dice and sockets: gateways, CXS transport, and two coherency models.

By the end of this lesson you can

  • Explain CML and the CCG gateway internals (CCRA / CCHA / CCLA).
  • Contrast CCIX and CXL coherency models and say when each fits.
  • Explain the CXS-B fast path and the Super Home Node concept.
  • Discuss realistic multi-die topologies and their limitations.

1Why go beyond one die

caveman mode

One die not big enough, or too expensive to make big. So: many smaller dice, glue them so they act like one coherent machine. Glue = CML. Doorman at each end = CCG. Road between = CXS.

Reticle limits, yield economics and memory-capacity demands all push past a single die. CML (Coherent Multichip Link) is how CMN-700 extends one coherency domain across dice and sockets, so software still sees a single coherent memory system.

2CML: the coherent multichip link

CML extends the mesh's coherency beyond the die for chiplets, multi-die packages and multi-socket SMP. Conceptually, one mesh's gateway presents remote agents to the local mesh as if they were local nodes, and vice versa — so the local home nodes, snoop filters and SAM keep working with only the target IDs changing.

3Inside the CCG gateway

The CCG (CML / CXL-CCIX gateway) bridges on-chip CHI to the chip-to-chip transport. Its internal agents mirror the on-chip request / home / link split — which is a satisfying way to remember them:

AgentRoleOn-chip analogue
CCRARequest agent — proxies remote requesters into the local mesh.like an RN
CCHAHome agent — represents remote home / coherency on this die.like an HN
CCLALink agent — drives the physical chip-to-chip interface (optionally with an embedded RN-I for PCIe-to-remote-memory).link layer

The earlier CXG gateway is the same idea one generation back, with agents CXRA / CXHA / CXLA, supporting CHI plus CXS Issue A (CCIX 1.1).

caveman mode

Gateway wear two hats. To local mesh it pretend to be a requester (CCRA) when remote die asks for something. It pretend to be a home (CCHA) when local core asks for remote memory. CCLA just drive the wires.

4CXS and the fast path

The chip-to-chip transport is CXS. CMN-700 supports CXS Issue B, which can carry CCIX 2.0 or CXL. Because every remote access pays gateway plus link latency, CMN-700 adds a CXS-B fast path that bypasses the transaction layer straight to the link layer, trimming latency on remote accesses.

Remember the asymmetry: on-chip DAT is 256-bit (or effectively 512-bit with the double mesh channel), while the chip-to-chip link is comparatively narrow. That asymmetry, not the protocol, is usually what limits cross-die traffic.

5CCIX versus CXL — two coherency models

CMN-700 supports both because they resolve coherency from opposite ends:

CCIX — near-memory

Coherency is resolved near the memory: home node, cache and snoop filter sit closest to the shared memory. Suits symmetric peers, distributed caching, and multi-socket SMP where both sides are full participants.

CXL — host-based

The host owns shared memory and maintains snoop state. Simpler for building coherent accelerators and for memory expansion / pooling devices, because the device does less coherency work.

CMN-700 also grew CCIX device ports substantially over CMN-600 (from 4 to 32) and added CXL gateways — a clear bet on accelerator-heavy and memory-disaggregated systems.

6The Super Home Node

In multi-die systems, some memory is shared across dice and needs a single ordering point. The Super Home Node is a home node — or a whole mesh acting as one — that serves as the central coherency point for memory shared between dice. It can hold SLC and act as local home for remote memory, which is what makes a central I/O die plus several compute dice work as one coherent system.

Mapping to your own experience is fair game in an interview: any architecture with a per-chip coherency director plus a chip-to-chip coherent link is solving the same problem with different names.

8What limits multichip scaling

  • Remote latency. Gateway translation plus link traversal makes remote memory materially slower than local — so NUMA-aware software placement matters.
  • Link bandwidth asymmetry. CXS is narrower than the on-chip data channel, so heavy cross-die sharing saturates the link before the mesh.
  • Coherency tracking cost. Tracking remote sharers grows the directory and snoop problem; the fast path helps latency but not tracking cost.
  • Gateway overhead. CCG plus SerDes costs area and power at every edge.
  • Practical die counts. Real designs cluster in the small numbers of dice rather than arbitrarily many, because each hop compounds the effects above. Check the TRM for the exact configuration limits of a given release.

The design rule that follows: keep working sets local, and treat cross-die coherent traffic as a scarce resource.

10Interview Q&A

How does CMN-700 scale across chips?
Through CML, using CCG gateways that bridge on-chip CHI to chip-to-chip CXS Issue B (carrying CCIX 2.0 or CXL). Inside the CCG: CCRA proxies remote requesters into the local mesh, CCHA represents remote home and coherency locally, and CCLA drives the physical link. For memory shared across dice, a Super Home Node acts as the central coherency point. The result is one coherency domain spanning multiple dice or sockets.
CCIX versus CXL — when would you use each?
CCIX resolves coherency near the memory, with home node, cache and snoop filter closest to the shared memory — a good fit for symmetric peers and multi-socket SMP. CXL is host-based: the host owns shared memory and snoop state, which makes coherent accelerators and memory pooling or expansion devices simpler to build. CMN-700 supports both, and grew CCIX device ports from 4 to 32 versus CMN-600.
What limits multichip scaling in practice?
Remote access latency from gateway plus link traversal; bandwidth asymmetry, since CXS is narrower than the on-chip data channel; the growing cost of tracking remote sharers; and gateway plus SerDes area and power at each edge. The design response is to keep working sets local and treat cross-die coherent traffic as scarce. The fast path reduces latency but does not remove the tracking cost.
How does the local mesh see a remote requester?
Through the gateway's CCRA, which proxies remote requesters so they appear as local participants. Conversely a local core reaching remote memory is served via the CCHA, which represents the remote home locally. This is what lets the existing SAM, home nodes and snoop filters keep working with only target IDs changing.
Why does a chiplet design need a Super Home Node?
Memory shared across dice still needs a single point of coherency and ordering. A Super Home Node provides that central point — it can hold SLC and act as local home for remote memory — which is what makes a central IO die plus multiple compute dice behave as one coherent system rather than several islands.

11Recap & key terms

  • CML extends one coherency domain across dice / sockets.
  • CCG = gateway; agents CCRA (request), CCHA (home), CCLA (link). Older CXG = CXRA/CXHA/CXLA.
  • Transport is CXS Issue B carrying CCIX 2.0 or CXL; fast path bypasses the transaction layer.
  • CCIX = near-memory coherency; CXL = host-based. CCIX ports grew 4 → 32.
  • Super Home Node = central coherency point for cross-die shared memory.
  • Limits: remote latency, link narrowness, remote-sharer tracking, gateway cost.
