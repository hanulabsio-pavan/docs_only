Instruction Categories

The actual instruction set: integer, load/store, floating-point, vector, branch and system — plus the v3.1 prefixed encodings that broke the 32-bit ceiling.

By the end of this lesson you can

  • Place any Power instruction into the right category and name its likely form.
  • Explain why rlwinm replaces a whole family of shift and extract instructions.
  • Read the BO/BI encoding and understand how CTR loops branch in one instruction.
  • Tell VMX, VSX and MMA apart and say what each is for.
  • Read an unfamiliar Power function prologue and epilogue without help.

1The category map

caveman mode

Six families only: move numbers around registers, move numbers to/from memory, do float maths, do many numbers at once, jump somewhere, talk to the machine itself. Everything else is a variation.

Instruction families and their usual primary opcodes
  FIXED-POINT          arithmetic, logical, compare, rotate/shift
                       opcodes 7–15, 20–31   forms D, X, XO, M, MD

  LOAD / STORE         byte/half/word/double, update & indexed,
                       byte-reverse, atomics
                       opcodes 32–47, 58, 62, 31   forms D, DS, X

  FLOATING-POINT       scalar binary FP + fused multiply-add,
                       decimal FP (DFP), IEEE-128
                       opcodes 48–63   forms D, X, A

  VECTOR               VMX/AltiVec (opcode 4) · VSX (opcodes 60/61)
                       · MMA accumulators (v3.1)

  BRANCH & CR          b / bc / bclr / bcctr, CR logical ops, isel
                       opcodes 16, 18, 19   forms I, B, XL

  SYSTEM               mtspr/mfspr, sc, rfid, traps, TLB & cache control
                       opcodes 17, 19, 31   forms X, XFX, XL

A useful mental shortcut: primary opcode 31 is the junk drawer. Hundreds of register-to-register operations — arithmetic, logical, indexed loads and stores, atomics, SPR moves, cache and TLB control — all live there, separated by a 9- or 10-bit extended opcode.

3Fixed-point instructions

The integer core. Two things to internalise before anything else:

  • Word vs doubleword. A w suffix means the operation is on 32 bits, d means 64. mullw multiplies 32-bit values, mulld multiplies 64-bit ones. Results are still written to a 64-bit register.
  • subf subtracts backwards. subf RT,RA,RB computes RB − RA, not RA − RB. This exists because it lets one XO-form encoding also express negate and reverse-subtract, but it catches everyone once.

Building a 64-bit constant — the classic four-instruction dance
  # load 0x1234_5678_9ABC_DEF0 into r3
  lis     r3, 0x1234        # addis r3,0,0x1234  → r3 = 0x1234 << 16
  ori     r3, r3, 0x5678    # r3 = 0x1234_5678
  rldicr  r3, r3, 32, 31    # shift left 32
  oris    r3, r3, 0x9ABC
  ori     r3, r3, 0xDEF0
  # v3.1 alternative — one prefixed instruction covers 34 bits:
  pli     r3, 0x123456789   # (paddi with RA=0)

This is a direct consequence of fixed 32-bit encoding: no single instruction can carry a 64-bit immediate. It's also exactly the pain v3.1's prefixed instructions were designed to reduce.

4Rotate-and-mask: the Swiss army knife

Power has no dedicated bit-field-extract or bit-field-insert instruction, because rlwinm and rldicl already do all of it. The idea: rotate left by N, then AND with a mask defined by a begin and end bit. One instruction, three operations.

rlwinm RA, RS, SH, MB, ME
   RS  ┌────────────────────────────────┐
       │ the 32-bit source value        │
       └────────────────────────────────┘
                    │ rotate left by SH
                    ▼
       ┌────────────────────────────────┐
       └────────────────────────────────┘
                    │ AND with mask of 1s from bit MB to bit ME
                    ▼
   RA  ┌────────────────────────────────┐
       │0000XXXXXXXXXXX000000000000000│
       └────────────────────────────────┘

   Everything below is the SAME instruction, different SH/MB/ME:
     slwi   rA,rS,n     =  rlwinm rA,rS, n,    0,   31-n
     srwi   rA,rS,n     =  rlwinm rA,rS, 32-n, n,   31
     clrlwi rA,rS,n     =  rlwinm rA,rS, 0,    n,   31
     extlwi rA,rS,n,b   =  rlwinm rA,rS, b,    0,   n-1
     rotlwi rA,rS,n     =  rlwinm rA,rS, n,    0,   31

The 64-bit family is rldicl / rldicr / rldic / rldimi (MD-form), where a single mb or me value suffices because one end of the mask is implicit. rldimi is the insert variant — it merges a rotated field into the destination without disturbing the surrounding bits.

caveman mode

Why 20 different shift instructions when one rotate + mask do all? Assembler give you pretty names (slwi, srwi, clrldi), hardware see one instruction. Fewer opcodes, simpler decoder, same power.

5Load and store

The naming is completely systematic once you see the pattern:

Decoding a load/store mnemonic
        l  w  z  u  x
        │  │  │  │  └─ x = indexed  (EA = RA|0 + RB)   else displacement
        │  │  │  └── u = update   (write EA back into RA)
        │  │  └───── z = zero-extend   a = algebraic (sign-extend)
        │  └──────── b=byte  h=halfword  w=word  d=doubleword
        └─────────── l = load   st = store

   so:  lwzux = load word, zero-extend, update RA, indexed by RB
        lha   = load halfword, sign-extend, displacement form
        stdu  = store doubleword and update  (the stack-push idiom)

gotcha

lvx silently ignores the low 4 address bits. The classic VMX idiom used lvsl plus two lvx loads and a vperm to assemble an unaligned vector. Since v3.0, lxv/stxv handle unaligned vector access directly — use those in new code.

7Floating-point

Power has had strong floating-point since POWER1 — the RS/6000 was a scientific workstation, and it shows. Three distinct families now coexist:

Binary FP

IEEE 754 single and double precision, plus IEEE binary-128 in hardware from v3.0. Operates on FPRs (i.e. the high half of VSR0–31).

Decimal FP

IEEE 754-2008 decimal64 and decimal128, added in v2.05. Exact decimal arithmetic — no 0.1 + 0.2 surprises. Built for finance.

Vector FP

VSX xv* instructions doing 2 doubles or 4 singles per instruction, on the full 128-bit VSRs.

GroupInstructionsNote
Arithmeticfadd, fsub, fmul, fdiv, fsqrt, fabs, fnegAn s suffix (fadds) means single-precision rounding of the result.
Fused multiply-addfmadd, fmsub, fnmadd, fnmsubComputes (A×C) ± B with one rounding at the end. More accurate and faster than separate ops — the reason Power dominated scientific benchmarks for years.
Compare / selectfcmpu, fcmpo, fselfcmpo raises an exception on a signalling NaN; fcmpu does not. fsel is a branchless FP select.
Convert / roundfrsp, fctid, fctiw, fcfid, frin, friz, frip, frimThe fri* round-to-integer family (v2.02+) avoids a trip through FPSCR to change rounding mode.
Estimatesfre, frsqrteFast reciprocal / reciprocal-square-root estimates for Newton-Raphson refinement.
Decimaldadd, dsub, dmul, ddiv, dqua, dcffixOperates on densely-packed-decimal values in FPRs / FPR pairs.

caveman mode

Fused multiply-add = multiply and add, round only once at end. Two operations, one rounding, one instruction. Matrix maths is nothing but multiply-add, so this instruction is why Power good at science.

8Vector: VMX, VSX and MMA

Three generations, layered rather than replaced.

The key MMA insight: a normal SIMD FMA does one row of work per instruction and must keep re-reading operands. An MMA ger ("generalised outer product") instruction updates an entire accumulator tile from two input vectors, so the operand-fetch-to-arithmetic ratio collapses. That is what makes it worth eight special 512-bit registers.

Practical note: you rarely write MMA by hand. GCC and LLVM expose it through __builtin_mma_* intrinsics, and libraries like OpenBLAS use it under the hood.

9Branches and the Condition Register

Four branch instructions cover everything:

InstructionFormTargetReach
b / bl / ba / blaIPC + (LI × 4), or absolute±32 MB
bc and friendsBPC + (BD × 4)±32 KB
bclr (blr)XLthe Link Registeranywhere
bcctr (bctr)XLthe Count Registeranywhere

Add l to any of them (bl, bctrl) to set LK=1, which saves the return address in LR — that's a call.

The BO / BI encoding

Conditional branches take two 5-bit fields. BI selects which bit of the CR to test (bits 0–31, so field = BI÷4, condition = BI mod 4 → LT/GT/EQ/SO). BO says how to test — and, crucially, whether to decrement CTR at the same time.

BOBehaviourUsual mnemonic
0b01100 = 12Branch if CR[BI] is truebeq, blt, bgt…
0b00100 = 4Branch if CR[BI] is falsebne, bge, ble…
0b10100 = 20Branch always (ignore CR)blr, bctr, b
0b10000 = 16Decrement CTR, branch if CTR ≠ 0bdnz
0b10010 = 18Decrement CTR, branch if CTR = 0bdz

The low bits of BO also carry a static branch hint, which the assembler writes as a + or - suffix: bne- retry means "predict not taken". You see this constantly in atomic retry loops, where the retry path is genuinely rare.

caveman mode

CTR is a counter with a branch built in. bdnz = "take one off counter, jump back if not zero". Loop with no compare, no separate decrement. One instruction per iteration of loop overhead.

Combining conditions without branching

crand, cror, crxor, crnand, crnor, creqv and mcrf operate on individual CR bits. A compiler can evaluate if (a < b && c != d) as two compares into different CR fields, one crand, and a single branch — instead of two branches. And isel removes the branch entirely for simple selections.

After writing instructions into memory you must run dcbst (push the data out of the D-cache), sync, icbi (invalidate the I-cache line) and isync before executing them. Power's split Harvard caches are not coherent with each other for instruction fetch — skipping this produces the worst kind of intermittent bug.

12Prefixed instructions — v3.1's big change

For 30 years every Power instruction was exactly 32 bits. v3.1 adds a second tier: a prefix word (primary opcode 1) immediately followed by a suffix word, making a single 64-bit instruction.

A prefixed instruction — 8 bytes, two words
   ┌──────── word 0 : PREFIX ────────┬──────── word 1 : SUFFIX ────────┐
   │ OPCD=1 type R high-order immediate │ looks like a normal        │
   │                                 │ D-form instruction         │
   └─────────────────────────────────┴─────────────────────────────────┘
     18 more immediate bits  +  16 from the suffix  =  34-bit displacement
     R = 1 means the displacement is relative to the address of the prefix

   paddi  r3, r4, 0x1FFFFFFFF   # ±8 GB immediate add, one instruction
   pld    r3, sym@pcrel         # PC-relative load — no TOC pointer needed
   pli    r3, 0x123456789       # 34-bit load immediate
  • 34-bit displacements replace multi-instruction constant and address construction.
  • PC-relative addressing (the R bit) makes position-independent code far cheaper — historically Power leaned on a TOC/GOT pointer in r2 for this.
  • Prefixed instructions must not cross a 64-byte boundary; the assembler pads to keep that true.
  • The prefix/suffix pair is architecturally one instruction — you cannot branch to the suffix, and an interrupt reports the address of the prefix.
  • MMA instructions use a prefixed form (MMIRR) to carry the extra operand masks.
caveman mode

32 bits too small to hold big number. Old way: four instructions to build one constant. New way: glue two words together, get 34 bits of room. Cost: decoder must look at two words. Worth it.

13Reading real code: a function, start to finish

Everything in this lesson shows up in the first and last few instructions of any Power function. Here is a typical non-leaf function under the ELFv2 (ppc64le) ABI.

Prologue, body, epilogue
  # ---- prologue -------------------------------------------------
  mflr    r0                  # get return address out of LR (mfspr r0,8)
  std     r0, 16(r1)          # save it in the caller's frame LR slot
  stdu    r1, -64(r1)         # push a 64-byte frame AND update the SP, atomically
  std     r31, 56(r1)         # save a callee-saved register

  # ---- body -----------------------------------------------------
  mr      r31, r3             # or r31,r3,r3   — stash the first argument
  cmpdi   r3, 0               # compare against 0, result into cr0
  beq     .Ldone              # bc 12,2,.Ldone  — branch if cr0[EQ]
  li      r4, 10              # addi r4,0,10   — the RA|0 trick
  mtctr   r4                  # mtspr 9,r4     — set up a loop count
.Lloop:
  ld      r5, 0(r31)          # DS-form load
  addi    r31, r31, 8         # advance the pointer
  bdnz    .Lloop              # bc 16,0,.Lloop — decrement CTR and loop
  bl      helper              # call: sets LK=1, so LR is clobbered
  nop                         # slot the linker may patch for TOC restore
.Ldone:
  # ---- epilogue -------------------------------------------------
  ld      r31, 56(r1)         # restore callee-saved register
  addi    r1, r1, 64          # pop the frame
  ld      r0, 16(r1)          # reload the saved return address
  mtlr    r0                  # mtspr 8,r0
  blr                         # bclr 20,0,0 — return

Three things to notice, because they are pure Power:

  • LR is a register, not a stack slot. Any non-leaf function must save and restore it explicitly — that's why mflr/mtlr bracket every real function.
  • stdu pushes the frame in one instruction and keeps the stack chain valid at every instant, which is what makes Power backtraces reliable.
  • The loop has no compare and no separate decrement — mtctr plus bdnz is the whole loop control.

15Interview Q&A

Give me the instruction categories in Power ISA.
Fixed-point (arithmetic, logical, compare, rotate/shift), load/store, floating-point (binary, decimal, and IEEE-128 from v3.0), vector (VMX/AltiVec, VSX, and MMA from v3.1), branch and condition-register operations, and system/storage-control (SPR access, system call, traps, barriers, cache and TLB management). Encoding-wise, primary opcode 31 hosts the bulk of the register-to-register work behind an extended opcode.
Explain rlwinm.
Rotate Left Word Immediate then AND with Mask. It rotates the low 32 bits of RS left by SH, builds a mask of ones from bit MB through bit ME, ANDs the two, and writes RA. Because the mask endpoints are independent, one instruction expresses left shift, right shift, rotate, field extract and field clear — which is why slwi, srwi, clrlwi, extlwi and rotlwi are all simplified mnemonics for it. The 64-bit equivalents are rldicl/rldicr/rldic, and rldimi adds field insert.
How does a loop work on Power without a compare?
Load the trip count into the Count Register with mtctr, then end the loop with bdnz. That's bc with BO=16, which decrements CTR and branches if the result is non-zero — decrement, test and branch in one instruction, with no CR involvement and no dependency on the comparison unit. bdz is the branch-if-zero variant.
What are BO and BI?
In a conditional branch, BI is the 5-bit index of the CR bit to test — the CR field is BI÷4 and the condition within it (LT/GT/EQ/SO) is BI mod 4. BO is the 5-bit control field saying how to branch: test true (12), test false (4), branch always (20), or decrement CTR and test it (16 / 18), with the low bits carrying a static prediction hint that the assembler writes as + or -. Every friendly mnemonic like beq, bne- or bdnz is a particular BO/BI pair.
VMX vs VSX vs MMA?
VMX (AltiVec) came from PowerPC: 32 × 128-bit vector registers, integer and single-precision SIMD, with vperm as its signature instruction. VSX (v2.06) unified the FP and vector register files into 64 × 128-bit VSRs and added double-precision vector arithmetic and better unaligned access. MMA (v3.1) adds eight 512-bit accumulators overlaying VSR0–31; a single outer-product instruction updates a whole output tile, which is what makes dense matrix multiply and ML inference efficient on POWER10.
What did prefixed instructions change, and what constraints do they bring?
They break the fixed 32-bit encoding: a prefix word with primary opcode 1 plus a suffix word forms one 64-bit instruction, giving 34-bit displacements and, via the R bit, PC-relative addressing — so building a large constant or addressing a global no longer needs several instructions or a TOC pointer in r2. The constraints: a prefixed instruction may not cross a 64-byte boundary, you cannot branch into the suffix, and the pair is architecturally a single instruction for interrupt reporting.
Why does Power have simplified mnemonics, and which ones matter?
Because many common operations are special cases of general instructions, and reading the general form is painful. The ones you must know on sight: li/lis (addi/addis with RA=0), mr (or rX,rY,rY), not (nor), nop (ori r0,r0,0), blr (bclr 20,0,0), bctrl, bdnz, mflr/mtlr/mtctr (mfspr/mtspr), and the srdi/clrldi family (rldicl).
Walk me through a Power function prologue.
mflr r0 pulls the return address out of the Link Register, std r0,16(r1) saves it into the caller's frame LR slot, and stdu r1,-N(r1) allocates the frame and updates the stack pointer in one atomic instruction so the backchain is never inconsistent. Callee-saved registers (r14–r31) are then stored into the new frame. The epilogue reverses it: restore registers, pop the frame, ld r0,16(r1), mtlr r0, blr.
What do you need to do after generating code at runtime?
Power's L1 instruction and data caches are not coherent for instruction fetch, so a JIT must explicitly synchronise: dcbst on each modified block to push it out of the data cache, then sync, then icbi on each block to invalidate the instruction cache, then isync to discard anything already fetched or speculated. Omitting this gives intermittent failures that depend on cache state.

16Recap & key terms

  • Six families: fixed-point · load/store · floating-point · vector · branch/CR · system. Opcode 31 is the junk drawer.
  • w = 32-bit, d = 64-bit; l in a compare means unsigned; . sets CR0; o sets XER[OV].
  • subf is backwards: subf RT,RA,RB = RB − RA.
  • rotate-and-mask (rlwinm, rldicl) is the shift/extract/insert engine behind a dozen mnemonics.
  • Load/store naming is systematic: l|st + b|h|w|d + z|a + u + x.
  • Branches: b ±32 MB · bc ±32 KB · blr/bctr via LR/CTR; BO = how to test, BI = which CR bit; bdnz is a whole loop.
  • Vector layers: VMX (32×128) → VSX (64×128) → MMA (8×512 accumulators).
  • v3.1 prefixed: opcode 1 prefix + suffix = 64-bit instruction, 34-bit displacement, PC-relative.
  • Self-modifying/JIT code needs dcbst · sync · icbi · isync.
