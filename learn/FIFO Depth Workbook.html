FIFO Depth Workbook

FIFO depth calculation

notes · worked cases, interview style · 27 Sep 2026

1The one idea

A FIFO only has to hold what the reader can't drain during the worst burst.

depth = B − ⌊ B × (Rrd / Rwr) ⌋

  • B = burst length (words written back to back, worst case)
  • Rwr = fwclk × (fraction of cycles that write)
  • Rrd = frclk × (fraction of cycles that read)
  • floor the reads: a half-finished read hasn't freed a slot

Sanity check first: long-term average write rate must be ≤ read rate. If not, no finite depth works; you need back-pressure.

2The standard cases

Case 1 · fW > fR, no idle cycles

given: fW = 80 MHz, fR = 50 MHz, B = 120

write time = 120 × 12.5 ns = 1500 ns
reads in 1500 ns = 1500 / 20 = 75
depth = 120 − 75

→ 45

Case 2 · fW > fR, both sides have idle cycles

given: fW = 80 MHz, 1 idle between writes; fR = 50 MHz, 3 idle between reads; B = 120

1 write every 2 clk → 25 ns per word
write time = 120 × 25 = 3000 ns
1 read every 4 clk → 80 ns per word
reads = ⌊3000 / 80⌋ = ⌊37.5⌋ = 37
depth = 120 − 37

→ 83

Case 3 · fW < fR, no idle cycles

given: fW = 50 MHz, fR = 80 MHz

Reader is always faster. Nothing piles up. Depth 1 in theory. An async FIFO still needs a few entries for pointer-sync latency, so use 2–4.

Case 4 · fW < fR, but the reader is slow because of idle cycles

given: fW = 30 MHz, no idle; fR = 50 MHz, reads 1 in 4 cycles; B = 120

write time = 120 × 33.33 ns = 4000 ns
1 read per 80 ns → reads = 4000 / 80 = 50
depth = 120 − 50

→ 70

Lesson: compare rates (words/s), not clock frequencies.

Case 5 · same frequency, no idle

Rwr = Rrd. Depth 1 for a sync FIFO (or none, just a register). If the clocks are async, the phases differ, so still use an async FIFO of ~4 for the sync delay.

Case 6 · duty-cycle spec (the favourite trap)

given: both 100 MHz · writer: 80 writes in any 100 clk · reader: 8 reads in any 10 clk

worst burst: last 80 of window 1 + first 80 of window 2
→ B = 160 writes in 160 clk
reads in 160 clk = 160 × 8/10 = 128
depth = 160 − 128

→ 32

Most people answer 16 (80 − 64) by using one window. The back-to-back case is the real worst case.

Case 7 · trick question

given: fW = 100 MHz, 80 writes in any 100 clk · fR = 50 MHz, reads every clk

average write rate = 100 × 0.8 = 80 M words/s
average read rate = 50 × 1 = 50 M words/s
80 > 50 → the FIFO fills forever

→ no finite depth

Say this out loud in the interview. Then offer: throttle the writer with full / almost-full back-pressure.

3Finish the answer

  • Async FIFO: add ~2–4 entries. The full flag clears 2–3 cycles late (pointer sync), and without slack the writer stalls.
  • Round up to a power of 2 so the gray-code pointers wrap cleanly (45 → 64, 83 → 128, 70 → 128, 32 → 32 + margin → 64).
  • Using almost-full for back-pressure? Add the round-trip latency (writer's reaction time × write rate) above the threshold.

Interview checklist

  • Ask: burst length? idle cycles on each side? clocks related?
  • Check average rates first (case 7)
  • Find the worst back-to-back burst (case 6)
  • Convert everything to words per second, then subtract
  • Floor the reads, add sync margin, round to 2n
