Cache Architecture · Replacement Policy Reference

Pseudo-LRU
(PLRU)

Near-perfect eviction accuracy at a fraction of the hardware cost. The dominant replacement algorithm in modern L1/L2 caches. Trades ≈5% accuracy for 90% less storage overhead.

N−1 bits for N ways Binary tree pointer O(1) lookup Used in ARM Cortex-A, x86 L1
// 01 — Motivation
Why Not True LRU?

True LRU tracks the exact access order of every cache way. That precision is expensive. PLRU approximates it with a minimal bit-vector and a binary decision tree.

⏱️
Latency

True LRU needs a priority encoder over all N ways. PLRU walks a 3-level tree — 3 bit-reads, done.

💾
Storage

8-way set: true LRU needs log₂(8!) = 16 bits. PLRU needs 7 bits. Savings scale with ways.

🎯
Accuracy

PLRU hits ≈95–98% of true LRU accuracy in real workloads. The 2–5% gap is negligible vs. the hardware savings.

Storage: True LRU = ⌈log₂(N!)⌉ bits  |  PLRU = (N − 1) bits
Example (8-way): True LRU = 16 bits  →  PLRU = 7 bits  (56% reduction)
// 02 — The Algorithm
Tree-Based PLRU — How It Works

PLRU stores N−1 pointer bits arranged as a binary tree. Each bit points left (0) or right (1) — toward the "older" subtree. The leaf at the end of the path from root is the eviction candidate.

// 4-Way PLRU Tree (3 bits: B0, B1, B2)
B0=0 → left branch B0=1 → right branch
📌 On Access (Cache Hit or Fill)

Walk from root → accessed way. At each node, flip the bit to point AWAY from the just-accessed way. This marks that subtree as "recently used."

🗑️ On Eviction (Cache Miss)

Follow bits from root → leaf. Each bit value steers the path. The leaf you land on is the victim (approximate LRU).

⚡ Complexity

Both update and lookup are O(log₂ N) bit reads/writes. For 8-way: 3 operations. No counters, no sorting.

// 04 — Mechanism
The Bit-Flipping Rule

One rule governs both reads and evictions. Simple, hardware-friendly, no counters.

✦ ON CACHE ACCESS (hit or fill)
  1. Find which way was accessed.
  2. Walk tree from root → that way's leaf.
  3. At each internal node, flip its bit to point AWAY from the accessed subtree.
  4. Result: bits now point toward the other side (the older one).
Example: Access Way 0 (left-left path). Flip B0: 0→1. Flip B1: 0→1. Now B0=1 and B1=1 point right — away from Way 0.
✦ ON CACHE MISS (eviction needed)
  1. Start at root (B0).
  2. Follow each bit's value: 0 → go left, 1 → go right.
  3. Reach a leaf — that way is the victim.
  4. Evict it, load new data, then update bits (step above).
Example: Bits B0=1, B2=0. Follow: 1→right branch, 0→left of right branch → Way 2 is evicted.

// 05 — Comparison
LRU vs PLRU vs Others

Choose your replacement policy based on the cache level, way count, and performance sensitivity.

Property True LRU Tree PLRU ★ Random FIFO
Storage (8-way) 16 bits 7 bits ★ 0 bits 3 bits
Update Complexity O(N) — sort N entries O(log₂ N) — flip 3 bits O(1) — none O(1) — pointer++
Eviction Accuracy 100% (exact) ~95–98% ~80% (workload dependent) ~85%
Hardware Cost High Low Minimal Low
Scan Resistance Yes Partial No No
Used in TLBs (small) L1/L2 CPU cache LLC (some designs) Simple controllers
★ Why PLRU dominates CPU caches: At 8-way associativity, PLRU uses 56% less storage than true LRU, adds zero pipeline latency (3-bit XOR chain), and achieves 95%+ accuracy. ARM Cortex-A series, Intel Core L1, and AMD Zen all use tree-PLRU variants.

THE ONE RULE

"On access, flip bits on the path from root to way — pointing away from what you just used."

TRADE-OFF PITCH

"Sacrifices 2–5% accuracy for 50%+ storage savings and O(log N) vs O(N) update time. Worth it at scale."

COMMON INTERVIEW Qs
  • ❓ Why not true LRU in L1? → Hardware cost: O(N) comparators.
  • ❓ How many bits for 8-way? → 7 bits (N−1).
  • ❓ What gets evicted? → Leaf at root-to-leaf path following bit values.
  • ❓ What happens on a hit? → Bits on path flip to point away from hit way.
  • ❓ Is PLRU optimal? → No. Belady's MIN is optimal but requires future knowledge.
PLRU WEAKNESSES
  • ⚠️ Streaming access: Sequential scan thrashes PLRU like LRU.
  • ⚠️ Working set > N: All policies degrade equally. Increase associativity.
  • ⚠️ Asymmetric access: Hot/cold imbalance degrades approximation quality.
  • ⚠️ Security: Predictable eviction enables Flush+Reload cache side-channel attacks.
