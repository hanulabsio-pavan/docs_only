§1 Executive Summary

The L2 Cache Controller is the second-level unified cache between a CPU cluster's private L1s and the hanuma CHI interconnect — the cluster's single coherent agent. All L1 misses are serviced, ordered, and made coherent through the L2 before being presented to CHI as an RN-F requester.

1.1 Role within the CHI SoC

The hanuma SoC is built around a 4×4 CHI mesh NoC carrying AMBA CHI Issue E traffic across 4 virtual channels. The L2 fills one RN-F socket per CPU cluster.

1.2 Design Goals

🔒 Correct CHI RN-F Coherency

Well-behaved MOESI participant (I/SC/UC/UD/SD). Answers every snoop class from the HN-F directory.

🔌 Decoupled Upstream

L1-agnostic interface usable for DV and FPGA bring-up before any core exists. Future L1s attach without re-architecture.

⚡ Non-Blocking

Up to 16 outstanding misses matching the RN tracker depth. Cluster never stalled on a single miss.

🏁 Frequency-Feasible

Banked, pipelined tag/data design. Closes timing at 1 GHz (NoC clock) with clean 2→1 GHz crossing. REC

📐 RTL-Ready & Scalable

Parameterized so size/associativity/bank count can change without structural rewrites. Reusable as shared LLC tile.

🛡️ RAS-Aware

SECDED ECC on data, parity on tags, poison propagation over CHI. REC

§5 CHI Integration

The L2 is a CHI RN-F requester and snoopee. It never acts as a home node. All CHI mechanics (flit packing, credits, link training, TxnID allocation, retry) are owned by the existing chi_rn.

6.4 Hazard: In-Flight Requests vs Snoops

⚠️ A snoop can hit a line that has an open MSHR. The snoop engine and MSHR share a single per-line ownership token. A snoop to an in-flight line is stalled or merged per CHI ordering rules until the outstanding transaction reaches a safe point, preventing data loss or protocol deadlock.

§8 Cache Pipeline

8.1 Hit Path

L1 req → [CDC] → FE decode → S1 tag read → S2 compare → S3 HIT
       → data bank read → ECC → critical word → L1 (fill/forward)

Target latency: ~6–8 NoC cycles + domain crossing  [REC]

8.2 Miss Path Sequence

sequenceDiagram participant L1 participant L2 as L2 FE/Tag participant M as MSHR participant RN as chi_rn participant HN as HN-F L1->>L2: req (miss) L2->>L2: S1..S3 tag lookup = MISS L2->>M: allocate MSHR, pick victim M->>RN: cache_req (ReadUnique/ReadShared + home_nid) RN->>HN: REQ flit (NoC) HN-->>RN: CompData (after dir lookup / snoops) RN-->>M: cache_rdata beats (2 × 256b) M->>L2: fill array, install tag/state L2-->>L1: critical-word data, wake M->>M: free MSHR

8.3 Eviction / Write-Back Path

Victim select (PLRU) → read victim line → state?
   UD/SD  → Write-Back Engine → WriteBackFull (+DAT 2 beats) → wait DBIDResp/Comp
   UC     → Evict (no data)  [optional, may drop silently]
   SC     → silent drop
Then install incoming fill into freed way.

Victim buffer [REC] (2–4 entries) decouples write-back drain from demand fill.

8.4 Snoop Path Timing

snp_req (S0) → tag lookup S1..S3 (shared ports, may bank-conflict)
            → state transition + optional data read
            → snp_rsp_* within CHI_TIMEOUT_SNP (5000 cycles)

Priority: Snoops take priority on bank arbitration to bound snoop latency.
