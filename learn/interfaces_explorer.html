Interface Overview
Five SystemVerilog interfaces forming the signal boundary of the Hanuma CHI NoC
System Architecture — Interface Placement
chi_link_if.sv
Primary CHI link between any two nodes. All 4 channels (REQ/RSP/SNP/DAT) with per-channel credit signals. Parametric widths.
requester completer monitor
chi_rn_if.sv
RN-centric convenience wrapper. Signals named from the RN's perspective: TX = what RN drives, RX = what RN receives.
rn hn monitor
chi_hn_if.sv
HN-centric interface with separate upstream (RN-facing) and downstream (SN-facing) signal groups. HN is completer upstream, requester downstream.
hn monitor
chi_sn_if.sv
SN-F (Slave Node) interface. SN only receives REQ+DAT and responds with RSP+DAT. Never originates snoops. Has link-activation signals.
sn hn monitor
noc_if.sv
Router-level flit bus. Carries noc_flit_ctrl_t with valid/ready handshake, VC ID, head/tail markers, and per-VC credit return.
source sink monitor

Embedded SVA Assertions
a_req_valid_needs_credit
REQ flit valid cannot be asserted without a prior pending signal. Ensures the pend→valid timing requirement of the CHI spec.
txreqflitv |-> ##[0:1] txreqflitpend;
a_link_active_ack
After txlinkactivereq rises, txlinkactiveack must be received within 20 cycles. Guards against link training stall.
$rose(txlinkactivereq) |-> ##[1:20] txlinkactiveack;

Key Design Note

chi_rn_if vs chi_link_if: Both interfaces carry identical signals. The difference is binding point of view. chi_link_if is technology-agnostic and requires selecting a modport (requester/completer) at connect time. chi_rn_if names signals from the RN's perspective, making module instantiation less error-prone in flat netlists where modport resolution is cumbersome. The hn modport in chi_rn_if is the exact mirror of the rn modport.

Embedded SVA Assertions
a_no_spurious_deassert
Once valid is asserted and the sink is not ready, valid must remain high next cycle. Prevents source from dropping a flit mid-transfer (AXI4-Stream style rule).
(valid && !ready) |=> valid;
a_lcrd_one_hot
At most one credit can be returned per cycle (one-hot or zero). Returning multiple credits simultaneously would corrupt the upstream counter.
$onehot0(lcrd_return);
Handshake Timing — valid / ready / lcrd_return

Transfer occurs when valid && ready on the same cycle. Credits are returned one cycle after consumption; a_no_spurious_deassert prevents source from retracting valid during stall.
