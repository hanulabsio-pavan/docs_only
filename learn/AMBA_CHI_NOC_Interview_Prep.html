Q01 Coherency Flows (HN/RN) Senior Logic Design
Describe the complete CHI transaction flow for a ReadUnique (MakeUnique) request from an RN-F when the cache line is held in a Modified state by a different RN-F.
▼
Core Technical Answer

When an RN-F wants to write to a cache line it does not own, it must acquire exclusive permissions. The flow across the CHI channels (REQ, SNP, RSP, DAT) is as follows:

  1. REQ Channel: The requesting RN-F sends a ReadUnique request to the Home Node (HN-F).
  2. HN-F Processing: The HN-F allocates a tracker, checks its Snoop Filter (SF), and identifies that RN-F_Owner holds the line in a Modified/Exclusive state.
  3. SNP Channel: The HN-F sends a SnpMakeInvalid (or SnpCleanInvalid) to the owning RN-F.
  4. RSP/DAT Channel (from Owner): The owning RN-F invalidates its local copy and responds. In a traditional flow, it sends SnpRespData (data + response) back to the HN-F.
  5. DAT Channel (to Requester): The HN-F forwards the data to the requesting RN-F via a CompData message.
  6. RSP Channel (from Requester): Once the requesting RN-F receives the data and completion, it sends a CompAck back to the HN-F, allowing the HN-F to deallocate the tracker and close the transaction.
Q02 CHI Issue E/F & CMN-700 Lead / Staff Design
How does Direct Cache Transfer (DCT), heavily featured in CHI Issue E and implementations like CMN-700, optimize the standard snoop response flow?
▼
Core Technical Answer

In the standard CHI flow, snoop data from an owning RN-F must be routed back to the HN-F, which then forwards it to the requesting RN-F. This adds an extra NoC hop and increases bandwidth utilization at the HN-F.

Direct Cache Transfer (DCT) eliminates this middleman for the data payload:

  • When the HN-F issues the snoop (e.g., SnpCleanInvalid) on the SNP channel, it embeds the ReturnNID (Node ID) of the requesting RN-F instead of its own.
  • The owning RN-F splits its response:
    • It sends a SnpRespFwded (status only, no data) on the RSP channel back to the HN-F to update the directory/tracker.
    • It sends CompData directly on the DAT channel to the requesting RN-F.
Architectural Tradeoff
Pro-Tip for Interviews: While DCT reduces latency and HN-F datapath congestion, it complicates the RN-F design. The RN-F must now be capable of sinking CompData from peer RN-Fs, not just the HN-F, and must handle complex race conditions if the direct data arrives before the HN-F's completion acknowledgment.
Q03 Hazards & Ordering Senior Logic Design
Why is the `CompAck` (Completion Acknowledge) message strictly required in CHI, and what race condition does it prevent at the HN-F?
▼
Core Technical Answer

Unlike AXI, where a transaction ends when the master receives the response (BVALID or RLAST), CHI requires the master (RN-F) to explicitly tell the Home Node (HN-F) that it has finalized the transaction by sending a CompAck on the RSP channel.

The Race Condition (Without CompAck):

  1. RN-F1 requests a line (ReadShared). HN-F sends CompData.
  2. If the HN-F immediately clears its internal tracker upon sending CompData, it believes RN-F1 now holds the line in a Shared state.
  3. Before the CompData physically traverses the NoC mesh to reach RN-F1, RN-F2 issues a WriteUnique to the same address.
  4. The HN-F receives the write, checks its directory, and immediately fires a SnpInvalidate to RN-F1.
  5. Because of NoC routing variations, the SnpInvalidate might arrive at RN-F1 before the original CompData. RN-F1 receives a snoop for a line it doesn't even know it has yet, leading to a fatal protocol error.

The Fix: The HN-F keeps the transaction "locked" in its active tracker until RN-F1 replies with CompAck. Any incoming snoops to that address are stalled or queued at the HN-F until the CompAck arrives.

Q04 NoC Routing & Deadlock Principal / System Architect
How does CHI utilize Virtual Networks (VNs) and Link-Layer Credits to ensure protocol-level deadlock avoidance across a mesh NoC?
▼
Core Technical Answer

Protocol deadlock occurs when a cyclic dependency is formed. In coherency protocols, a Request triggers a Snoop, which triggers a Response, which may trigger Data. If all these messages share a single physical buffer queue in the NoC routers, the network will deadlock when the queues fill up.

CHI Solution (Message Classes & VNs):

CHI strictly divides communication into four independent Message Classes, mapped to isolated Virtual Networks (VNs) inside the NoC routers. Each VN has its own dedicated buffer space and its own independent pool of Link-Layer Credits (L-Credits):

  • REQ (Request): Lowest priority. Can be stalled indefinitely without causing deadlock.
  • SNP (Snoop): Higher priority than REQ.
  • RSP (Response): Higher priority than SNP.
  • DAT (Data): Highest priority. Can always drain.

Because an RN or HN is architecturally guaranteed to always be able to sink and process an RSP or DAT message without generating new outward dependencies, the response VNs will always drain. This breaks the cyclic dependency loop, allowing SNP and eventually REQ buffers to unblock.

Q05 Coherency Flows (HN/RN) Lead / Staff Design
What is a Snoop Filter (SF) eviction, and why must the HN-F generate a back-invalidation to an RN-F when an eviction occurs?
▼
Core Technical Answer

The Snoop Filter (SF) located at the HN-F acts as a directory to track which RN-Fs hold copies of which cache lines. It prevents the HN-F from having to broadcast snoops to all cores in a many-core system.

To function correctly, the SF must maintain an Inclusive property—meaning the SF must have an entry for every line present in any RN-F's L2/L3 cache. However, the SF has finite capacity.

The Eviction Process:

  • When the SF is full and a new read request arrives, the SF must allocate a new entry by evicting an old one (usually via LRU/Pseudo-LRU).
  • If the SF simply dropped the old entry, it would lose track of a line that still exists in an RN-F's cache. If another core later wrote to that line, the HN-F wouldn't know to snoop the holding RN-F, breaking coherency.
  • Therefore, before the SF can evict an entry, the HN-F must issue a back-invalidation (e.g., SnpCleanInvalid or SnpSharedInvalid) to the RN-F(s) currently holding that line, forcing them to evict the line from their local caches and write back dirty data if necessary.
Q06 CHI Issue E/F & CMN-700 Principal / System Architect
In a Server-class architecture, explain how CHI handles Atomic operations (e.g., AtomicCompare, AtomicAdd). Where are they executed and why?
▼
Core Technical Answer

In legacy protocols, atomic operations were implemented using Load-Exclusive/Store-Exclusive (LL/SC) loops. In highly scaled server chips (like Power processors or high-core-count ARM SoCs), LL/SC causes massive thrashing, where a cache line ping-pongs between RN-Fs, consuming massive NoC bandwidth and causing livelocks.

CHI Near-Memory Atomics:

  • CHI resolves this by pushing the atomic arithmetic logic (ALU) away from the requester and down into the Home Node (HN-F) or Memory Controller (SN-F).
  • The RN-F sends an AtomicAdd or AtomicCompare request on the REQ channel, carrying the operands directly in the DAT channel.
  • The HN-F pulls the cache line from the SLC or memory, performs the arithmetic operation locally inside the HN-F's logic block, updates the directory, and returns the result (original or modified data) back to the RN-F.
  • Advantage: The cache line never moves to the requesting core. This reduces interconnect traffic by >50% for highly contented locks and guarantees forward progress for synchronization primitives.
Q07 Hazards & Ordering Senior Logic Design
Describe a WriteBack (WriteBackFull) hazard. How does the HN-F resolve a collision between an incoming WriteBack from an RN-F and an outgoing Snoop to that same RN-F?
▼
Core Technical Answer

A classic coherency hazard occurs when an RN-F decides to voluntarily evict a dirty cache line (issuing a WriteBackFull to the HN-F) at the exact same time another RN-F requests that line, causing the HN-F to issue a SnpCleanInvalid.

Because NoC routing is asynchronous, the requests cross paths in the mesh:

  1. The RN-F receives a snoop for a line it is in the process of writing back. It can no longer respond with data because the data is in the NoC DAT channel.
  2. RN-F Action: The RN-F responds to the snoop with a special status (e.g., SnpResp_WrBack or by deferring the response), indicating that it has already relinquished the line via a WriteBack.
  3. HN-F Action: The HN-F detects the collision. It must match the incoming WriteBackFull data with the outstanding Snoop tracker. It waits to receive the WriteBack data, sinks it, updates the directory, and then satisfies the new requester using the newly written-back data.
Q08 CHI Issue E/F & CMN-700 Lead / Staff Design
What is Stash (Stashing), and how do ReadPreferUnique/StashOnce operations allow endpoints to optimize memory placement ahead of software execution?
▼
Core Technical Answer

Stashing is a performance optimization feature in CHI where a master (like a PCIe controller or an accelerator) writes data to the system and simultaneously provides a "hint" to the interconnect to push that data directly into a specific CPU's L2/L3 cache, rather than leaving it in the HN-F's SLC or Main Memory.

  • A transaction like WriteStash or StashOnce includes the NodeID (NID) of the target RN-F.
  • When the HN-F processes the write, it generates a SnpMakeInvalidStash or similar snoop to the target RN-F.
  • If the target RN-F has available cache capacity, it allocates a line and pulls the data directly. When the software running on that core eventually needs the data (e.g., a network packet descriptor), it results in a fast L2 cache hit instead of a high-latency main memory access.
