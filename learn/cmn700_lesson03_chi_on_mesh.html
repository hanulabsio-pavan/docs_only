1From protocol to wires

caveman mode

CHI = the words. Mesh = the postal system. This lesson: watch a letter actually travel — who sends it, which mailbag (channel) it rides, who answers, and how the data comes back. No new protocol, just the journey.

You know CHI's message classes. Here we make them physical: each class is a separate network across the XPs, and a transaction is a choreography of flits hopping between RN, HN and SN. Being able to walk a transaction out loud is the single most common deep-dive in interviews.

2The four channels as independent networks

ChannelTypical directionCarries
REQRN → HNReads, writes, atomics, prefetch, CMOs.
RSPany ↔ anyCompletions, snoop responses, credits/acks. No data.
SNPHN → RN-FSnoops to caching requesters.
DATany ↔ anyThe cache-line data payload (read data, write data, copybacks, snoop data).

They share the same XPs but have separate buffers and arbitration. That independence is the deadlock-avoidance guarantee: a backed-up DAT flit can never block the RSP/SNP traffic needed to free it up.

3Flits & credited flow control

A flit (flow-control unit) is the quantum moved across a link each cycle. A CHI message becomes one or more flits. Links are credited: a sender transmits only while it holds credits for the downstream buffer, so nothing is ever dropped — overload becomes backpressure that propagates upstream. This is why a congested home node slows requesters rather than losing data, and it's the mechanism CBusy (Lesson 7) rides on.

4Transaction walk — a coherent read miss

An RN-F reads a line it doesn't have; the owning HN-F misses in its SLC, so memory is fetched:

ReadShared, SLC miss, no other sharer
  RN-F                 HN-F                 SN-F
   |   1. REQ ReadShared  |                    |
   | ───────────────► |  check SLC + SF     |
   |                    |  miss, no sharers  |
   |                    |  2. REQ Read       |
   |                    | ───────────────► | fetch line
   |                    |  3. DAT data       |
   |   4. DAT data       | ◄─────────────── |
   | ◄───────────────   | fill SLC, set SF    |
   | install line (Shared)|                   |

With Direct Memory Transfer (DMT), step 3/4 can be optimised so the SN returns data toward the requester directly, saving a hop through the HN. Each arrow is also several mesh hops (|ΔX|+|ΔY|) — that's the transport from Lesson 1 underneath the protocol.

5Transaction walk — a write-back

A dirty line evicted from an RN-F is written back to its home:

  • REQ: RN-F sends a WriteBack/CopyBack request to the owning HN-F.
  • RSP: HN-F returns a data-buffer credit (e.g. CompDBIDResp) telling the RN-F where to send data.
  • DAT: RN-F streams the dirty line on the data channel; HN-F updates its SLC/snoop-filter state (and may later write through to the SN-F).

Key idea: control (RSP) and data (DAT) are decoupled — the home node hands out a data-buffer ID first, then the data follows on its own network.

6Transaction walk — a snoop with cache-to-cache transfer

Now another RN-F already holds the line. The home node consults its snoop filter and snoops only that one sharer — and with Direct Cache Transfer (DCT) the data goes cache-to-cache:

Read with a sharer → targeted snoop + DCT
  RN-F (req)        HN-F          RN-F (owner)
     | 1.REQ Read  |                |
     | ─────────►| SF: owner is → |
     |            | 2.SNP (fwd)    |
     |            | ───────────► |
     |  3.DAT (cache-to-cache, DCT)   |
     | ◄────────────────────────── |
     | 4.RSP SnpResp to HN |          |
     |            | ◄──────────    | update SF

The win: no memory access at all, and the snoop went to one cache, not a broadcast — that's the snoop filter doing its job (detailed in Lesson 4).

7Where latency actually comes from

Hops

Each XP-to-XP step costs cycles; total ≈ |ΔX|+|ΔY|. Placement & mesh size set this.

Serialization

The home node orders contending requests to a line — a hot line queues.

Queueing / credits

Backpressure when buffers fill; busy SN/HN throttles upstream.

So "make it faster" usually means: fewer hops (placement), less contention (hashing/interleaving, L5), and congestion control (CBusy/re-routing, L7). The transaction walks above are the skeleton those optimisations hang on.

9Interview Q&A

Walk me through a read miss from a core.
RN-F issues a REQ (e.g. ReadShared) routed to the owning HN-F. The HN-F checks its SLC and snoop filter; on a clean miss it issues a read to the SN-F via its MC SAM. Data returns on DAT (optionally via DMT straight to the requester), the HN-F updates SLC + snoop-filter state, and the RN-F installs the line in the right state. Each arrow is several mesh hops.
Why four separate channels?
So message classes can't block each other: a stalled DAT flit can never hold up the RSP/SNP traffic needed to make forward progress. Independent buffers + credited flow control = no protocol deadlock.
How is data flow decoupled from control on a write-back?
The requester sends a write request on REQ; the home replies on RSP with a data-buffer ID/credit; only then does the data stream on DAT. Control and data ride different networks, so the home can pace incoming data.
What does the snoop filter save you on a shared read?
It tells the home exactly which caches hold the line, so it sends a targeted snoop to one owner instead of broadcasting — and with DCT the owner forwards data cache-to-cache, avoiding a memory access entirely.
Where does mesh latency come from?
Hop count (|ΔX|+|ΔY|), serialization at the home node for contended lines, and queueing/backpressure when buffers fill. Mitigations: placement, address interleaving, and congestion control.

10Recap & key terms

  • REQ (RN→HN), SNP (HN→RN-F), RSP & DAT (any↔any) — four independent networks.
  • Flits ride credited links; overload = backpressure, never loss.
  • Read miss: REQ→HN, HN→SN, DAT back (DMT can shortcut).
  • Write-back: REQ, then RSP grants a data-buffer ID, then DAT.
  • Shared read w/ owner: targeted SNP + DCT = cache-to-cache, no memory.
