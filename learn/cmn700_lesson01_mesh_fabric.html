The Mesh Fabric & Crosspoints

Before any cache or coherency logic, CMN-700 is a grid of routers moving packets. Get this transport layer solid and every later lesson clicks into place.

By the end of this lesson you can

  • Draw a crosspoint (XP/MXP) and label its mesh ports and device ports.
  • Explain the (X,Y) coordinate system and how a node ID is composed.
  • Describe credited, per-channel links and the double-mesh-channel option.
  • Route a flit deterministically from one XP to another and explain why it can't deadlock.

1Why start with the fabric

caveman mode

Before worry about what message say, learn how message travel. Build roads first. Roads = mesh. Crossroads = routers. Once roads clear in head, all the clever cache talk just becomes "who sends what down which road."

You already know CHI as a protocol — the rules for requests, responses, snoops and data. CMN-700 is the machine that carries those messages. That machine is a 2-D mesh: a rectangular grid of router blocks called crosspoints. Everything else in this course — home nodes, SLC, SAM, QoS — is logic bolted onto this grid. So we anchor here first.

A full CMN-700 mesh can be as large as 12×12 = 144 crosspoints, but most designs are far smaller (a 2×4 edge SoC, a 6×6 mid-range part). The grid is configured at build time; what stays constant is how a crosspoint works.

2The crosspoint (XP / MXP)

The crosspoint — written XP or MXP (Mesh Cross Point) — is the atom of the fabric. Think of it as a small router with two jobs: forward traffic to neighbouring crosspoints, and inject/eject traffic for the components plugged into it. Internally it switches each of the four CHI channels independently.

Anatomy of one crosspoint (XP)
                    North mesh port
                         ▲
                         │  to XP above
                 ┌───────┴───────┐
   West          │      XP       │          East
   ◄────────────┤  per-channel  ├────────────►
   to XP left    │   switching   │    to XP right
                 └───┬───────┬───┘
                     │       ▼  South mesh port (to XP below)
            ┌────────┴──┐ ┌──┴────────┐
            │ device P0 │ │ device P1 │   + P2 (and P3 on edge XPs)
            └─────┬─────┘ └─────┬─────┘
                  │             │
               [RN-F]        [HN-F]   whatever attaches here

The four mesh ports (N/S/E/W) connect to the adjacent crosspoints — edge and corner XPs simply have fewer neighbours. The device ports are where actual components attach. The internal switch arbitrates, per channel, between flits arriving from any port and chooses the next hop.

3Mesh ports vs device ports

Mesh ports (×4)

North, South, East, West. They link XP→XP and form the grid. Carry through-traffic that's just passing by, plus traffic entering/leaving the local devices.

Device ports

Where components plug in: a CHI agent (CPU cluster), an HN-F/SLC slice, an SN-F memory interface, or an AMBA bridge. This is the on/off ramp to the fabric.

A key CMN-700 upgrade over CMN-600: device-port density. CMN-600 allowed 2 devices per XP; CMN-700 supports 3 per XP, 4 on an edge XP (and up to 5 in a single-XP topology). When you still need more components than ports, the CAL (Component Aggregation Layer) lets several devices share one device port — we cover it more in Lesson 2.

Why this matters: more devices per XP means a given amount of compute/memory/IO fits in a smaller mesh, which lowers hop count and latency. Port density is a real area-vs-latency lever.

4Coordinates & node IDs

caveman mode

Every crossroad has an address on the grid: how far right (X) and how far up (Y). Bottom-left corner = (0,0). To name a specific driveway at that crossroad, add which port and which device. That full name = node ID. Routing = "get this flit to that node ID."

Each XP has an (X,Y) coordinate. (0,0) is the bottom-left; the top-right of a full grid is (11,11). The X and Y values are also called XID and YID.

A node ID uniquely names an endpoint on the mesh. Conceptually it's built from sub-fields:

Node ID composition (conceptual)
   node ID  =  [ X ] [ Y ] [ port ] [ device ]
               which XP ───┘    └── which on-ramp at that XP

   e.g.  XP (2,1), device port 0, sub-device 1
         ────────────────────────────────────► one specific RN-F

The number of bits given to each field scales with the configured mesh size (a bigger grid needs more X/Y bits). You don't need exact widths for an interview — what matters is the idea: routing is by node ID, and the node ID encodes the destination's grid position plus which port/device. The XP examines the X/Y of the target and forwards toward it.

This is also why the PMU lets you target a specific node by its nodeid (Lesson 9): the ID is a real coordinate-based handle, not an opaque number.

5Links, flits & the four channels

The wires between crosspoints are credited links: a sender only transmits when it holds a credit proving the receiver has buffer space, so flits are never dropped — congestion turns into backpressure, not loss. The unit of transfer on a link is a flit (flow-control unit); a CHI message is carried as one or more flits.

Critically, the four CHI channel classes each ride their own independent network across the mesh:

ChannelCarries
REQRequests from a requester toward a home node (reads, writes, atomics, prefetch).
RSPControl/coherence responses & completions — no data payload.
DATThe cache-line data payload. The widest, highest-bandwidth channel.
SNPSnoops sent from a home node down to caching requesters.

Keeping them separate is how the fabric avoids protocol deadlock: a stalled data flit can never block a response or snoop that's needed to make forward progress. This maps directly onto CHI's channel independence — CMN-700 just gives each channel real wires and buffers.

6Channel width & the double mesh channel

The DAT channel is the bandwidth backbone. Baseline is a pair of 256-bit data paths — one for each direction (transmit / receive). CMN-700 offers an optional double mesh channel: a second 256-bit pair, giving effectively 512-bit data lanes per direction. AMBA AXI and CXS interfaces widen to 512-bit to match.

Back-of-envelope bandwidth

Peak cross-sectional bandwidth ≈ (links crossing the mesh midline) × (width) × (frequency). For a full 12×12 mesh at ~2 GHz with the double-width data channel, Arm quotes roughly 3.07 TB/s. The takeaway for interviews: bandwidth scales with mesh width and channel width — the double mesh channel is the knob for data-hungry designs.

7Routing across the grid

caveman mode

Simple rule so no two flits ever wait on each other in a circle: always travel one direction first (say, sideways) until lined up, then the other direction (up/down). Same rule everywhere = no traffic-jam loops = no deadlock.

CMN-700 uses deterministic dimension-ordered routing: a flit travels along one axis first, then the other, following the target node ID's X/Y. Because every flit obeys the same turn rule, the fabric is provably free of routing deadlock — there's no cycle of buffers all waiting on each other.

Two consequences worth stating in an interview:

  • Predictable latency: hop count ≈ |ΔX| + |ΔY| between source and destination XPs. This is why placement (where you put CPUs vs HN-F vs memory) affects performance — a topic in Lesson 7.
  • Ordering: deterministic paths keep same-source/same-dest traffic in order on a channel; adaptive hot-spot re-routing (Lesson 7) is the controlled exception.

8Worked example — route a flit from (0,0) to (3,2)

A REQ flit leaves an RN-F at XP (0,0) heading for an HN-F at XP (3,2). Dimension-ordered routing (X-first here) sends it east to X=3, then north to Y=2 — 5 hops:

X-first, then Y · 5 hops · (0,0) → (3,2)
  Y=2  (0,2)─────(1,2)─────(2,2)─────(3,2)   ◄ destination HN-F
                                       ▲
                                       │ step 5: north
  Y=1  (0,1)─────(1,1)─────(2,1)─────(3,1)
                                       ▲
                                       │ step 4: north
  Y=0  (0,0)═══►(1,0)═══►(2,0)═══►(3,0)
       source   1       2       3   then turn
        RN-F   east    east    east    north ↑

  hops = |ΔX| + |ΔY| = |3-0| + |2-0| = 5

The response and any data take their own channels back. Notice nothing here is about coherency yet — it's pure transport. That's the whole point of Lesson 1: once the road network is clear, Lessons 2–10 are about who sits at each XP and what they say.

10Interview Q&A

Sketch the CMN-700 mesh and walk a packet from a CPU to memory.
Draw a grid of XPs (routers) with N/S/E/W mesh links. Attach an RN-F (CPU) at one XP, an HN-F at another, an SN-F (memory controller) at a third. The CPU's RN issues a REQ flit; routing is dimension-ordered (X then Y) by the target node ID toward the owning HN-F; if the HN-F misses, it forwards to the SN-F via its MC SAM; data returns on the DAT channel. Emphasise: four independent channels, credited links, hop count = |ΔX|+|ΔY|.
What is a crosspoint and what ports does it have?
The XP/MXP is the mesh router. It has four mesh ports (N/S/E/W) linking neighbouring XPs, plus device ports (up to 3, or 4 on an edge XP) where components attach. It switches each CHI channel independently and arbitrates between through-traffic and local inject/eject.
How is a node addressed on the mesh?
By node ID, which encodes the XP's (X,Y) coordinate plus which port and device. Routing forwards toward the target's X then Y. Field widths scale with mesh size. (0,0) is bottom-left; a full grid tops out at (11,11).
Why is the routing deadlock-free?
Deterministic dimension-ordered routing imposes the same turn discipline everywhere (one axis fully, then the other), so no cyclic dependency among link/buffer resources can form. Combined with separate per-channel networks and credited flow control, the fabric can't deadlock at the routing level.
How does mesh size relate to bandwidth and latency?
Latency tracks hop count (|ΔX|+|ΔY|), so larger meshes mean longer average paths — placement matters. Cross-sectional bandwidth scales with the number of links crossing the midline times channel width times frequency; the double mesh channel widens DAT to 512-bit. A full 12×12 at ~2 GHz reaches ~3 TB/s.

11Recap & key terms

  • CMN-700 is a 2-D mesh of crosspoints (XP/MXP), up to 12×12 = 144.
  • Each XP has 4 mesh ports (N/S/E/W) and device ports (3, or 4 on edges; CAL aggregates more).
  • Endpoints are named by node ID = (X,Y) + port + device; (0,0) is bottom-left.
  • Four CHI channels (REQ/RSP/SNP/DAT) ride independent credited networks → no deadlock.
  • DAT is 256-bit per direction, optionally 512-bit via the double mesh channel.
  • Routing is deterministic dimension-ordered; hop count = |ΔX| + |ΔY|.
