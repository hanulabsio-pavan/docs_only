Coherency Flows & CHI-E Optimizations

Cache states, snoop flows, and the latency-cutting features: DMT, DCT, atomics and cache stashing.

By the end of this lesson you can

  • Trace coherent read, write and upgrade flows and the snoop responses involved.

1From walks to flows

caveman mode

Lesson 3 = watch letter travel. This lesson = the clever shortcuts. Why send data all the way back through home node when memory can throw it straight at the asker? Why go to memory at all when neighbour cache already hold line? Each trick save hops. Hops = time.

Lesson 3 gave you the baseline choreography. Now we look at the CHI Issue E optimisations that CMN-700 implements in hardware, all of which exist for one reason: remove hops and round trips from the critical path. In an interview, naming these and saying which hop each one removes is what separates recall from understanding.

2What the home node tracks

For each line in its range, the owning HN-F holds two related pieces of state:

SLC state

Is the line present in this slice, and is it clean or dirty? Drives whether memory must be touched at all.

Snoop-filter state

Which RN-Fs hold a copy, and broadly in what state (shared vs unique/owned). Drives who gets snooped and whether a snoop can supply data.

Every flow below is really the home node reading those two pieces of state and choosing the cheapest legal way to satisfy the request. The possibilities:

Home-node findingCheapest path
Hit in SLC, no other sharer conflictServe from the slice — no memory, no snoop.
Miss in SLC, another RN-F holds itSnoop that RN-F; with DCT it forwards data cache-to-cache.
Miss in SLC, nobody holds itFetch from SN-F; with DMT memory returns data straight to the requester.
Write / upgrade with sharersInvalidate sharers via snoops, then grant unique ownership.

3Direct Memory Transfer (DMT)

Baseline miss path: the home node reads memory, memory returns data to the home node, and the home node forwards it to the requester. That's a wasted store-and-forward through the HN.

DMT lets the home node instruct the SN-F to return data directly toward the requester. The home node still owns coherency — it stays in the control loop via responses — but the data payload skips the extra hop.

Without DMT vs with DMT
-- baseline: data store-and-forwards through the home node --
  RN-F --REQ-> HN-F --REQ-> SN-F
  RN-F <-DAT-- HN-F <-DAT-- SN-F      2 data legs

-- with DMT: memory answers the requester directly --
  RN-F --REQ-> HN-F --REQ-> SN-F
  RN-F <------------- DAT --------- SN-F   1 data leg

Biggest win when the home node is far from both requester and memory — exactly the case in a large mesh.

4Direct Cache Transfer (DCT)

If a peer cache already holds the line, going to DRAM is pure waste. DCT has the snooped RN-F forward the line straight to the requesting RN-F, cache-to-cache, while the snoop response goes to the home node so it can update the snoop filter.

DCT: data cache-to-cache, response to home
  RN-F (asks)      HN-F         RN-F (owns)
      --REQ-->          |               |
      |            SF: owner known    |
      |              --SNP (fwd)-->       |
      <=========== DAT (cache-to-cache) ====
      |              <--SnpResp----       |
      no DRAM access at all; SF updated from SnpResp

DCT is the reason producer–consumer sharing between two cores is fast on a mesh: the line moves core-to-core at mesh latency, never at DRAM latency.

5Atomics

caveman mode

Old way to add 1 to shared counter: grab line exclusive, bring it home, add, write back. Line bounce between cores like hot potato. New way: send "add 1" to the counter. Work happen where data live. No bouncing.

CHI-E atomics let an operation (add, swap, compare-and-swap, logical ops) be executed near the point of coherency or near memory instead of requiring the requester to take the line into its own cache first.

Why it matters

A read-modify-write on a contended variable no longer ping-pongs the line between caches. One message out, one response back.

Where it shines

Highly contended counters, locks, reference counts, queue head/tail pointers — the classic many-core scaling killers.

6Cache stashing

Stashing inverts the usual direction: instead of a consumer pulling data, a producer pushes data into a target cache so it's already warm when the consumer looks. A NIC receiving a packet can stash it toward the core (or the SLC region) that will process it, converting what would have been a cold miss into a hit.

Pair this with prefetch hints (which the RN SAM can even target straight at a memory controller, Lesson 5) and you have two complementary ways to hide latency: pull early, or have someone push for you.

7Hazards, retries and forward progress

All of this happens under contention, so the home node needs rules for when two operations collide on one line:

  • Hazard detection. A new request arriving while a snoop or fill for the same line is outstanding is a hazard. The home node detects it rather than letting the two interleave.
  • Hold or retry. The home either holds the request in a tracker until the in-flight operation completes, or sends a retry so the requester re-issues later.
  • Tracker capacity. The home node has a finite number of outstanding-transaction slots. When they fill, that becomes backpressure — and it is one of the signals congestion control reacts to (Lesson 7).
  • Forward progress. Because the home is the single point of serialization, it can guarantee that a contended line makes progress rather than livelocking.

Good interview instinct: whenever you describe an optimisation, mention what it does under contention. Optimisations that only work on quiet lines are not interesting in a 256-core system.

10Interview Q&A

What does CMN-700 add over plain CHI?
CHI is the protocol contract; CMN-700 is the implementation. It adds the physical realisation — distributed home nodes with SLC and snoop filters, the SAM and address hashing, per-channel mesh networks, QoS and congestion control, multichip gateways, and the distributed PMU — plus hardware support for the CHI-E optimisations (DMT, DCT, atomics, stashing).
Explain DMT and DCT and the difference between them.
Both remove a data hop. DMT: on an SLC miss, the memory controller returns data directly toward the requester instead of store-and-forwarding through the home node. DCT: when a peer cache holds the line, that cache forwards it directly to the requester, avoiding DRAM entirely. DMT optimises the memory path; DCT optimises the cache-to-cache path. In both cases the home node stays in the control loop to maintain coherency state.
How do near-memory atomics improve scalability?
A classic read-modify-write requires the requester to obtain the line uniquely, so a contended counter migrates between caches on every increment. Executing the atomic near the point of coherency or near memory means one request out and one response back, with no line migration — removing the ping-pong that limits many-core scaling on locks and counters.
What is cache stashing used for?
Pushing data into a target cache before it is requested, so the consumer hits instead of missing. Typical use: a NIC or accelerator stashes an inbound packet toward the core or cache region that will process it, hiding memory latency for streaming workloads.
How does the home node keep a contended line making progress?
It is the single point of serialization, so it detects hazards (a new request colliding with an in-flight snoop or fill) and either holds the request in an outstanding-transaction tracker or issues a retry. Because ordering decisions all happen at one place, it can guarantee forward progress rather than livelock. When trackers fill, that appears upstream as backpressure.

11Recap & key terms

  • Home node picks the cheapest legal path using SLC state + snoop-filter state.
  • DMT: memory returns data straight to the requester — removes a data leg.
  • DCT: owning cache forwards cache-to-cache — removes DRAM entirely.
  • Atomics near memory/home stop line ping-pong on contended variables.
  • Stashing pushes data into a cache before it is asked for.
  • Hazards are detected and held/retried at the home; trackers filling becomes backpressure.
