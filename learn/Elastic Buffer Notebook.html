Elastic Buffer Notebook

The elastic buffer

notes · CDC in serial links (PCIe / USB3 / SATA PHY) · 27 Sep 2026

1The problem

Transmitter and receiver run off separate reference clocks. CDR recovers the Tx clock (rclk) from the data, but the Rx core runs on its own local clock (lclk). Same nominal frequency, never exactly equal.

  • PCIe allows ±300 ppm per side → worst case 600 ppm apart
  • 600 ppm = one symbol slips every 1/600e-6 ≈ 1667 symbols
  • Plain async FIFO would drift → overflow if rclk faster, underflow if lclk faster

Fix: protocol sends SKP ordered sets periodically. SKP symbols carry no data, so receiver may add or drop them to soak up the rate difference. The buffer "stretches" → elastic.

3Why gray-coded pointers

Gray code changes exactly one bit per increment. If the lclk flop samples mid-transition, it gets either the old or the new value. Never a garbage pointer. Binary 0111→1000 flips 4 bits, so a sampled value could be anything.

bin→gray
g = b ^ (b >> 1)

gray→bin
b[i] = ^g[W-1:i] (XOR from MSB down)

Pointers are one bit wider than the address, so full vs empty can be told apart. Sync delay (2–3 lclk) means the read side sees a slightly stale level. That only costs margin, never correctness.

4The add / drop rule

In lclk: level = wr_ptr_sync − rd_ptr. Only act when a SKP is at the read head.

  • level > HI and head is SKP → skip it (rd_ptr += 2)
  • level < LO and head is SKP → emit it again, hold rd_ptr
  • otherwise → normal read, rd_ptr += 1
  • report each add/drop to the MAC (PIPE RxStatus = SKP added / removed)

Variant: drop on the write side (just don't write the SKP), insert on the read side. Then rd_ptr must also be synced into rclk.

5Sizing the depth

drift between SKPs = interval × Δf
= 1538 symbols × 600e-6 ≈ 0.92 symbol
→ at most 1 add/drop per SKP OS ✓

So drift alone needs ~1 entry each way. Real depth comes from everything else:

  • sync latency in the level compare (2–3 lclk)
  • add/drop granularity (Gen3+ 128b/130b adjusts in 4-symbol chunks)
  • SKP not arriving during a long TLP → worst gap between SKPs
  • SSC / SRIS (one side spread, one not) → up to ~5600 ppm, needs deeper buffer + more frequent SKP

Rule of thumb: depth ≥ 2 × (max drift + sync lag) + margin → typically 8–16 entries, preloaded to N/2 so it can absorb both directions.

6RTL sketch (read side)

// lclk domain
always @(posedge lclk) begin
  wr_g_s1 <= wr_ptr_gray;      // 2-FF sync
  wr_g_s2 <= wr_g_s1;
end

wire [AW:0] wr_b   = gray2bin(wr_g_s2);
wire [AW:0] level  = wr_b - rd_ptr;
wire        is_skp = (ram[rd_ptr[AW-1:0]] == SKP);

always @(posedge lclk or negedge rst_n) begin
  if (!rst_n)                        rd_ptr <= '0;
  else if (rd_en) begin
    if      (is_skp && level > HI_TH) rd_ptr <= rd_ptr + 2; // drop
    else if (is_skp && level < LO_TH) rd_ptr <= rd_ptr;     // insert
    else                              rd_ptr <= rd_ptr + 1; // normal
  end
end

+ write side: wr_ptr++ every rclk symbol, register the gray version before it leaves the domain (no comb logic into the sync flop!)

Gotchas (interview traps)

  • Gray pointer must come straight from a flop. Comb logic can glitch into the synchronizer.
  • Drop only if a second SKP remains. PCIe needs at least 1 SKP left in the set.
  • Hold reads until preload reaches N/2 after reset / CDR lock.
  • One buffer per lane. Lane-to-lane deskew is a separate stage after it.
  • Over/underflow still possible (bad link) → flag it in RxStatus, don't hide it.
