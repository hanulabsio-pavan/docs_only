Deep Dives · Lesson 5 of 7

Key Features

The three subsystems that give Power its performance character: a floating-point unit built for science, a SIMD stack layered three generations deep, and a memory hierarchy designed around very large shared caches.

By the end of this lesson you can

  • Explain exactly why a fused multiply-add is more accurate than a multiply then an add — and demonstrate a case where the answers differ.
  • Lay out a 128-bit vector register in any element width and predict modulo vs saturating results.
  • Say what MMA actually buys over ordinary SIMD FMA, in terms of operand bandwidth.
  • Describe the POWER9/POWER10 cache hierarchy and reason about where a working set lands.
  • Explain the ERAT, the TLB, and what dcbt and dcbz are for.

1Floating-point: built for numerics

The RS/6000 was a scientific workstation, and Power's floating-point unit has carried that inheritance ever since. Three properties matter most:

Full IEEE 754

Binary32 and binary64 from the start; binary128 in hardware from v3.0. All five exceptions, all four rounding modes, proper NaN and infinity semantics.

FMA as a primitive

fmadd has been there since POWER1 — decades before x86 got it. Not an add-on: the multiplier and adder are one pipeline.

Decimal in hardware

IEEE 754-2008 decimal64/128 since v2.05. Financial arithmetic where 0.1 + 0.2 must be exactly 0.3.

FPSCR: the control surface
FieldPurpose
RN (2 bits)Rounding mode: to-nearest-even (default), toward zero, toward +∞, toward −∞.
FX, FEX, VXSummary bits — exception occurred, enabled exception occurred, invalid operation.
OX, UX, ZX, XXSticky flags: overflow, underflow, zero-divide, inexact. Sticky means they stay set until cleared.

Read it with mffs, write it with mtfsf. The fri* round-to-integer family (v2.02+) exists precisely so you can round a specific way without the expensive round trip of saving FPSCR, changing RN, computing, and restoring it.

performance trap

Changing the rounding mode serialises the FPU. mtfsf is a synchronising operation on most implementations, so a loop that flips rounding mode per iteration can be an order of magnitude slower than the same loop using friz/frin. If you see mtfsf inside a hot loop in a profile, that is your problem.

2FMA precision lab

A fused multiply-add computes a×c + b with one rounding, at the end. Doing it as two instructions rounds twice — once after the multiply, once after the add. Usually that difference is invisible. Sometimes it is the entire answer.

caveman mode

Multiply make long number. Two-step machine must chop it before adding — information gone forever. Fused machine keep whole long number inside, add, chop once at end. Same speed, better answer. This why Power good at science for 30 years.

Two consequences worth carrying around:

  • Accuracy. FMA keeps the full-width product, so error accumulation in dot products, matrix multiplies and Newton–Raphson refinement is roughly halved.
  • Throughput. One instruction and one pipeline pass rather than two, and the dependency chain is shorter. A dense linear-algebra kernel is essentially a stream of FMAs.

This is also why -ffp-contract exists in compilers: contracting a*b+c into an FMA changes results bit-for-bit, so strict-IEEE builds may need it disabled for reproducibility across architectures.

3Decimal floating-point and IEEE-128

DFP — why it exists

Binary floating-point cannot represent 0.1 exactly, so repeated financial arithmetic drifts. Regulations in banking and insurance often mandate decimal semantics. Software decimal libraries are 100–1000× slower than hardware.

DFP — what Power provides

Hardware decimal64 and decimal128 from v2.05 (POWER6), operating on FPRs and FPR pairs using densely-packed-decimal encoding. dadd, dsub, dmul, ddiv, dqua (quantize/round to a decimal place), plus conversions.

IEEE binary-128 arrived in v3.0 as a genuine hardware quad-precision format (xsaddqp, xsmulqp, xsdivqp, xssqrtqp). This replaced the old "double-double" software long double, which had 106 bits of precision but non-IEEE exponent behaviour and awkward edge cases. On ppc64le, long double can now be true IEEE binary128 — a real ABI-visible change that distributions had to migrate through.

4The SIMD data model

Everything vector on Power is a 128-bit register reinterpreted as lanes. The register does not know what it holds; the instruction decides.

One 128-bit VSR, five interpretations
  bit  0                              64                            127
  byte   │16 lanes of 8 bits — vaddubm, string and codec work        │
  half   │ 8 lanes of 16 bits — audio, bfloat16 via MMA                 │
  word   │ 4 lanes of 32 bits — int32 or 4 × float                    │
  dword  │ 2 lanes of 64 bits — int64 or 2 × double                   │
  quad   │ 1 lane of 128 bits — IEEE binary128, 128-bit integer         │
Modulo vs saturating

VMX integer instructions come in two families, encoded in the mnemonic:

  • m = modulo — vaddubm wraps around, like C unsigned arithmetic. 250 + 10 = 4.
  • s = saturating — vaddubs clamps at the type maximum. 250 + 10 = 255, and VSCR[SAT] is set.

Saturation is not a curiosity — it is exactly what image and audio processing want, because a bright pixel plus more brightness should be white, not black.

The permute network

vperm is AltiVec's signature instruction: it takes two source vectors as a 32-byte pool and a third vector of 32 byte-indices, and produces any arbitrary rearrangement in one instruction. Shuffles, byte swaps, table lookups, unaligned assembly, matrix transposes — all become one vperm. VSX's xxpermdi is the doubleword-granular equivalent.

6MMA: why eight extra 512-bit registers earn their keep

The argument for MMA is not "more FLOPs per instruction" — it is operand bandwidth. A matrix multiply is arithmetically trivial and bottlenecked almost entirely on feeding the arithmetic units.

A POWER10 core carries four MMA engines. You almost never write these by hand — GCC and LLVM expose __builtin_mma_* intrinsics, and OpenBLAS and similar libraries use them under the hood. But knowing why the accumulators are architected state, rather than a hidden buffer, is the interview answer: they have to survive across many instructions, so they must be saveable and restorable on context switch.

7The memory hierarchy

Power's distinguishing choice at the top end is a very large shared L3, historically built from eDRAM, arranged as a non-uniform cache (NUCA): each core has a nearby region but can use the whole array.

L1 = pocket, tiny and instant. L2 = backpack. L3 = big shared shed near the camp — Power builds a very big shed. Memory = the warehouse across town. Other socket's memory = warehouse in next town. Every step out costs ~10× more time.

128-byte cache lines are worth internalising because they are double the x86/Arm norm. Consequences:

  • Sequential streaming is efficient — one miss brings in twice the data.
  • False sharing is twice as easy to trigger. Two hot per-thread counters 64 bytes apart share a line on Power but not on x86. Pad to 128 bytes.
  • dcbz zeroes a whole 128-byte block without reading it from memory first — a large win for memset and for initialising freshly allocated pages.

Power cores also have aggressive hardware stream prefetchers configured through the DSCR (Data Stream Control Register), which is user-accessible. Tuning DSCR is a real technique on POWER for streaming workloads — and one of the few places where user code can meaningfully steer the memory subsystem.

10Bandwidth, OMI and accelerator attach

Power's design point is bandwidth per socket rather than raw core count, which follows from its target workloads: large databases, analytics and HPC.

OMI — Open Memory Interface

POWER10 replaces a wide parallel DDR bus with a narrow serial link to off-chip memory controllers. Fewer pins per unit of bandwidth, and the media becomes pluggable: the same processor can sit behind DDR4, DDR5, or in principle GDDR, HBM or storage-class memory, because only the buffer chip knows the media.

Coherent accelerator attach

CAPI, then OpenCAPI, then PowerAXON: interfaces that let an FPGA or accelerator participate in the coherence domain and share virtual addresses with the host, rather than DMAing through a driver. POWER9 also carried NVLink 2.0 for coherent GPU attach — that is precisely what made the Summit and Sierra supercomputers work.

The strategic point: for the workloads Power targets, the bottleneck is rarely the core. It is getting data to the core and getting accelerators into the same coherent view of memory. Most of what looks distinctive about Power at the system level — huge L3, OMI, OpenCAPI, SMT8 — is an answer to that.

12Interview Q&A

Why is fused multiply-add a big deal?
Two reasons. Accuracy: the product is kept at full internal width and only one rounding happens, after the addition, so error accumulation in dot products, matrix kernels and iterative refinement is roughly halved — and there are cases where the two-instruction sequence loses the answer entirely to cancellation. Throughput: it's one instruction, one pipeline pass, and a shorter dependency chain, and dense linear algebra is essentially nothing but multiply-accumulate. Power has had it since POWER1, decades before x86.
Explain modulo versus saturating vector arithmetic.
Modulo instructions (the m suffix, e.g. vaddubm) wrap on overflow like ordinary unsigned C arithmetic — 250 + 10 in a byte lane gives 4. Saturating instructions (s, e.g. vaddubs) clamp at the type's limit and set VSCR[SAT] — 250 + 10 gives 255. Saturation is what media processing wants: brightening an already-bright pixel should give white, not wrap to black. Having both in the ISA means neither case needs a compare-and-branch.
What does MMA actually do, and why are the accumulators architected state?
An MMA ger instruction performs a rank-1 outer product: from two input vectors it updates every cell of a 512-bit accumulator tile in one instruction. The point isn't peak FLOPs, it's operand bandwidth — a matrix multiply is bottlenecked on feeding the arithmetic units, and keeping the output tile resident in a dedicated register collapses the reads-per-FLOP ratio. The accumulators are architected rather than hidden because they hold live state across many instructions, so they must be saveable and restorable across a context switch. They overlay VSR0–31, which means those registers are unavailable while an accumulator is primed.
Describe the POWER10 cache hierarchy.
Per core: 48 KB L1 instruction, 32 KB L1 data, and a 2 MB L2 — a big step up from POWER9's 512 KB. Beyond that a shared L3 of up to about 120 MB arranged as a non-uniform cache, roughly 8 MB of region per core but usable as one array, so a core can spill into a neighbour's region at higher latency. Cache lines are 128 bytes throughout, double the x86 norm. Off-chip, POWER10 uses OMI — a serial memory interface to buffer chips — rather than a wide parallel DDR bus.
What porting bugs does Power's 128-byte cache line cause?
Mainly false sharing. Code tuned for x86 pads hot per-thread structures to 64 bytes; on Power two such structures still share a line, so every write by one thread invalidates the other's copy and throughput collapses under contention. The fix is to pad to 128 bytes, ideally via a cache-line-size constant rather than a literal. The flip side is that streaming code benefits — one miss brings in twice the data — and dcbz can zero a whole 128-byte block without reading it.
What is the ERAT and why does it exist separately from the TLB?
The ERAT — Effective-to-Real Address Translation cache — is a very small, per-core, split instruction/data structure that can be looked up within the address-generation stage. The TLB is larger and shared, tagged with the (LPID, PID) pair, and a hit there still costs more than an ERAT hit. Splitting them is the same idea as splitting L1 from L2: the tiny fast structure keeps the pipeline fed, the larger one catches what it misses, and only then do you pay for a page-table walk.
How would you speed up a memory-bound loop on Power?
First, check the working set against the hierarchy — tiling to fit L2 usually beats anything else. Then use large pages to stop TLB thrashing, and on multi-socket machines make sure allocation is NUMA-local. At the instruction level, dcbt can prefetch irregular access patterns the hardware streamer won't predict, dcbz avoids read-for-ownership when you're overwriting whole lines, and the DSCR lets you tune the hardware stream prefetcher from user code. Padding shared structures to 128 bytes eliminates false sharing.
Why does Power have decimal floating-point in hardware?
Because binary floating-point cannot represent decimal fractions like 0.1 exactly, and financial and regulatory arithmetic often requires exact decimal semantics with specified rounding. Software decimal libraries are orders of magnitude slower. Power added IEEE 754-2008 decimal64 and decimal128 in hardware in v2.05 with POWER6, operating on the FPRs using densely-packed-decimal encoding. It reflects Power's customer base — banking, insurance and ERP workloads on AIX and IBM i.

13Recap & key terms

  • FMA rounds once, keeping the full product — more accurate and faster. Present since POWER1.
  • FPSCR carries the rounding mode and sticky exception flags; mtfsf in a hot loop is a performance bug.
  • DFP (v2.05) for exact decimal; IEEE binary128 in hardware (v3.0).
  • A 128-bit vector is 16/8/4/2/1 lanes; m = modulo, s = saturating; vperm is arbitrary byte shuffle.
  • MMA wins on operand bandwidth: a rank-1 outer product updates a resident 512-bit tile.
  • POWER10: 48 KB L1I / 32 KB L1D / 2 MB L2 / ~120 MB shared L3, 128-byte lines, 4096-entry TLB.
  • 128-byte lines double the false-sharing risk versus x86 — pad accordingly.
  • ERAT → TLB → page-table walk; large pages are the main TLB lever.
  • dcbt prefetch · dcbz zero-without-read · DSCR steers the hardware prefetcher.
  • OMI decouples the processor from the memory media; OpenCAPI/NVLink put accelerators in the coherence domain.
