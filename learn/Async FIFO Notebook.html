Async FIFO Notebook

The asynchronous FIFO

notes · multi-bit CDC · design + interview Q&A · 27 Sep 2026

1Why we need it

Writer runs on wclk, reader on rclk. The clocks are unrelated (different frequency, unknown phase). You cannot pass a multi-bit bus through 2-FF synchronizers: each bit can resolve differently, so the receiver sees a value that never existed.

  • Data itself never gets synchronized. It sits in a dual-port RAM and is only read once it is stable.
  • Only the pointers cross domains, and they cross as gray code.
  • Each side makes its own flag: full in wclk, empty in rclk.

2Block diagram

only gray pointers cross the red line. RAM is written in wclk, read in rclk

3Pointers: AW+1 bits, gray coded

Address = low AW bits. The extra MSB is a wrap bit: it flips each time the pointer goes round the RAM. Without it, wptr == rptr means both full and empty.

bin→gray
g = b ^ (b >> 1)

gray→bin
b[i] = ^g[AW:i] (XOR from MSB down)

Gray changes one bit per increment. A synchronizer that catches it mid-change returns either the old or new value. Worst case the other side sees a pointer one step stale, which is safe.

4Full & empty (the heart of it)

Empty (rclk): read pointer caught up with the write pointer.

rempty = (rgray_next == rq2_wptr)

Full (wclk): write pointer is exactly one lap ahead. In binary: MSB differs, rest equal. In gray the top two bits must differ, because gray code is reflected around the halfway point.

wfull = (wgray_next == {~wq2_rptr[AW:AW-1], wq2_rptr[AW-2:0]})

ptrbinarygrayptr+4binarygray
0000000↔4100110
1001001↔5101111
2010011↔6110101
3011010↔7111100

depth 4 (AW=2): ptr vs ptr+4 → top 2 gray bits inverted, LSB same. That's "full".

Both flags are pessimistic. They assert immediately (driven by the local pointer) and de-assert 2–3 cycles late (the remote pointer is stale). So the FIFO can look full/empty slightly too long, but it can never overflow or underflow.

5RTL (Cummings style, registered flags)

module afifo #(parameter DW=8, AW=4) (
  input  wclk, wrst_n, winc,  input [DW-1:0] wdata, output reg wfull,
  input  rclk, rrst_n, rinc,  output [DW-1:0] rdata, output reg rempty);

  reg [DW-1:0] mem [0:(1<<AW)-1];
  reg [AW:0] wbin, wptr, wq1_rptr, wq2_rptr;   // wclk
  reg [AW:0] rbin, rptr, rq1_wptr, rq2_wptr;   // rclk

  // ---------------- write side ----------------
  wire [AW:0] wbin_n  = wbin + (winc & ~wfull);
  wire [AW:0] wgray_n = (wbin_n >> 1) ^ wbin_n;
  wire wfull_n = (wgray_n == {~wq2_rptr[AW:AW-1], wq2_rptr[AW-2:0]});

  always @(posedge wclk or negedge wrst_n)
    if (!wrst_n) {wbin, wptr, wfull} <= '0;
    else         {wbin, wptr, wfull} <= {wbin_n, wgray_n, wfull_n};

  always @(posedge wclk)
    if (winc && !wfull) mem[wbin[AW-1:0]] <= wdata;

  always @(posedge wclk or negedge wrst_n)   // rptr → wclk
    if (!wrst_n) {wq2_rptr, wq1_rptr} <= '0;
    else         {wq2_rptr, wq1_rptr} <= {wq1_rptr, rptr};

  // ---------------- read side -----------------
  wire [AW:0] rbin_n  = rbin + (rinc & ~rempty);
  wire [AW:0] rgray_n = (rbin_n >> 1) ^ rbin_n;
  wire rempty_n = (rgray_n == rq2_wptr);

  always @(posedge rclk or negedge rrst_n)
    if (!rrst_n) begin rbin <= '0; rptr <= '0; rempty <= 1'b1; end
    else begin rbin <= rbin_n; rptr <= rgray_n; rempty <= rempty_n; end

  always @(posedge rclk or negedge rrst_n)   // wptr → rclk
    if (!rrst_n) {rq2_wptr, rq1_wptr} <= '0;
    else         {rq2_wptr, rq1_wptr} <= {rq1_wptr, wptr};

  assign rdata = mem[rbin[AW-1:0]];               // FWFT-style read
endmodule

note: wptr/rptr are flops. never feed comb logic into a synchronizer (glitches get sampled)

6Sizing the depth

FIFO only has to absorb the worst burst. Depth = words written during the burst − words read in the same time.

Ex 1: fW = 100 MHz, fR = 50 MHz, burst = 120, no idle cycles
burst time = 120 × 10 ns = 1200 ns
reads in 1200 ns = 1200 / 20 = 60
depth = 120 − 60 = 60 → round up to 64
Ex 2: fW = 80 MHz, 1 write every 2 clk; fR = 50 MHz, 1 read every 3 clk; burst = 120
write rate: 1 per 25 ns → burst time = 3000 ns
read rate: 1 per 60 ns → reads = 3000 / 60 = 50
depth = 120 − 50 = 70 → 128 (or 72 with non-pow-2 tricks)

Trap: "80 writes in any 100 clocks" → worst case is back-to-back 160 writes (last 80 of one window + first 80 of the next). Size for that burst, then add ~2–3 entries for sync latency.

7Interview questions

Q1Why not just synchronize the binary pointer with 2 flops per bit?

ASeveral bits change at once (0111→1000). Each bit resolves independently, so the receiver can see any mix, e.g. 1111. That pointer is wrong by a lot and breaks full/empty.

Q2Why is gray code safe to sync?

AOnly one bit changes per increment. The sampled value is either the old or the new pointer, both of which are real. At worst the flag is computed from a slightly stale pointer, which is conservative.

Q3Why is the pointer AW+1 bits wide?

ATo tell full from empty. Equal pointers with the same wrap bit = empty. Same address but different wrap bit = full.

Q4Why invert the top two bits for full in gray?

AGray code mirrors around the midpoint. ptr and ptr+2^AW differ in the binary MSB only; after the XOR conversion that becomes the top two gray bits differing. (See the table above.)

Q5Can the FIFO overflow because the full flag is late?

ANo. Full asserts from the local write pointer, so it is on time. Only de-assertion is late (waits for the synced read pointer). Late de-assert costs throughput, never data.

Q6wclk is 10× faster than rclk. The gray pointer changes many times between rclk edges. Is that a problem?

ANo. The sync doesn't need every value, just any recent valid one. At the moment rclk samples, only one bit can be in transition. Requirement: bit-to-bit skew on the crossing must be under one destination period, so constrain it with set_max_delay -datapath_only / set_bus_skew, not a blanket false path.

Q7How do you make a non-power-of-2 depth (e.g. 6)?

APlain gray breaks at the wrap (more than 1 bit changes). Options: use an even depth with a symmetric slice of the gray sequence (start at 2^N/2 − D/2 so the wrap is still 1-bit), use a Johnson/one-hot style counter, or send pointers with a req/ack handshake. Most teams just round up to a power of 2.

Q8How do you generate almost-full / almost-empty?

AConvert the synced gray pointer back to binary, subtract (wbin − wq2_rptr_bin), compare to a threshold. Result is still pessimistic, good enough for flow control.

Q9How do you reset an async FIFO?

AEach side gets its own reset: asynchronous assert, synchronous de-assert in its own clock. Reset both sides together. Keep full asserted during write-side reset if the writer might push early. Empty resets to 1.

Q102 flops or 3?

ADriven by MTBF = e^(t_r/τ) / (T0 · f_clk · f_data). At high frequency or advanced nodes, the settling time t_r in one cycle gets too small, so add a third flop. It costs one more cycle of flag latency.

Q11What's the latency from write to not-empty?

A~1 wclk (wptr register) + 2 rclk (sync) + 1 rclk (rempty register) ≈ 3–4 rclk after the write.

Q12Async FIFO vs. handshake (req/ack) synchronizer?

AHandshake: tiny, but one transfer per ~4–6 cycles of round-trip. Async FIFO: full throughput and bursts, but costs RAM and pointer logic. Pick handshake for occasional config/status data, FIFO for streams.

Q13Clocks are the same frequency but unknown phase. Still need it?

AYes, an async FIFO works and is the safe default. A shallow one (4–8 deep) is enough since there's no rate difference to absorb. If the frequencies differ slightly with no flow control, you need an elastic buffer instead.

Q14How would you verify it?

ARandom clock ratios and phase drift, random winc/rinc, scoreboard for order + data. SVA: no write accepted while full, no read while empty, gray pointer changes by exactly 1 bit per cycle. Structural CDC tool (Spyglass / Questa CDC) plus metastability injection in simulation.

Q15Why is rdata read from rbin and not from the synced pointer?

AThe read address is local to rclk, so no CDC. The RAM slot is safe to read because empty guarantees the writer finished that entry at least 2 rclk earlier.

Gotchas that fail silicon

  • Gray pointer driven from comb logic → glitch captured by the sync
  • set_false_path on the crossing → skew unbounded, gray guarantee lost
  • Using the synced pointer as-is for depth math. Convert gray → bin first.
  • Non-power-of-2 depth with plain gray wrap
  • Resetting only one side → phantom full or empty
  • Forgetting sync latency when sizing depth
