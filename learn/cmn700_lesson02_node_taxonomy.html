1Why the cast matters

caveman mode

Roads built (Lesson 1). Now meet the villagers. Three jobs only: ask for data, own the truth + keep cache, be the memory at the end. Everyone else is a doorman or translator. Learn the names — every later lesson uses them.

CMN-700 is CHI-native, so its components map cleanly onto CHI's three agent roles: Request Node (RN), Home Node (HN), Subordinate Node (SN). The trick for an interview is knowing the variants within each family and why they exist.

A request flows RN → HN → (if needed) SN and back. Hold that direction in your head; the variants below just specialise each role.

3Request nodes (RN)

NodeCoherent cache?What it is
RN-FYes (fully)A CPU cluster (via a DSU) or other fully-coherent master. It holds coherent caches, so it issues requests and answers snoops. The "snoop me" node.
RN-INoI/O-coherent bridge for AMBA masters (ACE5-Lite). A proxy with no coherent cache of its own — used for I/O/accelerators reaching into coherent memory.
RN-DNoAn RN-I that also handles DVM (distributed virtual-memory / TLB-maintenance messaging).
caveman mode

RN-F = has own fridge (cache), must share. RN-I = no fridge, just a courier for outside devices. RN-D = same courier, but also carries the "everyone clear your memory-map notes" letters (DVM).

4Home nodes (HN)

The home node is the brain of coherency: it owns an address range, serialises requests to it, and decides who to snoop. Variants differ by what they front and what extra duties they carry.

NodeWhat it does
HN-F (a.k.a. HN-S / HNS in CMN-700 naming)Fully coherent home node. Holds an SLC slice + snoop filter; is the Point of Coherency/Serialization for its addresses. This is the one we open up in Lesson 4.
HN-II/O home node — a proxy for AMBA slave subsystems; converts CHI to ACE5-Lite. No caching, generates no snoops.
HN-DHN-I plus the DVM node, the DTC (trace controller) and the configuration (CFG) node. Every CMN-700 must contain one HN-D — it's the config/boot anchor and default route target.
HN-PI/O home node with PCIe optimisation — adds a dedicated tracker for PCIe peer-to-peer traffic; connects PCIe subordinates.

Interview-ready one-liner: "HN-F is the coherent home with cache + snoop filter; HN-I/HN-P front non-coherent or PCIe I/O; HN-D is the mandatory one that also carries config, DVM and trace control."

5Subordinate nodes (SN)

NodeWhat it is
SN-FFully-coherent subordinate = the memory-controller interface (DMC for DDR5 / HBM). Where reads and writes finally land. CMN-700 supports up to 40 of these (80 dual-channel).
SBSXA CHI → ACE5-Lite bridge that behaves like an SN-F, used to attach ACE5-Lite slaves such as the CoreLink DMC-400 controller.

You can mix memory types on one mesh — e.g. HBM3 SN-Fs near compute for bandwidth and DDR5 SN-Fs on the edge for capacity.

6Glue & bridges (name-drops that score points)

CAL — Component Aggregation Layer

Lets multiple devices share one XP device port — the way you fit more components than ports onto a modest mesh.

CFG — Configuration node

Co-located with the HN-D; owns the config/control/monitor register space. Software discovers the mesh through it.

ADB — AMBA Domain Bridge

Crosses clock and power/voltage domains between two AMBA (AXI/ACE5-Lite) interfaces.

CDB — CHI Domain Bridge

Same idea for two CHI interfaces in different clock/power domains.

(The CCG multichip gateway is also "glue", but it earns its own lesson — L8.)

7Putting it on the mesh

In large server parts the mesh is built by replicating a tile: one XP carrying two CPU clusters and an HN-F slice, repeated across the die, with memory and I/O coming out of the edges. Here's a slice of that pattern:

A replicated compute tile + edge memory/IO
   edge: memory + IO                 compute interior
   [SN-F]        [SN-F]        [HN-F]        [HN-D]  ← mandatory
      |            |            |            |
   (0,1)━━━━(1,1)━━━━(2,1)━━━━(3,1)
      ┃            ┃            ┃            ┃
   (0,0)━━━━(1,0)━━━━(2,0)━━━━(3,0)
      |            |            |            |
   [RN-F]        [RN-F]        [RN-I]        [RN-D]
   CPU x2       CPU x2       PCIe/IO      IO + DVM

Notice the HN-D sits in the interior with the other home nodes, the SN-F memory controllers hug the edge near the PHYs, and I/O enters via RN-I / RN-D. The exact placement is a performance lever (Lesson 7), but the roles are what you must name instantly.

9Interview Q&A

Name the node families and what each does.
Request nodes (RN) start transactions; Home nodes (HN) own address ranges and coherency; Subordinate nodes (SN) are the endpoints (memory/AMBA slaves). Requests flow RN → HN → SN and back.
RN-F vs RN-I vs RN-D?
RN-F: fully coherent, has caches (CPUs). RN-I: I/O-coherent bridge for AMBA masters, no coherent cache (a proxy for I/O/accelerators). RN-D: an RN-I that also handles DVM (TLB-maintenance) messages.
What's inside an HN-D and why must there be one?
HN-D = HN-I plus the DVM node, the DTC (trace controller) and the configuration (CFG) node. It's the boot/config anchor and the default route target before the SAM is programmed, so every mesh needs exactly one.
HN-F vs HN-I?
HN-F is fully coherent: it holds an SLC slice and snoop filter and is the Point of Coherency. HN-I is an I/O home node — a proxy that converts CHI to ACE5-Lite for non-coherent slaves, with no caching and no snoops generated.
What is the CAL and when do you need it?
The Component Aggregation Layer lets several devices share one XP device port — useful when you have more components than ports and want to keep the mesh small (which lowers hop count/latency).

10Recap & key terms

  • Three families: RN (request), HN (home), SN (subordinate).
  • RN-F coherent w/ caches · RN-I I/O proxy · RN-D = RN-I + DVM.
  • HN-F (SLC+SF) · HN-I (CHI→ACE-Lite) · HN-D mandatory (CFG+DVM+DTC) · HN-P (PCIe).
  • SN-F = memory controller · SBSX bridges to ACE5-Lite slaves.
  • Glue: CAL (port sharing), ADB/CDB (domain crossing), CFG (config/discovery).
