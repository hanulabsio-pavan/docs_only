Fundamentals & History of Power ISA

Where Power came from, why it forked into three architectures and merged back into one, and what actually changed when IBM open-sourced it in 2019.

By the end of this lesson you can

  • Explain what an ISA specifies — and what it deliberately does not.
  • Trace the lineage IBM 801 → POWER → PowerPC → Book E → unified Power ISA.
  • Name the major spec versions and the headline feature each one added.
  • State precisely what IBM opened in August 2019, and how that differs from Arm and RISC-V.
  • Navigate the spec: which Book answers which kind of question.

1What an ISA actually is

caveman mode

ISA = contract. Software say what it want. Hardware promise what it do. Contract on paper, not in silicon. Many different chips, same contract → same program run everywhere.

An Instruction Set Architecture is the boundary between software and hardware — the part of a processor that a compiler, an OS kernel or an assembly programmer can actually see. Power ISA is a specification document, not a chip. IBM's POWER10, a Microwatt FPGA softcore and a Libre-SOC design can all be radically different silicon while implementing the same contract.

The ISA does specify

Instruction encodings and semantics · architected registers · addressing modes · memory ordering rules · exception/interrupt behaviour · privilege levels · the virtual memory model.

The ISA does not specify

Pipeline depth · issue width · cache sizes and hierarchy · branch predictors · clock speed · physical bus protocols · how many cycles anything takes. Those are microarchitecture.

That separation is exactly why an architecture can survive 30+ years. The Power contract written for a 1990 RS/6000 still describes, in its lineage, the instructions a 2024 POWER10 executes.

2RISC roots: IBM's 801 project

Power did not start as a product. It started as a research argument. In the mid-1970s at IBM's Watson Research Center, John Cocke's team built the IBM 801 (named after the building) on a heretical premise: compilers only ever use a small fraction of a CISC machine's elaborate instructions, so a machine with fewer, simpler, uniformly-encoded instructions could be clocked faster and pipelined harder — and a good compiler would make up the difference.

That premise gave the whole RISC family its DNA, and Power inherits it directly:

  • Load/store architecture — only explicit load and store instructions touch memory; arithmetic works register-to-register.
  • Fixed-width instructions — every instruction is 32 bits, so the decoder always knows where the next one begins.
  • A large register file — 32 general-purpose registers, so intermediate values stay out of memory.
  • Compiler as first-class citizen — the hardware exposes a regular machine and lets the compiler schedule it.
caveman mode

Old CISC machine like Swiss army knife with 400 blades. Cocke say: you only use 6 blades. Give me 6 sharp blades, I cut faster. Compiler smart enough to do rest.

The 801 shipped as a product only indirectly (as an I/O controller and in the ROMP chip behind the IBM RT PC), but its architecture became the seed of POWER.

4The great fork — and the merge back

In 2006, Power ISA v2.03 folded PowerPC v2.02 and the Book E extension into a single document. The embedded and server worlds kept their differences, but they were now categories inside one specification rather than separate architectures — which is why modern Book III splits into Book III-S (server) and Book III-E (embedded).

caveman mode

One tribe split in three: big-server tribe, desktop tribe, tiny-embedded tribe. Fight over how memory-map work. 2006 they sit down, write one book, put tribe differences in separate chapters. Peace.

6August 2019: the open-sourcing

At the OpenPOWER Summit in San Diego (August 2019) IBM announced that the Power ISA specification itself would be released under an open, royalty-free licence, with a grant of the patent rights needed to implement it. Alongside the ISA, IBM opened reference hardware — including softcore designs (the A2I and A2O cores) — and moved the OpenPOWER Foundation under the Linux Foundation.

Royalty-free

Implement Power ISA in your own silicon or FPGA without paying IBM a per-unit fee or a licence fee.

Patent grant

Rights to the IBM patents needed to build a compliant implementation, which is what makes "free spec" actually usable.

Neutral governance

OpenPOWER Foundation under the Linux Foundation; the ISA is evolved by a Technical Working Group with a public RFC process.

Practically, this is why projects like Microwatt (a small Power ISA core in VHDL, open-sourced by IBM), Libre-SOC (an open GPU/CPU hybrid targeting Power) and various FPGA softcores can exist without a commercial architecture licence.

caveman mode

Before: want build Power chip? Talk to IBM lawyer, pay. After 2019: take spec, build chip, owe nothing. IBM keep making own chips, but now anyone can join. Same move Sun once did, RISC-V born doing.

7How open is "open"? Power vs Arm vs RISC-V

"Open source" means different things for an ISA than for software. The spec being free does not make any particular implementation free — POWER10 is still proprietary IBM silicon.

8The spec's shape: Books I, II and III

The Power ISA document is deliberately layered by who needs to read it. Click a book below.

The layering matters in practice: a compiler back-end author lives in Book I, a lock-free-data-structure or driver author needs Book II, and only a kernel/hypervisor engineer opens Book III.

caveman mode

Book I = what instructions do. Book II = rules when many CPUs share memory. Book III = secret king-mode stuff for OS. Read only book you need.

9Compliancy subsets — you don't have to build all of it

Before v3.0, "Power compliant" implicitly meant "implements essentially everything". That's a brutal bar for a small embedded core or an FPGA softcore. Version 3.0 replaced it with a Base architecture plus at least one compliancy subset, with optional features layered on top.

LevelRoughly meansTypical target
BaseThe mandatory core every compliant implementation must have.Everything
SFS — Scalar Fixed-point SubsetInteger scalar core, no floating-point required.Tiny embedded / softcore
SFFS — Scalar Fixed-point + Floating-point SubsetAdds scalar FP; still no vector requirement.Microwatt-class cores, MCUs
LCS — Linux Compliancy SubsetEnough of the architecture to boot and run mainstream Linux.Open Linux-capable cores
ACS — AIX Compliancy SubsetThe full server-class surface AIX depends on.IBM POWER servers

This is the mechanism that makes the open ISA genuinely usable: you can build a legal, compliant Power core that fits in a modest FPGA by targeting SFFS, without pretending to implement transactional memory or a radix MMU.

10Where Power ISA actually runs

Enterprise servers

IBM Power Systems (POWER9, POWER10) running AIX, IBM i and Linux — databases, SAP HANA, and mainframe-adjacent RAS-heavy workloads.

Supercomputing

Summit (Oak Ridge) and Sierra (Livermore) — POWER9 CPUs paired with NVIDIA Volta GPUs over NVLink; both were #1/#2 on the TOP500 in 2018–19.

Open cores

Microwatt (VHDL, fits an FPGA), A2I / A2O (IBM's opened cores), Libre-SOC, plus Chiselwatt and other community cores.

Embedded & legacy

NXP/Freescale e-series in automotive and networking, plus a long tail of consoles (Xbox 360, PS3 PPE, Wii) and Macs pre-2006.

Note the common mix-up: the Frontier and Aurora exascale machines are not Power — they use AMD and Intel CPUs respectively. Summit and Sierra are the POWER9 flagships.

12Interview Q&A

In one minute: what is Power ISA and where did it come from?
Power ISA is an open, royalty-free 64-bit RISC instruction set architecture stewarded by the OpenPOWER Foundation under the Linux Foundation, and led by IBM. It descends from IBM's 801 research RISC of the late 1970s, which became POWER in the RS/6000 (1990), then PowerPC via the Apple–IBM–Motorola alliance (1991), which itself branched into server POWER, desktop PowerPC and embedded Book E. Those branches were reunified as Power ISA v2.03 in 2006, and IBM open-sourced the specification in August 2019.
What's the difference between POWER, PowerPC and Power ISA?
POWER was IBM's original server architecture and is now the brand for the processors. PowerPC was the AIM-alliance derivative aimed at desktop and embedded, and it added things like AltiVec. Power ISA (from v2.03, 2006) is the single unified specification that both lineages plus Book E embedded now conform to. Modern usage: "Power ISA" = the architecture spec, "POWER10" = an IBM implementation of it.
What does "IBM open-sourced Power" actually mean — can I build a Power chip?
Yes. The specification is published under an open licence, is royalty-free, and comes with a grant of the IBM patents needed to implement it, so you can design and ship a Power ISA core without an architecture licence or per-unit fee. What's not open is IBM's own implementations — POWER9/POWER10 RTL is proprietary. IBM did separately open-source reference cores such as A2I, A2O and Microwatt.
How is Power's openness different from RISC-V's?
RISC-V was designed open from day one with a deliberately small base ISA and reserved custom opcode space, governed by a vendor-neutral body. Power was opened in 2019 after 30 years as a commercial server architecture, so you inherit a mature, high-end, server-hardened design — including things like a strong virtualisation and RAS story — but the governance is still IBM-led and the encoding space is largely spoken for. Power is "mature architecture made free"; RISC-V is "free architecture growing up".
Explain the Books structure.
Book I is the user-level instruction set — the instructions and registers an application programmer or compiler sees. Book II is the virtual environment: the storage model, memory ordering, atomics and cache-management instructions available to applications. Book III is the operating environment — privileged state, interrupts, address translation — and splits into III-S for server and III-E for embedded, which is the legacy of the Book E merge.
Why did v3.0 introduce compliancy subsets?
To make the architecture implementable at smaller scale. Requiring every implementation to support the entire spec excluded small embedded cores and FPGA softcores. Since v3.0, a design implements the Base architecture plus at least one subset — SFS, SFFS, LCS or ACS — and may add optional features. That's what lets a core like Microwatt be legitimately Power-compliant.
Name three things v3.1 added and why they matter.
(1) Prefixed instructions — an 8-byte encoding formed from a prefix word plus a suffix word, which breaks the 32-bit limit and enables 34-bit displacements. (2) PC-relative addressing, which makes position-independent code much cheaper. (3) MMA, the Matrix-Multiply Assist facility with 512-bit accumulator registers, targeting AI/ML inference throughput on POWER10.

13Recap & key terms

  • An ISA is the software-visible contract; microarchitecture is everything the ISA leaves free.
  • Lineage: 801 → POWER (1990) → PowerPC (1993) → three-way fork → unified Power ISA v2.03 (2006).
  • Milestones: 2.06 VSX · 2.07 TM · 3.0 radix MMU + subsets · 3.1 prefixed instrs + MMA.
  • Aug 2019: spec open-sourced royalty-free with patent grant; OpenPOWER moved under the Linux Foundation.
  • Spec layering: Book I user instructions · Book II storage model · Book III-S/E privileged.
  • Compliance = Base + at least one subset (SFS / SFFS / LCS / ACS) + optional features.
