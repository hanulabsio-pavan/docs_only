Node Type Definitions

CHI defines three node families. Every silicon block in the SoC — CPU core, GPU, DMA engine, memory controller, peripheral — is classified as one of these. The subtype determines which channels it uses, whether it can cache, and what coherency obligations it carries.

RN — Requester Node Initiates transactions · Issues REQ flits
RN-F
Requester Node · Full
Fully Coherent Cache Agent

The most capable node. CPU cores and GPU clusters. Maintains a fully coherent cache and participates in all coherency protocols. Can hold lines in any cache state (UC, UD, SC, SD, I). Receives snoops from HN-F.

Has cacheYes — fully coherent
Receives snoopsYes — SNP channel
Cache statesUC, UD, SC, SD, I
Channels usedREQ, RSP, DAT, SNP
Typical devicesCPU cores, GPU clusters
LPID trackingYes — exclusives
RN-D
Requester Node · DMA
DMA / Non-Caching Requester

DMA engines and similar masters that issue memory transactions but hold no cache. Issues REQ flits for data movement but never caches the data. No snoops are ever directed at RN-D nodes.

Has cacheNo
Receives snoopsNo
Cache statesN/A
Channels usedREQ, RSP, DAT
Typical devicesDMA engines, ETH DMA
LPID trackingNo
RN-I
Requester Node · I/O
I/O Non-Coherent Requester

PCIe controllers, USB, display engines. Issues memory-mapped I/O transactions. Non-cacheable. Routes transactions through an HN-I. Never participates in cache coherency protocol. Simplest requester type.

Has cacheNo
Receives snoopsNo
Cache statesN/A
Channels usedREQ, RSP, DAT
Typical devicesPCIe, USB, display
Routes viaHN-I only
HN — Home Node Coordinates coherency · Owns address ranges
HN-F
Home Node · Full
Coherent Home Node

The brain of CHI coherency. Owns a range of physical addresses. Maintains a Snoop Filter tracking which RN-Fs hold which lines. Issues snoops, coordinates writebacks, and serialises conflicting requests to the same address.

Snoop FilterYes — per cache line
Issues snoopsYes — to RN-Fs
Address ownershipCoherent DRAM range
Channels usedREQ, RSP, DAT, SNP
Typical implCMN-700 crosspoint
Talks toRN-F, RN-D, SN-F
HN-I
Home Node · I/O
Non-Coherent Home Node

Manages non-coherent address space — device registers, ROM, peripheral MMIO. No snoop filter, no coherency tracking. Simply routes non-coherent REQ from RN-I/RN-D to the appropriate SN-I. Much simpler than HN-F.

Snoop FilterNo
Issues snoopsNo
Address ownershipI/O, MMIO, ROM
Channels usedREQ, RSP, DAT
Typical implPeripheral bridge
Talks toRN-I, RN-D, SN-I
SN — Slave Node Responds to requests · Holds data
SN-F
Slave Node · Full
Memory Controller Slave

DDR5, LPDDR5, HBM memory controllers. Receives ReadNoSnp and WriteNoSnp from HN-F. Responds with data on the DAT channel. Only communicates with HN-F — never with RN-F directly. No coherency logic needed.

Coherency logicNone
Talks toHN-F only
Channels usedREQ, RSP, DAT
Typical devicesDDR5, LPDDR5, HBM
Issues snoopsNo
Receives snoopsNo
SN-I
Slave Node · I/O
Peripheral / I/O Slave

ROM, flash, peripheral register banks, on-chip SRAM. Responds to non-coherent reads and writes routed via HN-I. The simplest node type — just returns data or accepts writes with no protocol complexity.

Coherency logicNone
Talks toHN-I only
Channels usedREQ, RSP, DAT
Typical devicesROM, SRAM, GPIO
Issues snoopsNo
Receives snoopsNo

System Topology

CHI is designed for ring and mesh Network-on-Chip topologies where multiple nodes communicate via routed flits. Each diagram below shows a different topology variant.

Diagram 1 — Simple Three-Node Chain
The fundamental RN-F → HN-F → SN-F relationship for a single coherent address range.
Diagram 2 — 4-CPU Coherent Cluster with Snoop
One HN-F coordinating four RN-F nodes. Shows snoop broadcast path when CPU0 requests a line held by CPU2.
Diagram 3 — Full SoC Mesh Topology (4×3 Grid)
A realistic large SoC mesh: 8 CPU RN-F nodes, 3 HN-F nodes (each owning a DRAM range), 1 HN-I node (peripherals), 3 SN-F (DDR), 1 SN-I (I/O), 1 RN-I (PCIe). Each intersection is a router node.

Address Space Partitioning

Every physical address maps to exactly one Home Node. This mapping is fixed at chip design time and encoded in every node's routing table. The TgtID in every REQ flit is derived from this map.

Address Range Size Home Node Slave Node Type Description Visual
0x0000_0000 – 0x1FFF_FFFF 512 MB HN-F #0 SN-F DDR0 Coherent Kernel + user heap, fully coherent DRAM
0x2000_0000 – 0x3FFF_FFFF 512 MB HN-F #1 SN-F DDR1 Coherent User space, GPU buffers, cacheable
0x4000_0000 – 0x5FFF_FFFF 512 MB HN-F #2 SN-F DDR2 Coherent Framebuffer + shared memory pools
0x6000_0000 – 0x7FFF_FFFF 512 MB HN-F #2 SN-F DDR2 Non-cacheable DMA bounce buffers, device-mapped mem
0x8000_0000 – 0xBFFF_FFFF 1 GB HN-I SN-I MMIO Device / MMIO Peripheral register banks, GIC, timers
0xC000_0000 – 0xCFFF_FFFF 256 MB HN-I SN-I ROM ROM / Static Boot ROM, on-chip SRAM, OTP
0xD000_0000 – 0xFFFF_FFFF 768 MB HN-I SN-I PCIe PCIe / RN-I PCIe config space, BAR regions
