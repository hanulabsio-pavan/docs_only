CHI Cache States & Transitions

The vocabulary every coherency answer rests on: two axes, five states, who owes the writeback, and why the snoop filter is allowed to be wrong.

Purpose of this appendix

  • Give the CHI cache-state vocabulary that every coherency answer implicitly rests on.
  • Make explicit who owes a writeback in each state, and which transitions can happen silently.
  • Clear up the most common confusion: a cache's line state is not the same as what the snoop filter records.

This was delivered as an appendix rather than a full lesson because you have already studied CHI directly. Use the self-test in §1 — if it is comfortable, treat this as reference only.

1Self-test first

Before read: try answer these three from memory. If easy, this page just reference card. If hard, read properly — every DMT/DCT/snoop answer sit on top of this.

  • Name the CHI cache states and what each pair of letters means.
  • In which states may a cache drop a line without telling anyone?
  • In which states does the cache owe the writeback — and can a shared line owe one?

If the third question gave you pause, that is the one worth reading for. It is also the one that separates a CHI answer from a textbook MESI answer.

2Two independent axes

CHI state names are built from two orthogonal properties. Once you see them as two axes rather than a list of five acronyms, the set becomes obvious rather than memorised.

Unique vs Shared

Unique — this is the only cached copy, so the cache may write to the line without asking anyone. Shared — other caches may also hold it, so a write needs permission first.

Clean vs Dirty

Clean — this cache does not owe a writeback. Dirty — this cache holds modified data and is responsible for getting it written back.

The state set as a 2x2, plus Invalid
                 CLEAN              DIRTY
              (owe nothing)     (owe writeback)

  UNIQUE          UC                 UD
  (only copy)  UniqueClean        UniqueDirty

  SHARED          SC                 SD
  (may be others) SharedClean       SharedDirty

  plus  I = Invalid  (not present)

There are also partial and empty variants of the unique states, used when a cache has permission for a line but does not hold all of its data as valid — useful for full-line writes where fetching the old data would be wasted work. Treat those as an optimisation detail; confirm exact naming and rules in the CHI specification.

3The state set in words

StateOnly copy?Owes writeback?Meaning in practice
I — Invalid—NoNot present. Any access misses.
SC — SharedCleanNoNoRead-only working copy. Others may have it too. Cheapest state to hold and to drop.
UC — UniqueCleanYesNoSole copy, unmodified. Can be written locally without asking — which turns it into UD.
SD — SharedDirtyNoYesThe interesting one. Others may hold read-only copies, but this cache owns the writeback duty. Equivalent in spirit to the Owned state in MOESI.
UD — UniqueDirtyYesYesSole copy, modified. Classic "modified" state.

The existence of SD is what makes CHI more than MESI: dirty data can be shared without immediately writing back, with one designated holder responsible. That enables cache-to-cache transfer of dirty data (Lesson 6's DCT) without a memory round trip.

4Who owes the writeback

This is the single most useful thing to have straight, because it determines what must happen on eviction and on snoop.

  • Clean states (SC, UC): nobody is waiting on this cache. The line can be discarded.
  • Dirty states (SD, UD): this cache holds the only up-to-date data. It cannot simply drop the line — it must either write it back or transfer the responsibility to another agent (for example by supplying the data in a snoop response, passing dirty ownership along).
  • Shared and dirty simultaneously is legal and important: SD means read-only copies may exist elsewhere while this cache carries the writeback duty.
Eviction depends entirely on the clean/dirty axis
   evict a line in SC or UC   ->  may just drop it        (silent eviction)
   evict a line in SD or UD   ->  must copy back, or hand
                                    responsibility to someone else

5Silent transitions

A silent transition is one a cache may make without notifying the home node. They exist because notifying on every state change would flood the fabric with messages that carry no useful information.

TransitionSilent?Why
SC → IYesDropping a clean shared copy loses nothing and obliges nobody.
UC → IYesDropping a clean sole copy still loses no data.
UC → UDYesThe cache already has exclusive permission, so writing locally needs no further permission.
UD or SD → INoWould destroy the only up-to-date copy. Requires a copyback or transfer of responsibility.
SC → UC/UDNoGaining exclusivity requires invalidating other copies — that needs the home node.

The pattern: giving up rights on clean data is silent; acquiring rights, or discarding dirty data, is not. That one sentence covers most cases.

6Cache state is not snoop-filter state

caveman mode

Cache quietly throw line away (silent eviction). Home node's list still say "that cache has it." So home send snoop, cache reply "not here." Not a bug. List is allowed to be pessimistic — never miss a real sharer, but may name a stale one.

Because clean lines can be silently evicted, the snoop filter's record and the cache's actual state can diverge. The snoop filter is permitted to be conservative: it must never fail to list an agent that really holds a line, but it may list an agent that has since dropped it.

Legal divergence between SF record and cache reality
   RN-F holds line in SC        SF records: RN-F is a sharer
        |
        ▼ silent eviction (allowed)
   RN-F now I                     SF still records: RN-F is a sharer
        |
        ▼ later request arrives at home
   home sends SNP to RN-F  ->  RN-F responds "I do not have it"
        correct behaviour, not an error; SF updates and moves on

Two consequences worth being able to state:

  • A snoop returning "not present" is normal traffic, not a fault.
  • This is part of why snoop-filter sizing (Lesson 4) is about tracking capacity rather than perfect accuracy — and why an undersized SF causes real harm through forced back-invalidation, while a merely stale SF entry only costs one wasted snoop.

9Interview Q&A

Name the CHI cache states and what the letters mean.
Invalid, plus four states built from two axes. Unique versus Shared says whether this is the only cached copy, which determines whether a write needs permission. Clean versus Dirty says whether this cache owes a writeback. That gives SharedClean, UniqueClean, SharedDirty and UniqueDirty. There are also partial and empty variants of the unique states for cases where a cache has permission without holding all the data valid, which helps full-line writes avoid fetching data that is about to be overwritten.
How does CHI differ from textbook MESI?
The key addition is SharedDirty. In MESI, dirty implies exclusive, so sharing dirty data requires writing back first. CHI allows a line to be shared read-only by several caches while one designated holder retains the writeback responsibility — conceptually the Owned state in MOESI. That is what makes cache-to-cache transfer of dirty data possible without a memory round trip, which is precisely what Direct Cache Transfer exploits.
Which transitions can happen silently and why?
Giving up rights on clean data is silent: SharedClean to Invalid, UniqueClean to Invalid. So is UniqueClean to UniqueDirty, because the cache already holds exclusive permission and needs no further authorisation to write. What is not silent is discarding dirty data, since that would destroy the only up-to-date copy, and acquiring rights such as going from shared to unique, since that requires invalidating other copies through the home node. The general rule: relinquishing clean rights is silent, acquiring rights or dropping dirty data is not.
Why can a cache's state disagree with the snoop filter?
Because clean lines may be evicted silently, so the filter can still list an agent that has already dropped the line. The filter is deliberately conservative: it must never omit an agent that genuinely holds a line, but it may name a stale one. The consequence is that a snoop returning "not present" is normal, not an error. It also clarifies the sizing discussion — a stale entry costs one wasted snoop, whereas an undersized filter forces back-invalidation of lines still in active use, which is far more damaging.
Who is responsible for writing a line back?
Whichever cache holds it in a dirty state, SharedDirty or UniqueDirty. On eviction that cache must either copy the line back or transfer the responsibility to another agent, for example by supplying the data in a snoop response so dirty ownership moves with it. Clean states carry no such duty and can simply be dropped.

10Recap & key terms

  • Two axes: Unique/Shared (may I write without asking?) and Clean/Dirty (do I owe a writeback?).
  • States: I, SC, UC, SD, UD, plus partial/empty unique variants.
  • SD is the CHI-specific one — shared read-only elsewhere, writeback still owed here. Enables DCT of dirty data.
  • Silent: relinquishing clean rights, and UC → UD. Not silent: dropping dirty data, or acquiring rights.
  • Snoop-filter records may be conservatively stale — a "not present" snoop response is normal.
