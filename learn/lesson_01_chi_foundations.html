CHI Foundations & the Link Interface

Before reading any router or node logic, you need to know what a flit is, what the four CHI channels do, and how two nodes talk over a link. Everything else in rtl/interconnect/ builds on these three concepts.

1The big picture

CHI (Coherent Hub Interface) is the protocol that lets CPU clusters, memory controllers, and IO agents share data coherently. In hanuma, every agent is one of three kinds — RN (request), HN (home), SN (slave) — and they all communicate over four channels. Click a channel name to highlight its path.

2The four channels

Each CHI channel carries a different kind of message and has its own flit structure, opcode set, and virtual-channel assignment inside the router. The widths below are taken straight from chi_pkg.sv.

CHI_CH_REQ  ·  VC0
REQ — Requests

Read, write, atomic, and DVM transactions issued by a Request Node toward a Home Node. This is the channel that starts every transaction.

Flit width: 88 bits Direction: RN → HN Opcodes: ~35
CHI_CH_RSP  ·  VC1
RSP — Responses

Completions, acknowledgements, retries, and credit grants. Carries no data — just protocol-level status (Comp, DBIDResp, RetryAck, PCrdGrant).

Flit width: 46 bits Direction: bidirectional Opcodes: ~20
CHI_CH_SNP  ·  VC0
SNP — Snoops

Coherency probes from a Home Node to Request Nodes. Asks an RN to invalidate or share its cached copy of a line so the requester can be served.

Flit width: 84 bits Direction: HN → RN Opcodes: ~20
CHI_CH_DAT  ·  VC2
DAT — Data

Cache-line payload — read returns, writeback data, snoop responses with data. The widest channel by far (one 256-bit cache line per flit).

Flit width: 368 bits Direction: bidirectional Opcodes: ~12

4The three node families

Every CHI participant is one of these. The role determines which channels it drives and which it receives — and which file in rtl/interconnect/chi/ implements it.

RN-F · RN-I · RN-D

Request Node

The initiator. CPUs, DMA engines, accelerators.

  • Sends: REQ, RSP, DAT
  • Receives: SNP, RSP, DAT
  • RTL: chi_rn.sv
  • F = Fully Coherent (with cache)
  • I = IO Coherent (no cache)
HN-F · HN-I

Home Node

The arbiter of coherency. Owns the directory and the last-level cache.

  • Sends: RSP, SNP, DAT
  • Receives: REQ, RSP, DAT
  • RTL: chi_hn.sv
  • F = LLC + Directory
  • I = MMIO regions (no caching)
SN-F · SN-I

Slave Node

The endpoint. Memory controllers and IO peripherals.

  • Sends: RSP, DAT
  • Receives: REQ, DAT
  • RTL: chi_sn.sv
  • F = DDR / fully coherent memory
  • I = peripherals

5The link-layer handshake

Every channel uses the same three signals to move a flit across a link: pend announces the sender's intent one cycle early, valid carries the actual flit, and lcrdv returns a credit so the sender knows the receiver had room. Press play to step through.

Click Play to walk through a single flit transfer. At t=0 the link is idle; the sender holds a credit from link training. Watch how pend rises one cycle before valid — this gives the receiver a cycle of head-start to prepare buffer write enables.

7Check yourself

If you can answer these without re-reading, you're ready for Lesson 2 (leaf primitives — flit buffers, credit managers, FIFOs).

Q1. A CPU cluster sends a ReadShared request and a memory controller eventually responds with CompData. Which two channels carried these flits, and which VCs did they use?
The ReadShared request is a REQ flit on VC0; the CompData reply is a DAT flit on VC2. Both are defined in chi_pkg.sv; the VC mapping is in noc_pkg.sv :: channel_to_vc().
Q2. Why is REQ 88 bits but DAT 368 bits? What does that imply for buffer sizing inside the router?
REQ carries protocol metadata only — addr, opcode, IDs. DAT carries a full 256-bit cache line plus byte-enables and tags. Since router input/output buffers must size to the widest flit (NOC_FLIT_WIDTH = CHI_DAT_FLIT_WIDTH in noc_pkg.sv:51), every per-VC FIFO is 368 bits × 8 deep regardless of which channel actually uses it.
Q3. Why does txreqflitpend rise one cycle before txreqflitv?
The pend signal is an early hint that lets the receiver decode its buffer write enable in time for the flit to land in the right VC FIFO without a single-cycle stall. Without pend, the receiver would have to gate every incoming flit on a combinational decode of valid + channel, which is a timing-closure hazard at 1 GHz.
Q4. Where in the interface do you find the modport an RTL designer uses on the requester side of a link?
rtl/interfaces/chi_link_if.sv, line 106 — the requester modport. The mirror is completer on line 125; a third monitor modport (line 144) gives read-only access for assertions and scoreboards.
