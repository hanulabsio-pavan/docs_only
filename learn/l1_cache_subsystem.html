§1 Executive Summary

The L1 Cache Subsystem provides the first level of private caching for a single RV64GC core: an L1I feeding the fetch unit and an L1D serving the load/store unit. The L1 never touches CHI directly — all coherency flows through the L2, which is the cluster's sole CHI RN-F agent.

1.3 Design Philosophy

⚡ Small, Fast, Private

1–2 cycle hit at 2 GHz. Push all coherency complexity down to L2.

🔌 Non-Blocking

8 L1D MSHRs + 2–4 L1I MSHRs. Independent banks keep flowing when one misses.

🗺️ VIPT, Alias-Free

Index within page offset ⇒ no virtual aliasing. Physical tags ⇒ no context-switch flush.

📐 Scalable

Every structural parameter is an RTL parameter. Same block from FPGA prototype to multicore ASIC.

↩️ Write-Back / Write-Allocate

Minimize downstream write traffic to L2 / CHI / DDR5. Coalesces stores in the write buffer.

🔄 CHI-Free Interface

L1 sees only simple request/refill/invalidate contract to L2. No flits, TxnIDs, or credits.

§3 Functional Requirements

L1I — Instruction Cache

FunctionRequirement
Instruction fetch≥ 32 B/cycle; support unaligned RVC fetch across line boundaries
Cache-line fill64 B from L2 on miss, critical-word-first, early restart
Miss handlingNon-blocking: ≥ 2 outstanding I-fetch misses
Branch-target fetchAccept fetch redirects mid-flight; squash without corrupting MSHR state
I-cache coherenceNot snooped; coherence via FENCE.I (SW-managed, RISC-V)
Read-onlyNo store path; no dirty state; eviction is silent drop

L1D — Data Cache

FunctionRequirement
Load support1–2 loads/cycle; store-to-load forwarding from write buffer
Store supportWrite-back, write-allocate; stores retire into write buffer
Atomic supportRV64A: LR/SC (per-line reservation) + AMO* (RMW with line ownership)
Cache-line fill64 B from L2, critical-word-first, write-allocate on store miss
EvictionWrite-back dirty victims to L2; clean victims dropped
Fence orderingHonour FENCE, FENCE.I, SFENCE.VMA; drain write buffer

PA[11:6] INDEX 6 bits → 64 sets

§8 VIPT Organization

SchemeIndexTagProsCons
VIVTvirtualvirtualFastest (no TLB on hit)Aliasing + homonyms; flush on context switch; bad for Linux
PIPTphysicalphysicalNo aliasing; simple coherenceTLB on critical path before index → slower
VIPT ✓virtual (page-offset bits)physicalTLB lookup overlaps array read; alias-free when index ⊆ page offsetConstrains size×ways per way ≤ page size
VIPT constraint: index_bits + offset_bits ≤ 12 (4 KB page offset). For 64 B lines (6 offset bits): 6 index bits = 64 sets per way group.
32 KB / 8-way / 64 B = 64 sets → exactly alias-free. Growing capacity is done by adding ways, not sets.

§6 RV64GC Integration

⚠️ The RV64GC core does not exist yet. This section specifies the expected interaction surface so the L1 is drop-in ready for any conventional in-order or lightly-OoO Linux-capable core.

RV64A Atomic Instructions

OpL1D Handling
LR.W/DLoad + set a per-hart reservation (line address + valid)
SC.W/DSucceeds only if reservation still valid (no intervening write/back-invalidate); else fail
AMO*Acquire line in writable/owned state via L2 (write-allocate if miss), perform RMW at L1D, mark dirty
🔐 A back-invalidation from L2 (remote write) clears any matching reservation, giving correct LR/SC semantics across cores once multicore coherency is active.

§7 Address Translation — Sv39

Sv39 Virtual Address Layout

VA[38:30] VPN[2] 9 bits
VA[29:21] VPN[1] 9 bits
VA[20:12] VPN[0] 9 bits
VA[11:0] page offset 12 bits (4 KB)

39-bit VA → PA up to 44 bits. VA[11:0] is translation-invariant (page offset).

TLB InteractionDetail
Index sourceVA[11:6] — within page offset, no TLB needed for indexing → VIPT overlap
Tag sourcePA[43:12] from TLB — compared physically after translation completes
Page-table walkUp to 3 dependent loads (Sv39 levels) through L1D/L2 cacheable path. L1D treats PTW as ordinary cacheable loads.
SFENCE.VMAInvalidates TLB entries by VA/ASID. Physical tags mean caches need not be flushed — only TLBs.

§11 L1–L2 Interface

L1 attaches to the unified L2's upstream port (documented as L1-agnostic in docs/architecture/L2/l2_cache_controller.md §2.1, §7). The L2 owns the clock-domain crossing (2 GHz core → 1 GHz NoC) and is the coherence point.

§12 Coherency Considerations

⚠️ The L2 is the coherency point; the L1 caches are private. The L1 is not a CHI agent, is not directly snooped from the NoC, and holds no MOESI bus state.

12.3 Instruction/Data Coherence

⚠️ L1I is not kept coherent with stores in hardware (standard RISC-V). Software uses FENCE.I to invalidate L1I after self-modifying code. L1I exposes a full / address-ranged invalidate for this.
