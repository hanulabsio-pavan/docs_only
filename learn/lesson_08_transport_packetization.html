Transport & Packetization

Four modules that handle the impedance mismatch between CHI protocol flits and router-internal flits, manage transaction state across the network, and implement coherency on the RN-F side. By the end you'll know how a ReadShared becomes routed bytes and how a returning CompData becomes a cache fill.

1Why translate at all?

The protocol layer thinks in chi_req_flit_t, chi_rsp_flit_t, chi_snp_flit_t, chi_dat_flit_t — four differently-sized packed structs full of CHI semantics. The router thinks in noc_flit_ctrl_t — a single uniform 368-bit struct with head/tail/route_mask/VC metadata. These two blocks bridge that gap.

3chi_depacketizer — 1 wire fans out to 4 channels

The reverse direction. A noc_flit_ctrl_t arrives from the router; the depacketizer reads its channel field and routes the payload (truncated to the right typed-flit width) into REQ, RSP, SNP, or DAT outputs. Pick a channel below to see the routing light up.

Why the output register per channel

Each output has a registered *_valid_q and *_flit_q because the downstream might not be ready immediately. The depacketizer accepts a new pkt_in only when the relevant output channel is ready (dst_ready selects the right one). On unknown ch, decode_error rises and the a_no_decode_err assertion fires.

4chi_transport_layer — TXNIDs & retries

The transport layer owns the TXNID free-list (64 slots), stamps each new REQ with an allocated ID, and tracks every outstanding transaction. When a RetryAck arrives it queues the transaction for replay; when PCrdGrant arrives it increments the budget; when Comp arrives it frees the slot. Try it below.

What happens on RetryAck

  1. Detect retryack_hit on a received RSP (chi_transport_layer.sv:204).
  2. Move the matching transaction tracker state to TXN_RETRY; remember the pcrd_type requested.
  3. Push the TXNID to the retry_q (depth-8 FIFO).
  4. Wait for a PCrdGrant with matching pcrd_type — that increments pcrd_budget[type].
  5. When the head of retry_q has matching budget & link credits, replay: pop, decrement budget, move to TXN_ACTIVE, restart timeout.

Filtering internal-only RSPs out of the protocol path

RetryAck and PCrdGrant are link-flow-control responses — the protocol layer should never see them. Line 290 ensures only the meaningful RSPs (Comp, CompDBIDResp, DBIDResp, etc.) propagate up: rsp_to_proto = ll_rx_rsp_valid && opcode != RetryAck && opcode != PCrdGrant.

Snoop handling — the parallel pipeline

Snoops arrive asynchronously from CompData/Comp. The ff_snp_pipe block (line 339) forwards every incoming SNP to the cache controller, then constructs either a plain SnpResp (clean line) or a SnpRespData with the cache line payload (dirty line). To prevent deadlock, the snoop response can't block REQ traffic — that's why CHI mandates separate VCs and why the protocol layer prioritizes SnpResp ahead of CompAck on the TX RSP channel (chi_protocol_layer.sv:258).

7Check yourself

Q1. Why is DAT the highest priority in chi_packetizer's arbitration?
DAT flits are the wide ones (368 bits including a full cache line). If DAT backs up at the packetizer it implies a stalled response path, which means transactions can't complete, which means upstream traffic (REQ) eventually deadlocks. Draining DAT first matches CHI's deadlock-freedom requirement that response classes must never be blocked by request classes.
Q2. The packetizer zero-pads narrower flits up to NOC_FLIT_WIDTH = 368. Why not use four different-sized buses?
Because the router only knows about a single uniform flit type. Routers parameterize FLIT_W to the widest channel; building one fabric per channel would multiply gate count 4× and quadruple the assertion / verification surface. Zero-padding wastes a few bits of buffer per non-DAT cycle but keeps the router parametric.
Q3. A transaction gets RetryAck'd. What three things must happen before it can re-issue?
(1) Transaction moves to TXN_RETRY state; (2) it's pushed to the head of retry_q; (3) a PCrdGrant with matching pcrd_type arrives, incrementing the budget. Then the replay condition fires: head of queue has matching budget AND link credits available — pop, decrement budget, move back to TXN_ACTIVE.
Q4. The protocol layer's snoop response is prioritized ahead of CompAck on the TX RSP channel. Why?
Snoop deadlock prevention. A pending CompAck is part of my transaction completing — I can wait. A pending SnpResp is blocking some other transaction at the HN; if I sit on it, that HN transaction can't complete, which prevents the HN from accepting new REQs, which prevents me from sending my next request. Always drain snoop responses first.
