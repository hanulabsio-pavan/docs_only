ReadShared with Snooping

CPU0 issues a cache-miss read for a line currently held Unique Dirty (UD) by CPU1. The Home Node detects this via the Snoop Filter, issues a snoop to CPU1, which writes back dirty data — and that data is forwarded directly to CPU0.

CPU0 Issues ReadShared Request
CPU0 load-misses on address 0xDEAD_C080. It places a ReadShared flit on the REQ channel toward the Home Node.

CPU0 executes LDR X1, [0xDEAD_C080]. The address misses in both L1 and L2 — no valid entry. The CHI interface generates a ReadShared REQ flit.

CPU0 has no knowledge that CPU1 currently holds this line in Unique Dirty state. That's the Home Node's job to discover via the Snoop Filter.

CPU0 sets ExpCompAck=1, signalling it will send CompAck once data is received — allowing HN to safely track when CPU0 has installed the line.

Same first step as the non-snoop case. The difference only emerges at the HN when it checks the Snoop Filter and finds CPU1 holds the dirty line.

HN Sends ReadReceipt + Checks Snoop Filter
HN allocates a tracker, acknowledges the REQ, and simultaneously checks the Snoop Filter — discovering CPU1 holds the line as Unique Dirty.

The HN allocates a tracker for TxnID=0x12 from CPU0 and immediately sends ReadReceipt on the RSP channel. This releases CPU0's protocol credit so it can issue more transactions.

In parallel, HN consults the Snoop Filter: it finds that CPU1 (NodeID=0x02) holds this line in UD (Unique Dirty) state.

This is the critical decision point: because the line is dirty, HN must not fetch from memory — the memory copy is stale. It must snoop CPU1 first to get the up-to-date data.

Key difference vs clean path: Snoop Filter hit on a dirty line forces the snoop path. Memory fetch is suppressed entirely until CPU1's dirty data is retrieved.

HN Issues SnpShared to CPU1
HN sends a snoop to CPU1 requesting it downgrade from UD to SC — and return the dirty data. RetToSrc=1 forces CPU1 to send data even if it thinks the line is clean.

HN issues a SnpShared flit on the SNP channel to CPU1. This snoop says: "You hold this line uniquely. Another node wants to share it. Downgrade to Shared and send me the data."

Since CPU1's copy is Unique Dirty, it has modified the data from the memory image. HN sets RetToSrc=1 to explicitly request that CPU1 return the data payload — HN needs it to forward to CPU0 and write back to memory.

Note: the SNP channel has no TgtID field — the target is implicit from which physical link the flit is dispatched on (the link toward CPU1's mesh port).

DoNotGoToSD=0 here — HN allows CPU1 to transition to Shared Dirty if needed. But since CPU0 only wants SC, HN will manage state carefully in the response.

CPU1 Returns Dirty Data via SnpRespData
CPU1 flushes its dirty cache line to HN in 2 DAT flits (SnpRespData), downgrading its own copy from UD to SC. This is the only copy of correct data.

CPU1 receives the SnpShared snoop. It finds the line is Unique Dirty — it has made modifications since the memory copy was written. It must return the data.

CPU1 sends a SnpRespData on the DAT channel to HN, carrying the full 64-byte dirty cache line in 2 flits. The Resp=SC_PD (Shared Clean, Pass Dirty) tells HN: "I'm giving you the dirty data. I'm transitioning to SC. You own the dirty responsibility now."

After this, CPU1 retains the line in SC state — it has shared the clean version of what it knew. Memory is still stale until HN writes it back.

SC_PD (Pass Dirty): The "PD" flag tells HN it must write this data back to memory before the transaction ends. HN accepts the dirty responsibility from CPU1.

HN Forwards CompData to CPU0
HN re-packages the dirty data received from CPU1 and delivers it to CPU0 with Resp=SC. CPU0 can now complete its load instruction.

HN now holds the up-to-date 64-byte cache line (from CPU1's dirty writeback). It re-packages it as a CompData and sends it to CPU0 — again in 2 DAT flits.

HN sets Resp=SC — Shared Clean — giving CPU0 a shared copy of the now-clean data. Both CPU0 and CPU1 will end up in SC state.

HN includes HomeNID=0x10 so CPU0 knows where to send the final CompAck. CPU0 can now service the load instruction and bring the line into its L1/L2 cache.

HN is the data broker here. It received dirty data from CPU1 and simultaneously needs to: (1) send it to CPU0, and (2) write it back to memory. These happen independently.

HN Writes Dirty Data Back to Memory
Because CPU1 passed dirty responsibility (SC_PD) to HN, the HN must now update memory with the correct data. This happens in parallel with Step 5.

When CPU1 responded with Resp=SC_PD (Pass Dirty), it transferred the writeback obligation to HN. HN must update memory before releasing its tracker.

HN sends a WriteNoSnpFull (or CopyBackWrData) to the Slave Node (DDR controller), carrying the 64-byte line in 2 DAT flits. This is a non-coherent write — just a direct memory update.

Steps 5 and 6 can happen in parallel — HN can forward data to CPU0 and issue the memory writeback simultaneously, since they use independent routing paths.

No extra REQ needed: HN uses an internal write mechanism (or a pre-allocated write buffer at the SN) to do this writeback efficiently. Memory is updated and the stale state is corrected.

CPU0 Sends CompAck — Transaction Complete
CPU0 confirms data receipt and cache line installation. HN frees the tracker. Snoop Filter updated: both CPU0 and CPU1 in SC.

CPU0 has received all 2 DAT flits (DataID 0x0 and 0x1) and installed the line in SC state. It sends CompAck to HN-F (HomeNID=0x10 from Step 5).

CompAck is the final signal to HN that CPU0 owns the cache line. Only after receiving CompAck does HN update the Snoop Filter to show both CPU0 and CPU1 as sharers in SC state.

HN can now deallocate its transaction tracker for TxnID=0x12. All resources are freed. The memory writeback (Step 6) completes independently.

Transaction is now complete. CPU0 load returns data. CPU1 downgraded cleanly. Memory updated. Both caches coherent at SC.
