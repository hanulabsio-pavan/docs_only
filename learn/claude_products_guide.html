Model Context Protocol

MCP Servers — Claude's Plugin System

MCP (Model Context Protocol) is an open standard that lets Claude connect to external tools and data sources. Think of it as USB-C for AI — one standard interface, thousands of compatible tools.

Without MCP, Claude is isolated — it knows things but can't do things outside of text. MCP servers give Claude hands. Each server exposes a set of tools (actions), resources (data), and prompts (templates) that Claude can use.

💡 MCP was created by Anthropic and is now an open industry standard. Thousands of MCP servers exist in 2026 — from simple database connectors to full workflow automation platforms.

Under the hood, MCP servers expose three building blocks:

🛠️ Tools (Actions)

Things Claude can do. These are functions the server exposes that Claude can call.

  • Create a GitHub PR
  • Insert a row in PostgreSQL
  • Post a Slack message
  • Click a button in Playwright
  • Create a Notion page

📦 Resources (Data)

Data Claude can read. Raw structured data the server makes available for context.

  • Database records / schema
  • GitHub repository files
  • Notion pages and databases
  • File contents from disk
  • API responses / webhooks

📝 Prompts (Templates)

Reusable prompt templates with pre-built context for common workflows.

  • "Review this PR for security issues"
  • "Summarize all open issues"
  • "Generate a standup from my commits"

🔒 Transport Layers

How Claude communicates with MCP servers. Different modes for different environments.

  • stdio — Local process (most common for dev)
  • HTTP/SSE — Remote servers over the internet
  • MCP Tunnels — Private network servers (enterprise)

⚠️ Security tip: Give each MCP server the minimum permissions it needs. Use read-only tokens for GitHub when you only need to read — limit the blast radius if something goes wrong.

Installing an MCP server in Claude Code is a single command:

# Install via HTTP (remote server) claude mcp add --transport http notion https://mcp.notion.com/mcp # Install a local stdio server (npm-based) claude mcp add github -- npx -y @modelcontextprotocol/server-github # List all installed MCP servers claude mcp list # Remove a server claude mcp remove github
💡 MCP configuration is stored in ~/.claude/settings.json. Track this file in your dotfiles repo so your setup is reproducible across machines.
Agentic AI

Agents — Claude That Does, Not Just Talks

An agent is Claude in a loop — it gets a goal, plans steps, executes them, checks results, and keeps going until done. No hand-holding required.

🤖 Key difference: Regular Chat gives you one response per message. An agent takes your goal and works through many steps autonomously — reading files, running code, calling APIs — before reporting back.

⌨️ Subagents in Claude Code Code only

Claude Code can spawn specialized sub-agents that run in parallel — up to 7 simultaneously. Each handles a focused task while the parent agent orchestrates the whole job.

  • Explore agent — maps and understands the file structure
  • Plan agent — researches the codebase, proposes a strategy
  • General agent — executes complex multi-step tasks
  • Example: "refactor auth module" spawns Explore + Plan + 2× implementation agents simultaneously

🖥️ Cowork Agent Model Human-in-loop

Cowork uses the same agentic engine as Claude Code but wraps it in a graphical interface with mandatory human approval steps. Safer for sensitive work.

  • You describe the outcome in plain English
  • Claude proposes a plan with numbered steps
  • You review and approve before execution begins
  • Claude executes — opening apps, editing docs, browsing websites
  • Always triggered manually — no background automation

🏢 Managed Agents Enterprise API

For teams building production agent pipelines via the API. Managed Agents with self-hosted sandboxes give enterprise control over security boundaries.

  • Run inside your own infrastructure
  • Network policies and audit logging you control
  • Files never leave your perimeter
  • MCP tunnels for private network access
  • Used by companies like Amplitude, Clay, Rogo

🔐 Agent Safety Important!

More power means more responsibility. Claude has built-in safety mechanisms, but you should understand them.

  • Claude Code asks permission before destructive actions by default
  • Cowork's VM isolation limits damage if something goes wrong
  • Prompt injection attacks are a real risk (malicious websites can try to hijack agents)
  • Enterprise: use MCP tunnels to keep servers private
  • Principle of least privilege: give agents only the access they need
⚠️ Cowork limitation: Cowork only activates when you manually trigger it. It is not an always-on background agent — it won't run tasks on a schedule or wake up automatically. That capability currently requires Claude Code + a CI/CD pipeline or the API.
Persistent Workspaces

Projects — Persistent Context Across Sessions

By default Claude has no memory between conversations. Projects solve this — they are persistent workspaces where you pin files, instructions, and links that Claude always has access to, no matter which conversation you start.

📁 What is a Project?

A Project is a persistent workspace in Claude Chat or Cowork. It holds:
  • ▸ A permanent system prompt / instructions
  • ▸ Uploaded reference files (code, docs, data)
  • ▸ Linked URLs (documentation, wikis)
  • ▸ All related conversations, grouped
Example Project: "AMBA CHI Documentation" 📌 Instructions: You are a hardware architect expert in AMBA 5 CHI. Always use cyan for RN-F, amber for HN-F, green for SN-F. 📎 Files: - chi_spec_v5.pdf - cache_state_machine.md - flit_reference.xlsx 🔗 Links: - https://arm.com/architecture/system-architectures/amba

Custom Instructions

Skills — Teaching Claude Your Standards

Skills are reusable instruction sets that activate when relevant. Unlike Projects (which are always-on), Skills are context-aware — they kick in only when the task calls for them. Think of them as specialist training modules.

⚡ What is a Skill?

A Skill is a markdown file (typically SKILL.md) containing instructions for a specific type of task. When you or Claude identify a matching task, the skill is loaded into context.

Skills work across Chat, Cowork, and Claude Code. They're not locked to a project — they're reusable across all your work.
# SKILL: CHI Snoop Filter Design Trigger: Any question about snoop filters, SF sizing, or cache lookup in a CHI interconnect. Rules: - Always show filter tables with hit/miss/evict columns - Color code: RN-F=cyan, HN-F=amber - Assume 16-way set associative unless stated - Include latency breakdown when analyzing performance - Reference ARM IHI0050 spec section numbers

⌨️ Skills in Claude Code — SKILL.md & CLAUDE.md Advanced

Claude Code has a more structured skills system. It reads special markdown files from your project directory and activates relevant ones automatically.

# CLAUDE.md — project-wide persistent context (memory) # Loaded at the start of every Claude Code session in this repo project: CHI NoC Micro-architecture Reference language: SystemVerilog + Python build: make sim TEST=<testname> test: pytest tests/ -v # Rules - never modify golden reference files under rtl/golden/ - always run lint before committing # skills/chi-snoop-filter/SKILL.md — activated when relevant # trigger: snoop filter, SF, lookup latency Always include HitMissEvict table. Show cycle breakdown.
  • CLAUDE.md = always-on project memory (like a project README Claude always reads)
  • SKILL.md = conditional instructions that activate for specific task types
  • Skills with no skills/ subdirectory and only a root SKILL.md are surfaced as single skills in the UI
Version Control

Git Access — From Read-Only to Full Automation

Git access varies dramatically across the three products. Claude Code is where git really shines — it can handle your entire development workflow end-to-end.

💬 Claude Chat

  • No direct git access
  • Can read git diffs you paste in
  • Can write git commands for you to run
  • Can review commit messages, PR descriptions
  • Understands git concepts and explains them
Use for: learning git, writing commit messages, reviewing diffs you paste

🖥️ Claude Cowork

  • Limited git via GitHub MCP connector
  • Can read repos, issues, and PRs
  • Cannot execute local git commands directly
  • Can browse github.com via its browser
  • Best for: project management tasks
Use for: reading GitHub issues, creating PR descriptions, reviewing code on github.com

⌨️ Claude Code

  • Full git integration — reads your entire repo
  • Creates branches, commits with messages
  • Runs git diff, git log, git blame
  • Creates and reviews pull requests (via GitHub MCP)
  • Manages worktrees for parallel development
  • Hooks into CI/CD pipelines
Use for: full software development lifecycle automation

Example: Claude Code Full Git Workflow

# Start Claude Code in your repo cd my-chi-noc-project claude # Then just talk to it: You: "There's a bug in the snoop filter hit calculation — fix it, write a test, and open a PR against main" # Claude Code will: # 1. Run git log to understand recent changes # 2. Read the relevant source files # 3. Identify the bug # 4. Create a new branch: git checkout -b fix/snoop-filter-hit # 5. Edit the source file to fix the bug # 6. Write a pytest test # 7. Run the tests to confirm they pass # 8. git add + git commit -m "fix: correct SF hit calculation logic" # 9. git push origin fix/snoop-filter-hit # 10. Create a GitHub PR via the GitHub MCP server
⚠️ New in May 2026: Claude Code now properly handles pre-existing git worktrees in background sessions — a previous bug blocked editing while EnterWorktree refused to create duplicates. This is now fixed.
When to Use What

Decision Guide — Pick the Right Tool

Not sure which product to reach for? Match your task to the right Claude mode.

  • 💭 I want to brainstorm, write an essay, analyze a document, or have a conversation
    Chat
  • 📊 I need to reorganize 200 PDFs, pull data from them into a spreadsheet, and email a summary
    Cowork
  • 🐛 I need to find and fix a bug in my codebase, run tests, and commit the fix
    Code
  • ✉️ I want to review my emails, draft replies, and schedule follow-ups — no code involved
    Cowork
  • 🚀 I want to build a CI pipeline that automatically reviews PRs and comments with suggestions
    Code
  • 📝 Quick question: "What is cache coherency in AMBA CHI?"
    Chat
  • 🖼️ I need to open Figma, screenshot each screen, and document them in Notion
    Cowork
  • 🔧 I want to add a new API endpoint, write docs, write tests, and deploy to staging
    Code
  • 📚 I'm working on an ongoing project and want Claude to always know my style, codebase, and rules
    Project
  • 🤔 I'm a non-developer who wants to automate repetitive computer tasks without learning to code
    Cowork
  • ⚡ I want maximum autonomy — Claude just goes and does the work, I'll review the result
    Code
