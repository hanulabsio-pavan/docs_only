Router Building Blocks

Three mid-size modules sit between the leaf primitives and the full router: the input port that sorts incoming flits into per-VC FIFOs, the output port that arbitrates among VCs and gates on downstream credits, and the virtual-channel manager that tracks occupancy and watches for deadlock. By the end, you'll be able to read router_top.sv top-to-bottom.

1input_port — sorting flits into per-VC FIFOs

One input_port sits at each of the 5 router input directions (N/S/E/W/Local). It decodes the channel field of the incoming flit, looks up which VC it belongs to via channel_to_vc(), and writes it to that VC's dedicated FIFO. Each VC has its own depth-8 storage so head-of-line blocking on one channel doesn't stall the others.

Send a flit on:

Backpressure: ready_out

The input port asserts ready_out only when the selected VC's FIFO has room. If REQ's VC0 is full but RSP's VC1 is empty, the port is not ready for REQ but is for RSP — that's why each VC has its own FIFO instead of one shared FIFO.

2output_port — VC priority + credit gating

The output port instantiates 4 flit_buffers (one per VC) on its input side. On the output side it does strict-priority arbitration: VC3 wins over VC2 over VC1 over VC0. But a VC only enters arbitration if both its FIFO has a flit ready and it has at least one downstream credit. Click any VC's "credit" button to spend a credit; press Tick to advance the arbiter.

The dequeue condition: buf_rd_ready[vc] = any_grant && (grant_vc == vc) && link_ready; — meaning the buffer drains only when this VC won arbitration AND the downstream link said it was ready. any_grant requires both buf_rd_valid && credit_avail.

3virtual_channel_mgr — occupancy & deadlock

A bookkeeper that tracks how many flits sit in each (port, VC) pair across the whole router, allocates VCs by mapping channel → VC class, and watches for the worst kind of bug — a deadlock. The stall counter increments any cycle the buffer is at BUF_DEPTH; if it ever hits 0xFFFF the watchdog raises deadlock_suspected.

Buffer occupancy across all (port, VC) pairs

Click any cell to push a flit into that (port, VC). Cell turns yellow at 7/8 (almost_full), red at 8/8 (full).

⚠ deadlock_suspected = 1: at least one (port, VC) has been at full capacity for 65,535 consecutive cycles. perf_monitor logs the event and error_handler raises irq_error.

6Check yourself

Q1. Why does input_port have four separate FIFOs instead of one shared FIFO with VC tags?
Head-of-line blocking. If a REQ flit at the front can't make forward progress (its output port is congested), a single FIFO would also block the RSP and DAT flits queued behind it — even if their output ports were wide open. Separate per-VC FIFOs let each channel make progress independently. This is fundamental to deadlock freedom.
Q2. output_port uses strict priority (VC3 > VC2 > VC1 > VC0). Could VC0 ever starve?
In theory yes — if VC1/2/3 always have something to send. In practice the upstream protocol guarantees a finite supply: each transaction generates a bounded number of higher-VC flits per REQ. The Hi-VC (VC3) is reserved for retry traffic specifically so normal Hi-priority bursts don't choke REQ/SNP forever. The DV plan checks this in TC-STRESS-002.
Q3. The dequeue condition is any_grant && (grant_vc == g) && link_ready. Why include link_ready?
The downstream link or next router could be back-pressuring even if we have credits available. link_ready is the immediate handshake from the next module saying "I can accept a flit this cycle." Without it we'd dequeue from our FIFO with nowhere to send the flit — losing data. Credits are upstream flow control; link_ready is downstream readiness.
Q4. The deadlock watchdog uses a 16-bit stall counter. With 1 GHz clock, how long before it trips?
2¹⁶ = 65,536 cycles at 1 GHz ≈ 65 microseconds. That's aggressively long for a fabric event — by then either real traffic has unblocked or there's a genuine cycle. It's an intentional choice: short enough to catch silicon bugs, long enough to never false-fire on legitimate congestion bursts.
