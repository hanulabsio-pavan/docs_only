Section 01
Why SNP Has No TgtID

Every other CHI channel carries a TgtID so mesh routers can forward the flit to the right node. SNP drops it entirely — because the link itself identifies the destination.

REQ / RSP / DAT: Flit enters mesh. Router reads TgtID. Forwards hop-by-hop. Destination unknown without TgtID.
SNP: HN-F looks up Snoop Filter → gets NodeID of sharer → maps NodeID to physical link → puts flit directly on that link. Router not involved. TgtID = redundant = dropped.
The saving: TgtID = 11 bits. Every SNP flit shrinks by 11 bits. At thousands of snoops/sec across a 16-core mesh, this is meaningful bandwidth reduction.

Section 02
What Exactly Is a "Link"?

Link ≠ separate wire. Link = one physical connection between two adjacent nodes, carrying ALL four CHI channels simultaneously via virtual channel multiplexing.

🔌 Wire (Physical)

Actual copper/metal trace on silicon die. Current flows here. Cannot be reprogrammed.

🔗 Link (Physical+Logical)

Bundle of wires between two nodes. Carries REQ + RSP + DAT + SNP channels. One link per neighbour node.

🚪 Port (Logical)

HN-F's named endpoint of a link. "Port 2" = the end of the link that connects to CPU2. Not a separate wire.

Section 05
Direct Link vs Broadcast — Full Comparison

Snoop Filter exists precisely to convert broadcasts into direct-link snoops. Every filter miss is a broadcast penalty.

Property Direct Link (Filter HIT) Broadcast (Filter MISS)
Trigger Filter has entry → knows which CPU Filter miss → no entry for address
Links used 1 (targeted) N (all RN-Fs)
SNP flits sent 1 4 (for 4-CPU system)
RSP flits received 1 4 (must wait for all)
CPUs interrupted 1 All N CPUs
Wasted SNP flits 0 N−1 (only 1 had the line)
Latency ~1 RTT ~2–3 RTT (wait slowest CPU)
Mesh bandwidth Minimal High — all links active
Pipeline disruption 1 CPU pipeline stalled All N pipelines stalled
Scales with core count? Yes — always 1 SNP No — N flits for N CPUs
Why direct-link works without TgtID: HN-F selects which physical link to put the SNP flit on. The CPU at the other end of that link receives it. The link IS the addressing mechanism — no TgtID field needed inside the flit.
Broadcast penalty scales badly: 16-core system with 10% filter miss rate → every miss costs 16× the bandwidth and latency. This is why engineers spend silicon area on large snoop filters.

The key insight: REQ needs TgtID because it enters a shared mesh where multiple routers must forward it. SNP goes on a specific pre-selected link — HN-F picks the link based on its routing table (NodeID → port). The link itself carries the addressing information. No field inside the flit needed. This is why SNP is point-to-point only — mesh routing of SNP would require adding TgtID back.
