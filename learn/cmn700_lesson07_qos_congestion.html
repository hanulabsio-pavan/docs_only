QoS, Congestion Control & Performance Tuning

Keeping the fabric fast and fair under load: priority classes, closed-loop throttling, re-routing and placement.

By the end of this lesson you can

  • Explain CHI QoS priority classes and how arbitration uses them.
  • Describe CBusy closed-loop throttling and why it raises throughput.
  • Explain hot-spot re-routing and its ordering caveat.
  • Reason about how node placement and channel width change latency and bandwidth.

1The problem: contention

caveman mode

Roads jam. Two fixes. One: tell greedy CPU "memory busy, stop prefetching so hard" — fewer cars enter road. Two: when one crossroad jammed, send some cars around it. Also: important ambulance cars go first (QoS).

A 100+ core mesh under load is a queueing system, and an unmanaged queueing system collapses: everyone issues more requests, queues grow, latency explodes, useful throughput falls. CMN-700 has three answers — prioritise (QoS), reduce injection (CBusy), and spread the load (re-routing and placement).

2QoS priority classes

Every CHI transaction carries a QoS priority value. Arbitration points in the fabric — XP switching, home-node tracker allocation, memory-controller scheduling — use it to favour higher-priority traffic.

Latency-critical flows

Real-time or interactive traffic gets a high class so it isn't stuck behind bulk transfers.

Bulk / best-effort flows

Large DMA copies and streaming get a lower class — they care about aggregate bandwidth, not per-request latency.

QoS alone does not create bandwidth; it decides who waits. That is why it pairs with the mechanisms below, which actually reduce or redistribute load.

3CBusy — Completer Busy

CBusy (early material called it MemBusy) is closed-loop congestion feedback. When a completer — a memory controller or home node — is getting congested, that busy level is signalled back to the requester, and the core responds by throttling: reducing prefetcher aggressiveness and the number of outstanding transactions it keeps in flight.

Closed loop: congestion feeds back, injection drops
   core / RN-F                          HN-F / SN-F
        |  requests + speculative prefetch      |
        | -------------------------------->     | queues filling
        |                                       |
        | <----------- CBusy level ----------     |
        ▼                                       |
   throttle prefetch + fewer outstanding txns
        |                                       |
        ▼  less speculative junk in the queues  ▼
   queues drain -> real demand requests get served faster

Counter-intuitive but important: issuing fewer requests can make the system faster, because speculative prefetches were displacing demand traffic. Arm reported an uplift of roughly 15% from this mechanism on a Neoverse V1-class design.

This is a strong interview answer because it shows you understand that fabric performance is about controlling offered load, not just widening pipes.

4Hot-spot re-routing

Baseline routing is deterministic and dimension-ordered (Lesson 1). CMN-700 can detect a congested crosspoint or path and temporarily steer traffic through alternative XPs to relieve the jam.

Benefit

A single hot XP — often near a heavily used memory controller or gateway — stops throttling the whole region.

Caveat

Alternative paths mean packets can arrive out of the deterministic order, so re-routing is applied carefully and only where ordering rules permit.

Mentioning that caveat unprompted is a good signal: adaptive routing always trades ordering guarantees for load balance.

5Bandwidth levers

A full 12×12 mesh at roughly 2 GHz with the double-width data channel reaches about 3.07 TB/s cross-sectional bandwidth — a useful anchor number.

6Placement: the free latency win

Since latency tracks hop count, where you put things is a first-order design decision:

  • Memory controllers on the edges, near their PHYs — physically necessary, and it keeps the interior free for compute.
  • Home nodes spread through the interior, so the average distance from any core to its home node is small and no region is starved of coherency throughput.
  • Gateways (CCG) at the edge, near the chip-to-chip PHYs.
  • Latency-sensitive accelerators close to the memory or cores they pair with, rather than diagonally opposite them.
Typical placement intuition
   SN-F  SN-F  SN-F  SN-F      memory hugs the edge (PHYs)
    |     |     |     |
   XP----XP----XP----XP
    |     |     |     |
   HN-F  RN-F  HN-F  RN-F     homes interleaved with compute,
    |     |     |     |            so no core is far from a home
   XP----XP----XP----XP
    |     |     |     |
   RN-F  HN-F  RN-F  RN-I     IO / gateways toward the edge

9Interview Q&A

How does the fabric handle congestion?
Three complementary mechanisms. QoS priority classes decide who waits at arbitration points. CBusy is closed-loop feedback: completer congestion is signalled back so cores throttle prefetching and outstanding transactions, which drains queues and raises useful throughput (Arm cited around 15% on a V1-class design). Hot-spot re-routing temporarily steers traffic around a congested crosspoint, subject to ordering constraints.
How would node placement change performance?
Latency tracks hop count, so placement sets the average distance between cores, home nodes and memory. Memory controllers sit at the edges near their PHYs; home nodes are spread through the interior so no core is far from its home; gateways go near the chip-to-chip PHYs. Bad placement creates choke points where traffic funnels through a few crosspoints.
What are the levers for more bandwidth?
Enable the double mesh channel (256 to effectively 512-bit DAT), grow mesh dimensions for more midline links, raise frequency, add HN-F slices for more parallel coherency engines and SLC capacity, and add SN-F memory channels with good MC SAM interleaving. A full 12x12 at about 2 GHz with double-width data reaches roughly 3 TB/s cross-sectional.
QoS versus congestion control — what is the difference?
QoS is allocation under scarcity: it decides which traffic wins at arbitration, but it does not reduce total load. Congestion control (CBusy) reduces the offered load, and re-routing redistributes it. You generally need all three: prioritise, reduce, and spread.
Latency degrades badly at high load. How do you investigate?
Use the PMU to find whether one home node or crosspoint is disproportionately hot. If a single HN-F is hot, suspect address hashing or interleave granularity. If a single XP is hot, suspect placement or a funnelling path. If everything is uniformly saturated, look at offered load and whether prefetch throttling is engaging, and at whether the data channel or memory channels are the true limit.

10Recap & key terms

  • QoS classes prioritise at arbitration but create no bandwidth.
  • CBusy feeds completer congestion back → core throttles prefetch and outstanding transactions (~15% uplift reported).
  • Hot-spot re-routing spreads load around congested XPs, with an ordering caveat.
  • Bandwidth levers: double mesh channel, mesh size, frequency, more HN-F / SN-F.
  • Placement is a first-order latency decision: memory at edges, homes spread through the interior.
