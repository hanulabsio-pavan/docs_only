Section 01
Memory Hierarchy Overview

Modern processors bridge the gap between fast CPU execution (sub-nanosecond) and slow DRAM access (60–100ns) using multiple levels of increasingly large, increasingly slow, increasingly shared caches. Each level serves a different role in the memory subsystem.

// Memory Hierarchy Pyramid — Size vs Speed
Why multiple levels? A single cache large enough to hold the full working set would be too slow (large SRAM = long access paths). A single cache fast enough for 1-cycle access would be too small (SRAM area scales with size). Multiple levels give you speed where it matters most (L1 for hot data) and capacity where you need it (L3 for large working sets).
Section 02
L1 Cache — First Level, Fastest

The closest memory to the CPU execution pipeline. Split into separate Instruction (L1-I) and Data (L1-D) caches to allow simultaneous fetch and load/store without structural hazards.

Section 03
L2 Cache — Unified Private Buffer

The L2 acts as a combined instruction and data buffer, catching misses from both L1-I and L1-D. Still private to one CPU core (or a small cluster). Significantly larger than L1 but with higher latency.

L2 Cache Entry Structure
Per cache line entry (64B line): ┌──────────────────────────────────────────────────┐ │ Valid(1) │ Dirty(1) │ State(3) │ Tag(38b) │ Data(64B×8) │ └──────────────────────────────────────────────────┘ Tag comparison: Address → Index[13:6] → jump to set (256 sets typical) Compare tag against 8 ways simultaneously 8 comparators fire in parallel → hit or miss in 1 read Write-back policy: dirty lines written to L3 on eviction Victim cache: some L2s have a small fully-associative victim cache to reduce conflict misses at set boundaries
Typical size256KB – 4MB
Associativity8–16 way
Line size64 bytes
Access latency5–15 cycles
ECCSECDED (full)
Shared?No — per core (or 2-core cluster)
InclusivityInclusive or exclusive of L1
L2 Inclusivity Policy: Some designs make L2 inclusive of L1 (every L1 line also exists in L2). This simplifies coherency snoop handling — an L2 hit means the line is definitely present. Other designs use exclusive L2 (L2 holds only lines NOT in L1), maximising effective capacity. CHI does not mandate either policy.

Section 04
L3 Cache — Shared Last-Level Cache

The Last Level Cache (LLC) is shared across all CPU cores in a cluster. It is the final line of defence before going off-chip to DRAM. Much larger but significantly slower than L1/L2. Connects directly to the CHI interconnect.

L3 Cache Entry Structure
Per cache line entry (more complex than L1/L2): ┌─────────────────────────────────────────────────────────────────┐ │ Valid │ Dirty │ State(3) │ Tag(38b) │ CoreID(4) │ ECC │ Data(64B) │ └─────────────────────────────────────────────────────────────────┘ Additional complexity vs L1/L2: → CoreID: tracks which L1/L2 may have a copy (directory function) → Wider ECC: stronger protection (SECDED per 64B + check bits) → Snoop directory: some L3 designs embed limited directory tracking → Banked SRAM: 8–32 banks to serve multiple cores simultaneously → Hash-based interleaving: distribute hot addresses across banks Multi-bank design (16-core shared L3): Bank 0: handles addr[5:4] = 00 Bank 1: handles addr[5:4] = 01 Bank 2: handles addr[5:4] = 10 Bank 3: handles addr[5:4] = 11 → 4 concurrent accesses from different cores possible
Typical size4MB – 256MB
Associativity16–32 way
Banks8–64 banks
Access latency20–60 cycles
Shared?Yes — all cores in cluster
ECCSECDED per chunk
Transistors/bit6T SRAM (standard)
L3 and CHI: The L3 cache sits at the boundary between the CPU cluster and the CHI mesh. When L3 misses, it issues a CHI REQ to the HN-F. When another CPU on a different cluster requests a line held here, the HN-F's Snoop Filter detects it and issues a CHI SNP back to this L3 (technically to the RN-F interface of this cluster). The L3 must respond with a SnpResp or SnpRespData on the DAT channel.
Section 05
Snoop Filter — The Coherency Tracker

The Snoop Filter lives inside the HN-F node (not inside any CPU). It does NOT store actual data — it stores only the metadata needed to answer: "which CPU caches currently hold this cache line, and in what state?"

Critical distinction: Caches store data. The Snoop Filter stores only tracking metadata. Yet it costs 2–3× more per bit than cache SRAM. This is the central paradox of snoop filter design — expensive hardware that holds no useful data, only bookkeeping.
Snoop Filter Entry Structure (CAM-based)
Per entry — NO DATA PAYLOAD: ┌─────────────────────────────────────────────────────────┐ │ Valid(1) │ Tag(38b) │ Sharers(N bits) │ State(3) │ Dirty(1) │ └─────────────────────────────────────────────────────────┘ N = number of RN-F nodes in system (e.g. 8 bits for 8 CPUs) Example with 8 CPUs, 44-bit PA: Valid: 1 bit Tag: 38 bits (44 - 6 offset bits) Sharers: 8 bits (bitmap: bit0=CPU0, bit1=CPU1, ...) State: 3 bits (UC=001, SC=010, UD=011, SD=100) Dirty: 1 bit (PD flag pending) ───────────────── Total: 51 bits → padded to 64 bits (8 bytes) per entry 8K entries × 8 bytes = 64KB SRAM for metadata only 8K entries × 64 bytes of actual data = 512KB L3 coverage CAM search operation: Incoming address → broadcast to ALL entries simultaneously Each entry compares its tag in parallel Match found → read sharer bitmap → target those CPUs only No match → broadcast snoop to all CPUs

Section 06
SRAM vs CAM — Deep Dive

The fundamental structural difference between cache SRAM (set-associative) and Snoop Filter CAM (fully-associative) explains why the filter is so much more expensive per bit.

6T SRAM Cell — Cache
Standard bit cell · Set-associative access
VDD │ ┌──[P1]──┬──[P2]──┐ │ │ │ BL─[N3]──Q──Q̄──[N4]─BL̄ │ │ │ └──[N1]──┴──[N2]──┘ │ GND 6 transistors: 2 PMOS (P1,P2) 4 NMOS (N1,N2,N3,N4) Q and Q̄ form cross-coupled latch

Use INDEX bits of address to select one row (set)
2.
Activate only that row's word-line
3.
Read N tags (N = associativity, e.g. 8)
4.
Compare 8 tags in parallel with 8 comparators
5.
Hit → read data. Miss → next level
✓ Only 1 row activated per lookup
✓ Only N comparators (small N)
✓ Low power — most SRAM idle
✓ Scales well to 256MB+
✗ Cannot search by content
12–16T CAM Cell — Snoop Filter
Content Addressable Memory · Fully-associative
Standard 6T SRAM cell + Match Line (ML) circuitry: VDD │ [Precharge] │ ML─────[N5]────── GND │ [N6 gated by Q] │ [N7 gated by search_data] 12–16T total: 6T store + 6–10T match ML precharged HIGH each cycle Mismatch: one transistor pulls ML LOW Match: ML stays HIGH → row matched!
1.
Broadcast search address to ALL rows simultaneously
2.
Every row's match circuit fires in parallel
3.
Any mismatch pulls that row's Match Line low
4.
Remaining HIGH match lines = address found
5.
Read sharer bitmap from matching row
✓ Can search by content (address)
✓ Fully associative — no conflicts
✗ ALL rows activate every lookup
✗ 2–3× transistors per bit
✗ High power — match lines loaded
✗ Scales poorly beyond ~8MB
// Match Line Scaling Problem
Solution: Modern snoop filters use set-associative CAM — index bits select a subset of rows (e.g. 32 rows), then CAM-compare only those. This limits match line length while preserving content-addressable lookup within the set.

Section 09
Coverage & The Cost Paradox

The Snoop Filter costs 2–3× per bit more than L3 SRAM, yet can only track 5–15% of total cached data. This is the fundamental tension in coherency hardware design.

// Coverage Ratio by SoC Tier
Why can't we just make it bigger? Each doubling of snoop filter entries doubles die area (CAM SRAM at 2–3× per bit) AND doubles the Match Line capacitance (slower lookup) AND doubles leakage power. In 5nm technology, a 32MB snoop filter would consume ~10–15mm² of die area and significant leakage power — larger than many L3 caches at the same technology node, yet storing no actual data.

Appendix
Glossary
TermDefinition
6T SRAMStandard 6-transistor SRAM bit cell. Cross-coupled inverters hold state. Used in all cache levels.
12–16T CAMContent Addressable Memory cell. 6T SRAM plus 6–10 additional transistors for match-line comparison logic.
Match Line (ML)Wire in a CAM that is precharged high each cycle. Any mismatching cell pulls it low. High = match found.
Set-AssociativeCache organisation where each address maps to a fixed set (via index bits) and can occupy any way within that set.
Fully-AssociativeCache/filter organisation where any entry can hold any address. Requires content-addressable lookup (CAM).
PLRUPseudo Least Recently Used. Approximates LRU replacement using a tree of 1-bit recency indicators per set.
SECDED ECCSingle Error Correct, Double Error Detect. ECC scheme protecting cache data from bit flips.
Sharer BitmapBit vector in snoop filter with one bit per RN-F node. Set bits indicate which CPUs currently cache a line.
Filter EvictionWhen snoop filter is full, an entry is removed — requiring forced invalidation snoops to all its sharers.
Broadcast SnoopSNP sent to all RN-F nodes when filter has no entry for an address. Expensive — interrupts all CPUs.
HN-FHome Node Full. CHI node that owns an address range, holds the Snoop Filter, and coordinates coherency.
UC / UD / SC / SDCHI cache states: Unique Clean, Unique Dirty, Shared Clean, Shared Dirty. Determines snoop requirements.
PD (Pass Dirty)Flag in CHI snoop response indicating the responder is handing dirty writeback responsibility to the HN-F.
LLCLast Level Cache. The final cache level before DRAM. Usually L3 in modern SoCs.
Working SetThe set of memory addresses actively accessed by a running workload within a time window.
