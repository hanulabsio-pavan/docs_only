Chapter 1: CHI Protocol Overview

What is CHI?

The Coherent Hub Interface (CHI) is ARM's open-source protocol for coherent system interconnects. It defines how multiple processors, caches, and other coherent agents communicate to maintain cache consistency across a system-on-chip (SoC).

CHI is designed for:

  • Multi-core processors with shared caches
  • Heterogeneous computing (CPUs + GPUs + accelerators)
  • Scalable SoCs with complex memory hierarchies
  • Deterministic, low-latency coherency

Core Architecture

CHI systems consist of three main components:

Transaction Model

CHI transactions follow a three-phase model:

  1. Request Phase: Request Node sends a coherent request (e.g., read, write, atomic) to the Home Node
  2. Snoop Phase: Home Node broadcasts snoop messages to relevant nodes (caches) to invalidate or update data
  3. Response & Data Phase: Snoop nodes and home respond with acknowledgments and data
Advanced: CHI vs. Other Protocols (ACE, AXI)

ACE (AXI Coherency Extension): Earlier ARM coherency protocol; simpler but less flexible. Still used in some SoCs.

AXI: Non-coherent interconnect; CHI sits on top of AXI in some designs.

CHI advantages:

  • Scalable: Supports many more agents than ACE
  • Flexible: Multiple transaction types and ordering semantics
  • Modern: Designed for heterogeneous compute with GPU/AI accelerators

Self-Check Quiz

Q1: What are the three main node types in a CHI system?

Request Nodes (CPUs/GPUs), Home Nodes (memory controllers), and Snoop Nodes (caches). The Home Node maintains coherency and distributes snoops; Snoop Nodes respond to maintain cache consistency.

Q2: How many phases does a typical CHI transaction have?

Three phases: (1) Request Phase, (2) Snoop Phase, and (3) Response & Data Phase. This allows distributed coherency decisions.

Key Takeaways

  • CHI (Coherent Hub Interface) is ARM's protocol for cache coherency in SoCs
  • Systems consist of Request Nodes (CPU/GPU), Home Nodes (memory), and Snoop Nodes (caches)
  • Transactions follow a three-phase model: request → snoop → response
  • CHI scales better than older ACE protocol and supports heterogeneous architectures

Chapter 2: Cache States & Transitions

The MESI Coherency Model

CHI uses a MESI (Modified, Exclusive, Shared, Invalid) coherency model to track cache line states across the system. Each cache line can be in one of four states:

  • Invalid (I): Cache line does not contain valid data
  • Shared (S): Cache line is clean (matches memory); may exist in multiple caches
  • Exclusive (E): Cache line is clean and only in this cache; can transition to Modified without snoop
  • Modified (M): Cache line is dirty (differs from memory); exists only in this cache

State Transition Diagram (Interactive & Animated)

Key Transitions Explained

I → S (Read Miss): A cache miss on a read results in fetching the line in Shared state. Other caches may also have copies.

I → E (Read-Exclusive): If only this cache has requested the line, it arrives in Exclusive state (clean, owned by this cache).

S/E → M (Write): Writing to a cache line transitions it to Modified. From Shared, a snoop is required to invalidate other copies; from Exclusive, no snoop needed.

* → I (Snoop Invalidate): When another cache requests write access, snoops invalidate other copies.

Advanced: MOESI & Other Extensions

Some systems use MOESI (adds Owned state), which allows a cache to hold a dirty line and supply data to other caches without writing to memory first.

CHI can be configured with various coherency models; MESI is the most common for ARMv8 systems.

Self-Check Quiz

Q1: What is the difference between Shared and Exclusive states?

Shared: Multiple caches may have the line; writes require snoops to invalidate others. Exclusive: Only this cache has the line; writes can proceed without snoops.

Q2: What transition occurs when a snoop invalidate message arrives for a cache line in Modified state?

The line transitions from Modified → Invalid. The cache must write-back the dirty data to memory (or supply it to the requestor) before invalidating.

Key Takeaways

  • MESI has four states: Invalid, Shared, Exclusive, Modified
  • Exclusive is special: allows writes without snoops (fast path)
  • Transitions are triggered by local reads/writes and incoming snoop messages
  • Coherency invariant: Only one cache can have Modified; Shared lines are clean

Chapter 3: CHI Transaction Types

Overview

CHI defines several categories of transactions to handle different access patterns and coherency requirements:

  • Request Transactions: Initiated by Request Nodes (reads, writes, atomics)
  • Snoop Transactions: Broadcast by Home Node to invalidate/update cache lines
  • Response Transactions: Sent by nodes to acknowledge and provide data

Request Transaction Types

Transaction Purpose
ReadShared Read-only access; line arrives in Shared state
ReadUnique Read for future write; line arrives Exclusive
WriteUnique Write; invalidates other copies, line arrives Modified
AtomicStore Atomic operation (CAS, swap); returns old value
Evict Cache line eviction; notifies home

Snoop Transaction Types

The Home Node sends snoop transactions to Snoop Nodes (caches) to maintain coherency:

  • SnpShared: "Do you have this line?" (read-only check)
  • SnpUnique: "Invalidate or downgrade your copy" (for incoming exclusive access)
  • SnpCleanInvalid: "If you have a clean copy, invalidate it"

Example Transaction Flow

Let's trace a ReadUnique transaction (read for future write):

Transaction Sequence (ReadUnique)
// Step 1: Requester sends ReadUnique to Home Request: ReadUnique (Address=0x4000, Requester=CPU0) // Step 2: Home Node checks directory, sends snoops to caches holding line Snoop: SnpUnique → CPU1 (Address=0x4000) Snoop: SnpUnique → CPU2 (Address=0x4000) // Step 3: Snoopers respond with SnpResp_Inv (invalidate & send data if dirty) Response: SnpResp_Inv (Data="CachedValue", WasModified=false) ← CPU1 Response: SnpResp_Inv (Data="invalid", WasModified=false) ← CPU2 // Step 4: Home sends CompData with line in Exclusive state Response: CompData (Data=0x4000, State=Exclusive) → CPU0 // Result: CPU0 has line in Exclusive; can write without further snoops
Advanced: WriteUnique vs. ReadUnique Performance Trade-off

ReadUnique: Acquires exclusive access before write; higher latency upfront, but write is fast (no snoop needed).

WriteUnique: Sends write directly; lower latency if no other copies, but requires snoop at write time if others have the line.

Software (compiler, runtime) chooses based on predicted access patterns.

Self-Check Quiz

Q1: What is the key difference between ReadShared and ReadUnique requests?

ReadShared fetches the line in Shared state (multiple readers allowed). ReadUnique acquires exclusive access, allowing a fast subsequent write without additional snoops.

Q2: When a WriteUnique request arrives at the Home Node, what snoop messages are sent?

SnpUnique snoops are sent to all caches holding the line (in directory). They respond by invalidating their copy and sending data if modified.

Key Takeaways

  • Request transactions (ReadShared, ReadUnique, WriteUnique, Atomic, Evict) initiate coherent operations
  • Snoop transactions (SnpShared, SnpUnique, SnpCleanInvalid) maintain consistency across caches
  • ReadUnique is optimized for read-modify-write patterns; avoids snoop on subsequent write
  • Home Node** maintains a directory to target snoops efficiently

Chapter 4: Deadlock Avoidance & Performance

The Deadlock Problem

In distributed systems with multiple nodes exchanging messages, deadlock can occur if:

  • Node A waits for Node B's response
  • Node B waits for Node C's response
  • Node C waits for Node A's response
  • → Circular wait; all nodes stall indefinitely

CHI mitigates this through careful protocol design and resource management.

CHI Deadlock Prevention Techniques

1. Virtual Channels (VCs)

CHI separates traffic into multiple virtual channels, each with independent buffering and ordering guarantees:

  • Request VC: Request transactions (ReadShared, WriteUnique, etc.)
  • Response VC: Response transactions (CompData, SnpResp)
  • Data VC: Data-bearing responses
  • Snoop VC: Snoop requests from Home

By separating channels, a stall in one VC (e.g., waiting for data) doesn't block other VCs, breaking dependency cycles.

2. Strict Ordering Rules

CHI enforces ordering constraints to prevent circular dependencies:

  • A request must receive a response before being considered complete
  • Snoops must be answered before further requests to the same address from that snoopers
  • Data responses follow a deterministic ordering (FIFO per VC)

3. Timeout & Recovery (Optional)

Advanced implementations include watchdog timers to detect stalls and reset interconnect state.

Performance Optimization Strategies

1. Cache Prefetching

Anticipate future accesses and fetch lines early using prefetch requests. Reduces latency of predicted reads.

2. Speculative Reads

Use ReadUnique speculatively (guessing a write will follow soon). If no write occurs, downgrade to Shared on eviction.

3. Directory Optimization

Home Node maintains a directory of which caches hold each line. Reduces snoop broadcast to only relevant nodes (vs. broadcasting to all).

4. Link-Level Flow Control

Use backpressure (NREADY/credits) to manage interconnect congestion and prevent buffer overflow.

Advanced: CHI Ordering Guarantees (Sequential vs. Relaxed)

CHI supports multiple ordering semantics:

  • Sequential Consistency: Strictest; all processors see same order of operations
  • Relaxed Consistency: Allows reordering with explicit barriers (e.g., DSB - Data Synchronization Barrier)

Software uses barriers (DMB, DSB) when order matters (e.g., before releasing a lock). This improves performance by allowing aggressive reordering in the common case.

Self-Check Quiz

Q1: How do virtual channels prevent deadlock in CHI?

Virtual channels separate traffic into independent lanes (Request, Response, Data, Snoop) with independent buffering. A stall in one VC cannot block another, breaking circular wait conditions that cause deadlock.

Q2: What is the advantage of a directory-based approach over broadcast snooping?

A directory tracks which caches hold each line, allowing snoops to target only relevant caches. Broadcast snooping wastes bandwidth and interconnect resources by sending to all nodes.

Key Takeaways

  • Deadlock arises from circular dependencies in message flow
  • Virtual channels separate traffic into independent lanes, breaking cycles
  • Ordering rules enforce strict sequencing to prevent hazards
  • Directory-based snooping improves efficiency over broadcast
  • Speculation & prefetching hide latency and improve performance
