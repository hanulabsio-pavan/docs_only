Base RV32I — encoding, decode and datapath

The base is not the easy part. It is the part you are expected to explain without hesitation. Every encoding choice in RV32I was made to shrink a specific piece of hardware. Name the hardware and you have answered the question.

By the end of this lesson you can

  • Draw all six instruction formats from memory, field by field.
  • Explain immediate scrambling as a hardware optimisation, not an oddity.
  • State exactly which instruction bits are needed before decode completes.
  • Describe the inst[30] alternate-operation bit and where it does not apply.
  • Justify a 2-read 1-write register file for a single-issue core.
  • Say what RV32I excludes after the Zicsr and Zifencei split.

1The interview frame

Panels probe the base to test whether you designed a core or merely used one. The tell is causality. A user says "immediates are split across the word". A designer says "immediates are split so the sign-extension network is a single wire fanout and the immediate mux stays 2:1".

crux

RV32I optimises for one thing above all: starting work before decode finishes. Register indices, the sign bit and most immediate bits sit at fixed positions. The regfile read and the immediate generator therefore run in parallel with opcode decode, not after it.

Hold that sentence. It answers at least five different questions.

2Six instruction formats

Four base formats: R, I, S, U. Two immediate variants: B (from S) and J (from U). All are 32 bits with inst[1:0] = 11.

Range is −2048 to +2047. This is why LI of a large constant expands to LUI plus ADDI.

3Immediate scrambling — the real answer

This is the single most asked RV32I question. Answer it with hardware.

Four invariants that never break
  • Sign bit. Every immediate takes its sign from inst[31]. Always. So sign-extension is a fanout of one wire, not a mux tree.
  • Bits 10:5. Always from inst[30:25], in every format that has them.
  • Bits 4:1. From inst[24:21] in I and J. From inst[11:8] in S and B. Exactly two sources.
  • Bit 0. From inst[20] in I, inst[7] in S. Absent in B, J and U.
crux

Only bit 11 and bits 19:12 genuinely vary across formats. Everything else is fixed or a 2:1 choice.

What it actually saves
Immediate bitSourcesMux width

19:12inst[31] or inst[19:12]2:1

A naive encoding would need a 6:1 mux on all 32 bits plus a variable-width sign extender. The scrambled encoding reduces that to mostly wires and a handful of narrow muxes. In a tight core that difference is real timing slack on the ID stage.

Immediate generator, RV32I
Verilog — immediate generation
wire sgn = inst[31];   // one wire feeds bits 31:11 of every format

wire [31:0] imm_i = {{21{sgn}}, inst[30:20]};
wire [31:0] imm_s = {{21{sgn}}, inst[30:25], inst[11:7]};
wire [31:0] imm_b = {{20{sgn}}, inst[7], inst[30:25], inst[11:8], 1'b0};
wire [31:0] imm_u = {inst[31:12], 12'b0};
wire [31:0] imm_j = {{12{sgn}}, inst[19:12], inst[20], inst[30:21], 1'b0};

// Notice: zero logic gates. Pure bit selection and replication.
// The only real hardware is the final select, driven by opcode[6:2].

Every one of those five expressions is wiring. The synthesiser emits no gates for them. Only the 5:1 select at the end costs area, and that select is off the critical path if you compute all five in parallel.

Contrast: why ARM did it differently

ARM's classic 12-bit data-processing immediate is an 8-bit value with a 4-bit rotate. That trades decode logic — a barrel rotator in the immediate path — for encoding density on common constants.

RISC-V takes the opposite view. Immediate generation must be free; the compiler can emit two instructions for an awkward constant. That is the whole philosophy in one comparison.

use this line
  • "RISC-V pushes complexity out of the decoder into the compiler. ARM historically pushed it the other way. Neither is wrong — it depends on whether your bottleneck is the decode critical path or I-cache pressure."

5The inst[30] trap

inst[30] is the "alternate operation" bit. It distinguishes SUB from ADD and SRA from SRL. Candidates then over-generalise.

the trap

Ask: "So ADDI with inst[30]=1 is SUBI?" No. For OP-IMM, bit 30 is part of the 12-bit immediate. Setting it just changes the constant. RISC-V has no SUBI because ADDI with a negative immediate covers it.

Opcodefunct3Is inst[30] a function bit?
OP000 (ADD/SUB)Yes — selects SUB
OP101 (SRL/SRA)Yes — selects SRA
OPall othersNo — must be 0, else illegal
OP-IMM001, 101 (shifts)Yes — selects SRAI
OP-IMMall othersNo — it is imm[10]

So the decoder cannot blindly wire inst[30] into the ALU function. It must be qualified by opcode and funct3. Getting this wrong is a classic RTL bug, and describing the qualification is exactly the level of detail a panel wants.

RV64 delta

In RV64 the shift amount grows to 6 bits, inst[25:20]. So inst[25] stops being a reserved-must-be-zero bit and becomes shamt[5]. A decoder written for RV32 that checks inst[25]==0 will reject legal RV64 shifts. Mention this if asked about portable decoder design.

6Datapath walk — single-issue in-order

Reference pipeline for this whole track. Five stages, classical.

Instruction fetch

PC drives the I-cache. Next PC is PC+4 in the base. With C implemented it becomes PC+2 or PC+4, which Lesson 04 covers.

Redirect sources in priority order: trap vector, branch mispredict from EX, JALR target from EX, JAL target from ID, sequential.

The base has no architectural branch delay slot. That is a deliberate break from MIPS and it means the hardware must interlock or predict.

Decode

Three things happen in parallel, not in sequence:

  1. Regfile read using inst[19:15] and inst[24:20] — issued with no decode dependency at all.
  2. All five immediate forms computed as wires; one selected by inst[6:2].
  3. Control decode: ALU op, operand selects, memory command, writeback enable.

Hazard comparators also live here. They compare the two source indices against in-flight destination indices. Because those indices are at fixed bit positions, the comparators do not wait for decode either.

Execute

One adder does a lot of work: ALU add/sub, load and store address, branch comparison via subtraction, and AUIPC. Careful RTL shares it. Careless RTL instantiates four adders.

Branch target is a second adder on PC + imm_b. That one usually cannot be shared, because the branch comparison needs the main adder in the same cycle.

Shifts need a barrel shifter. A single shifter handling left, logical right and arithmetic right is built by reversing the input for left shifts and reversing the output again.

Memory

Byte and halfword accesses need a shifter and a sign/zero extender on the load return path, driven by funct3. funct3[2] is the unsigned flag; funct3[1:0] is the size.

Stores need byte-enable generation from the low address bits and the size. For SB at address ending in 10, byte enable is 4'b0100 and the data must be replicated across the lane.

Writeback

One write port. Source mux: ALU result, load data, PC+4 for JAL and JALR, CSR read data if Zicsr is present.

Write is suppressed when rd == 0, or when the instruction has no destination (stores, branches), or when a trap is taken.

7Register file and the x0 question

32 registers, 32 bits each. For a single-issue in-order core, 2 read ports and 1 write port is sufficient and that is the answer expected.

Instruction classReadsWrites

I-type ALU, loadrs1rd

Branchrs1, rs2—
AMO (A ext)rs1 (addr), rs2 (data)rd (old value)

No base or IMAC instruction reads three registers. That is why RISC-V has no fused multiply-add in the integer set — it would force a third read port.

design note

On FPGA, a 2R1W register file maps to two dual-port block RAMs written in lockstep, or to distributed LUT RAM. On ASIC it is usually a custom multi-port cell or a flop array with read muxes. The answer to "how did you build it" should name the technology.

x0 — three correct implementations
  1. Read mux. Store 32 real registers; force read data to zero when the index is 0. Costs a mux on the read path.
  2. Write suppress. Never write entry 0; initialise it to zero. Costs a gate on write enable. Entry 0 storage is wasted.
  3. No entry 0. 31 physical registers, decode index 0 as "return zero". Saves a register, complicates indexing.
the x0 forwarding trap

Suppressing the regfile write is not enough. If an in-flight instruction has rd = x0 and a younger instruction reads x0, the forwarding comparator matches and forwards a non-zero result. The register file is correct but the bypass is wrong. Every forwarding match must be qualified with rd != 0. Lesson 06 returns to this.

8Branch comparison without flags

RISC-V has no condition-code register. Comparison happens in the branch itself. This removes a serialising architectural resource and makes out-of-order renaming easier — worth saying aloud.

crux

funct3[0] is a pure invert bit. funct3[1] selects unsigned. funct3[2] selects magnitude compare over equality. So branch control is three bits straight into a tiny mux — no lookup table needed.

Encodings 010 and 011 are unused in BRANCH. They are reserved, and a conforming decoder must raise illegal instruction on them.

9Loads, stores and misalignment

Base RV32I addresses bytes. Loads sign-extend or zero-extend to XLEN.

Misaligned access — the honest answer

The specification permits two behaviours and requires you to pick one:

  • Handle it in hardware, possibly with a performance penalty.
  • Raise an address-misaligned exception and let software emulate it.

Trap causes worth knowing: 0 instruction address misaligned, 4 load address misaligned, 6 store/AMO address misaligned.

trap

A misaligned access to a region that does not support it may raise an access fault rather than a misaligned exception. The two are different causes and different recovery paths. Saying "it always traps as misaligned" is wrong.

defensible design choice

For an embedded RV32IMAC core, trapping is the normal choice. Hardware misalignment support costs a second cache access, a merge network and a much harder precise-exception story, for a case that compiled code rarely produces. Say that, and say you measured it.

12Interview Q&A

Why are register specifiers always at bits 19:15, 24:20 and 11:7?

So the register file read can be launched from the raw fetched word, before any decode logic resolves. Decode then only has to decide whether the read values are used, not where to read from.

The second-order benefit: hazard comparators and the rename table in an out-of-order design see stable indices at the same instant. It removes decode from the critical loop.

What determines the instruction format — and how early can you know it?

Only inst[6:2], once inst[1:0] = 11 confirms a 32-bit instruction. Five bits into a small decode gives the format. No funct3 or funct7 involvement.

Practically this means the immediate select resolves in one level of logic after fetch, which is why the imm generator is never the ID critical path.

Your ID stage is failing timing. Where do you look first, and what do you not touch?

Look at the control decode and hazard resolution, not the immediate generator. The imm path is wires. The usual offenders are the ALU-operation decode feeding an operand mux, and the forwarding priority network which is a wide comparator tree followed by a mux chain.

Standard fixes: precompute forwarding selects one stage early; flatten the priority mux into a one-hot select; move illegal-instruction detection off the fast path into a parallel cone that only affects the trap signal.

Why is there no SUBI, and no NOT, and no MOV?

Each is covered by an existing encoding. SUBI is ADDI with a negated immediate. NOT rd, rs is XORI rd, rs, -1. MV rd, rs is ADDI rd, rs, 0. NOP is ADDI x0, x0, 0.

These are assembler pseudo-instructions. The point is decoder area: every real opcode costs decode logic forever, so the ISA only spends one where no existing encoding covers the case.

Careful with the asymmetry: the immediate range is −2048 to +2047. So ADDI can subtract 2048 but cannot add it. Minor, but a panel may probe it.

Does removing condition codes help or hurt?

Helps for implementation, costs a little in code density. No flags register means no implicit serialising dependency between a compare and a branch, nothing to rename in an out-of-order machine, and no partial-flag-update hazards of the kind x86 suffers.

The cost: predicated execution becomes impossible, and ADD-then-branch-on-overflow patterns need explicit comparison instructions. Compilers handle it; the overflow-check sequence is a known two-instruction idiom.

How do you detect an illegal instruction cheaply?

Build it as the complement of a legal-instruction one-hot. Decode produces a set of match signals; illegal is the NOR of all matches, qualified by the reserved-field checks — inst[25] zero for RV32 shifts, funct7 zero where required, branch funct3 not in the reserved set.

Keep it out of the main control path. It only needs to be valid by the stage where the trap is taken, so it can have an extra pipeline stage of slack.

13Defend your claim — Hanu 1.0

write your answers down
  • How many register file read and write ports did you build, and in what technology — LUT RAM, block RAM, flop array?
  • Which x0 implementation did you choose, and did you gate your forwarding comparators on rd != 0?
  • Did you share one adder between ALU, address generation and branch comparison, or instantiate separate ones? What did that cost in LUTs or gates?
  • Misaligned loads: hardware or trap? What drove the decision?
  • Did you implement Zicsr and Zifencei? If not, how does your core take a trap at all?
  • What was your ID-stage critical path, and what was the achieved frequency?

14Recap

  • Six formats: R, I, S, B, U, J. Format is a function of inst[6:2] alone.
  • Fixed positions for rs1, rs2, rd and the sign bit let regfile read and immediate generation start before decode resolves.
  • Immediate generation is wires plus one select. That is the whole answer to the scrambling question.
  • inst[30] is a function bit only for OP and for the two OP-IMM shift encodings.
  • 2R1W register file. No three-source instruction exists in IMAC.
  • Branch condition decode is three bits: invert, unsigned, magnitude.
  • Zicsr, Zifencei and Zicntr are outside the base. Know it, say it.
